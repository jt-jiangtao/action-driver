# Codex 风格活动时间线回归修复设计

## 目标

让真实工具调用、重连和重新打开的任务均使用 Codex 风格活动时间线。一个活动任务表示一个工作阶段，包含 `n` 条工具调用及其间的可见正文；它不是工具类型分组，也不是单条工具卡。

## 已确认的体验规则

- 生成中：正文和活动任务按真实顺序平铺。活动任务显示受控标题和折叠箭头，内部工具显示为无外框的紧凑行。
- 脚本：仅当用户展开某条 Shell/脚本时，显示浅灰、等宽字体的原始输入输出区、滚动条与底部渐隐。
- 状态：运行中的活动、运行中的工具以及尾部“正在思考”使用低对比扫光；遵循 reduced-motion。
- 完成：完整过程默认收进“用时 N 秒”折叠项；最终结论及产物保持在折叠项之后。
- 审批：等待审批只出现在输入框上方，终态结果保留在所属工具行。

## 数据流与归属

Runtime 是唯一的任务聚合来源，Renderer 不按工具类别、LLM 调用次数或相邻卡片自行猜测分组。

1. 模型提供 `activity.update` 时，Graph 使用其稳定 `activityId`、受控标题和递增版本。
2. 模型未提供时，Graph 在首条外部工具调用前创建受控兜底活动，并把当前连续工具批次的 `n` 条调用及其间正文附着在该活动。
3. 收到显式新活动、Turn 结束或确定的阶段边界时，结束当前兜底活动。兜底标题只描述可观察操作，不暴露推理内容。
4. Stream Session 持久化活动事件，并在快照中提供完整活动投影；恢复路径与实时路径得到同一投影。

## 视觉组件边界

`ActivityTimeline` 是唯一的工具过程视图。它包含活动任务、任务内工具行、正文、尾部思考状态和完成归档；`ToolActivityCards` 不再用于 Runtime 驱动任务。

活动工具行只保留图标、动词/摘要、短状态和展开控制；无大圆角外框、无“运行结束”标题、无任务编号。灰色代码块只属于展开的原始 I/O。

## 验收与测试

- 普通模型仅返回工具调用时，页面仍出现活动任务而不是旧工具卡。
- 同一活动任务可包含多条异构工具和插入正文，并按事件 cursor 保序。
- 已完成任务重连、刷新或从快照恢复后仍显示“用时”归档和相同活动内容。
- 视觉 E2E 断言页面没有旧卡标题/类，且活动行、归档、原始 I/O 和结论处于正确层级。
