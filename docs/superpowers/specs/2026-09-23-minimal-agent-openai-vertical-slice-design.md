# 真实 OpenAI-compatible 最小 Agent 闭环设计

日期：2026-09-23

关联 OpenSpec：`serve-runtime-over-http`

状态：待实现前复核

## 目标与成功标准

先交付一个可重复验收的真实 Agent 最小实例：用户选择已保存的模型，提交目标，Runtime 向真实 OpenAI-compatible 端点发起一次请求，保存结果，并能在真实任务/会话列表、接口层日志和模型层日志中复盘整条链路。

成功必须同时满足：

1. 模型选择、任务/会话列表、任务详情、接口层日志、模型层日志全部来自真实服务端数据。
2. 模型调用由 Runtime 发起；页面不持有供应商凭据，也不直连供应商。
3. 成功、失败、空数据和应用重启后恢复都有明确行为。
4. 本阶段不调用 Skill、Browser Use 或 Computer Use，也不显示对应的虚构步骤或面板。
5. 本地生产装配不回退到确定性模型、Mock catalog 或示例日志。

## Battle 结论

这是产品优先级、系统边界和数据所有权共同变化的决策型任务。检查发现，现有页面选择只保存 `modelId`，任务提交不携带连接引用，Runtime 仍使用确定性模型网关，部分列表与模型日志仍来自 Mock；因此“只替换模型请求”不足以跑通真实闭环。

比较过三种方案：

- 同时实现 OpenAI-compatible 与 Anthropic-compatible：覆盖广，但首个闭环同时承担两套合同、错误映射与响应结构，返工面过大。
- 先实现 OpenAI-compatible 单轮非流式闭环：边界完整、可测试，且后续可沿同一模型引用与日志合同接入 Anthropic。
- 页面直连供应商：实现快，但破坏服务端唯一持有凭据、唯一写入会话和统一观测的既有裁决。

最终采用第二种方案。Anthropic 连接仍可配置和测试，但 Agent 选择中明确不可用；不做静默兼容或降级。

## 范围

包含：

- 真实启用模型的查询与选择；
- 精确模型引用的任务提交；
- OpenAI-compatible `/chat/completions` 单轮非流式调用；
- 真实任务、消息、运行事件的持久化与投影；
- 真实最近任务/会话列表和 Agent-only 任务详情；
- 真实接口层 Request/Response 和模型层执行日志；
- 本地假 OpenAI-compatible 服务的端到端验收。

不包含：

- Anthropic Agent 执行；
- 流式输出；
- Skill、MCP、Browser Use、Computer Use；
- 云端部署和多端同步；
- Figma 或视觉基线检查。

## 数据流与所有权

```text
Renderer
  ├─ 查询可执行模型 ────────────────┐
  ├─ 提交 {connectionId, modelId} ──┼─> Runtime API
  └─ 查询任务与日志 <───────────────┘       │
                                             ├─ ModelConnectionService
                                             │    ├─ 读取连接与加密凭据
                                             │    └─ OpenAI-compatible adapter
                                             │              │
                                             │              └─> /chat/completions
                                             ├─ RuntimeStore
                                             │    └─ 任务/消息/事件
                                             └─ InteractionLogStore
                                                  └─ Request/Response
```

Runtime 是连接、凭据、任务、消息和运行事件的唯一写入者。供应商密钥只在 Runtime 构造上游请求时解密到内存，不能进入任务合同、页面状态、日志摘要、日志正文或错误信息。

模型连接服务必须由 Runtime 组合根构造一次，并同时服务配置接口和执行网关，避免“设置页连接”和“执行时连接”落在两个互不共享的实例。测试/视觉装配可以显式注入 Mock；本地生产装配禁止注入 Mock gateway、catalog 或日志投影。

## 合同与状态模型

模型选择身份为：

```ts
type ModelRef = {
  connectionId: string;
  modelId: string;
};
```

`modelId` 不能独立作为身份，因为不同连接可以暴露同名模型。

最小任务提交包含：

```ts
type SubmitTask = {
  goal: string;
  model: ModelRef;
  systemPrompt?: string;
  skills: [];
};
```

页面提交前校验选择仍有效；Runtime 再做权威校验。连接不存在、连接停用、模型停用、不支持文本或协议尚未接入时，必须在上游请求前失败，且不能自动换模型。

任务至少覆盖 `queued → running → completed | failed`。成功保存用户消息、assistant 消息和完成事件；失败保存结构化错误与失败事件，不伪造 assistant 消息。认证、限流、超时、协议错误和无文本响应使用稳定错误码，并标记是否可重试。

## 模型选择与页面行为

模型选择器只展示服务端持久化连接的真实投影：

- 已启用、支持文本的 OpenAI-compatible 模型可选；
- Anthropic-compatible 连接显示但不可选，并显示“Agent 调用暂未接入”；
- 同名模型按连接名称分组和区分；
- 无可用模型时显示配置入口并禁用提交；
- 已选连接删除、停用或模型停用时清除选择并要求重选；
- 服务端不可用时显示不可用状态，不保留伪成功选择。

任务详情采用 Agent-only 布局，仅展示用户输入、运行状态、模型信息、assistant 输出或失败信息。Browser/Computer 区域不渲染，不用“未执行”占位制造不存在的能力。

## 真实列表与持久化

最近任务/会话列表和任务详情从 Runtime 存储读取。真实存储为空时展示空状态；查询失败时展示错误和重试；两者都不得显示示例数据。应用或本地服务重启后，已完成与失败任务、消息和运行事件应恢复一致。

“会话”和“任务”的展示关系沿用现有产品语义，但数据源统一为服务端投影。若当前最小提交只创建一个任务，则列表仍用真实 ID 和关联字段建立层级，不在页面端合成 Mock 会话。

## 接口层与模型层日志

接口层为真实供应商调用增加 `service->model` 方向。一个调用用同一 `correlationId` 关联 Request 和 Response，并携带可用的 `taskId`、`requestId`、连接上下文、耗时、状态码和结果。Request/Response 保存真实业务正文，但必须在采集边界排除 Authorization、API Key、Cookie 和服务端访问凭据。

模型层日志不是另一份 Mock 数据，而是从同一真实任务事件投影：

1. 系统提示词；
2. 用户输入；
3. 模型请求；
4. 模型响应或结构化失败；
5. 任务完成或失败终态。

接口层与模型层通过 `taskId`、`requestId` 和 `correlationId` 互相定位。日志查询、刷新、筛选和详情通道 `actiondriver:log:*` 必须继续排除，避免查看日志制造日志。

## 错误与安全

- 连接或模型失效：提交前后双重校验，阻止请求，不自动换模型。
- 上游认证失败：任务失败，日志保留不含凭据的请求元数据与真实错误响应。
- 限流或超时：返回稳定可重试错误，页面保留任务和诊断入口。
- 响应无文本：按协议错误处理，不生成空的成功消息。
- 持久化失败：不能先向页面报告完成；任务进入可诊断失败或保持未完成。
- 日志凭据过滤无法确认：拒绝保存正文，只保存不含正文的诊断摘要。

用户已明确业务正文无需通用脱敏；这不覆盖鉴权凭据永不落盘的安全边界。

## 测试与验收

主要端到端测试启动一个本地假 OpenAI-compatible HTTP 服务，并执行：

1. 保存并启用连接，发现或添加一个文本模型；
2. 从真实模型列表选择该连接与模型；
3. 提交用户目标；
4. 断言假服务实际收到预期 system/user messages 和模型名；
5. 返回固定 assistant 文本并断言任务完成、消息持久化；
6. 断言最近任务/会话列表和任务详情显示真实记录；
7. 断言接口层存在真实 Request/Response，模型层存在完整执行投影；
8. 重启服务并断言列表、详情和日志仍可读取；
9. 断言没有 Browser/Computer 调用、没有 Mock 降级、所有可观察输出均无密钥。

另以定向测试覆盖：重复 `modelId`、失效选择、Anthropic 禁用说明、认证失败、限流、超时、无文本响应、真实空列表和日志控制面排除。整个最高优先级任务组完成后再运行完整 `pnpm check`、桌面 E2E 和 OpenSpec 严格校验，避免每个子项重复跑全集。

## 实施顺序

1. 更新模型引用和任务提交合同。
2. 实现 OpenAI-compatible 完成请求与错误映射。
3. 在 Runtime 组合根共享连接服务并移除生产 Mock 降级。
4. 完成真实任务、消息、事件持久化与页面投影。
5. 接入真实接口层和模型层日志。
6. 完成本地假上游端到端测试。
7. 运行完整门禁并修复本任务范围内回归。

## 已知取舍与后续

首个闭环等待完整非流式响应，首 token 体验不如流式；这是用更小状态空间换取真实边界先稳定。Anthropic 暂时只能配置，不能执行；页面必须明确表达限制。两者后续都沿现有 `ModelRef`、任务状态和日志关联字段增量实现，不改变本设计的数据所有权。
