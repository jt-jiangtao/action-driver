# 活动任务组与正文阶段设计

## 目标

任务页按事件顺序呈现正文片段和工具任务组。等待模型返回而没有正文或工具时显示“正在思考”。每段连续工具调用组成一个任务组，即使只有一个工具；可见正文开始时结束前一个任务组，下次工具调用创建新组。任务组不包含正文。

## 已裁决的方案

- 工具标题由 Runtime 根据已注册工具类型、受限参数摘要和生命周期生成；不增加 LLM 标题调用，也不要求模型在工具调用中附带标题。
- 单工具组使用该工具的动作标题；同类多工具组按类型和数量汇总；混合工具组显示操作数量。组图标在运行中跟随当前工具，同类终态保留类型图标，混合终态用通用工具图标。
- 任务组标题及运行中的工具行有低强度扫光；所有终态停止动画，并遵循 `prefers-reduced-motion`。
- 正文片段在运行中显示于组外。任务结束后，以最终模型回复作为唯一默认展开的正文；先前正文和工具过程放进可展开的用时归档。无工具的过程文本也可回看。

## 事件与状态

Runtime 在 `response.start` 后进入等待模型状态。收到可见文本时，先结束当前工具组，再发送不归属工具组的正文片段。收到工具调用时，若没有活动组则创建新组，然后将该工具的所有生命周期事件归入组。没有正文隔开的后续工具沿用当前组。组标题版本单调递增；完成、失败或取消后立即更新。最终响应结束时关闭仍活动的组。

Renderer 由投影中的正文片段、工具组和任务状态决定显示；“正在思考”是瞬时状态行，不写入历史。组图标使用投影中的工具类型，不依赖中文标题的正则匹配。实时事件、快照和重连使用同一组边界及标题。

## 风险与处理

- 模型在同一次响应中先输出正文再调用工具：正文先成为独立片段，工具随后新建组。
- 连续模型轮次只有工具没有正文：保持同一组，不因模型请求边界拆组。
- 工具标题可能包含文件路径或查询：只使用现有安全摘要和长度限制；Shell 参数默认不进入标题。
- 失败、中断或取消：保留已收到的正文与工具记录，不把未完成片段误判为最终结论。
