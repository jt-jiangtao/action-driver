# Imagegen 系统 Skill 与生图画廊设计

## 目标

用户请求生图时，对话在生成开始就显示与本次需求数量相同的 1–4 个圆角点阵占位卡；每张成功图片在原卡片位置出现，文字始终排在图片上方。图片支持放大与保存，取消或部分失败不冒充成功。Action-Driver 随安装包提供 Imagegen 系统 Skill，用来指导 Agent 整理提示词和调用已有生图工具。

## 现状与根因

- `image.generate` 已支持一次传入 1–4 条独立提示词并并发执行，逐张发出 `tool.asset`，但界面没有请求张数这一安全元数据，无法在开始时画出对应数量的占位卡。
- 流式阶段 Runtime 把文字与图片按到达顺序写入消息部件。响应结束时，`stream-session-service.ts` 又重建为图片部件在前、完整文字在后；桌面 `stream-task-projection.ts` 也做同样的重排。因此结束瞬间图片跳到文字上方。历史恢复读取的也是已重排的持久化消息。
- 本机 Codex Imagegen Skill 默认调用 Codex 内置 `image_gen` 工具；Action-Driver 没有该工具。仓库已有系统 Skill 的打包、安装、只读展示及启停流程，可复用，但原版执行说明不能原样运行。

## Battle 结论

- 类型：产品交互与跨模块数据契约决策。
- 当前方案：Codex 风格的点阵占位动画、最多四张并行，文本先于图片；完整复制 Imagegen Skill 文件并适配执行说明。
- 替代方案：仅显示一个生图占位卡，完成后依次追加图片，无需传输张数或插槽编号；实现较小，但用户看不出并行数量，图片会移动，无法满足“每张原位替换”。另一个替代是原样复制 Codex Skill；它引用 Action-Driver 不提供的内置工具，安装后不能执行默认生图路径。
- 最终裁决：用户选择每张图固定占位、原位替换、柔和动画及减少动态效果支持；选择完整复制文件并将 Skill 默认路径适配到 Action-Driver 的 `image.generate`。
- 主要权衡：需要向任务事件和持久化图片部件加入非敏感的张数与插槽编号；Codex 备用 CLI 文件随 Skill 保留，但不作为 Action-Driver 默认执行路径，也不承诺随包携带其 `openai` Python 依赖。
- 用户覆盖：无。重新开启条件为现有模型接口不能返回单张图片，或需要跨会话继续未完成生图。

## 交互设计

文字区域先显示在助手消息顶部，下方是本次生图的卡片组。1 张使用一列；2–4 张按可用宽度排成最多两列，窄屏降为一列。卡片使用截图中的浅灰底、大圆角和细点阵；等待时点阵有低幅度的亮度流动，边界不跳动。每张成功后原位替换为图片，轻微淡入；失败时该插槽显示简短失败状态，完成后不留下永久动画。`prefers-reduced-motion: reduce` 时关闭连续动画和淡入。

占位张数来自生图调用的 `images.length`，不解析原始提示词。进行中的工具、已完成资产、失败数量均以调用 ID 和 0 起始插槽编号关联。多次生图调用各自保留独立卡片组；旧消息没有插槽元数据时按现有图片顺序显示。用户上传图片的 104×104 气泡样式保持不变。

## 数据与实现边界

- Runtime 在生图工具进入运行态后传递一个 `imageCount`（1–4），只对 `image.generate` 设置；输入提示词仍服从现有 raw I/O 开关，不作为界面计数来源。快照也保留该数量。
- `tool.asset` 的 `index` 已对应输入插槽。`response.image` 与持久化的助手图片部件保留调用 ID 和插槽编号，使断线重连、历史恢复及乱序完成都能回到原位置。协议扩展字段对旧数据可选。
- Runtime 和桌面投影在流式、结束、快照及旧历史读取时共用“助手文字区在前、生成图片区在后”的归一规则，不针对模型或单次生图写特殊分支，也不通过 CSS `order` 掩盖数据顺序错误。旧消息即使持久化为图片在前，也在读取投影时归一显示，且保留其中图片的相对顺序。重复资产事件仍按资产 ID 去重。用户消息仍保留图片在文字上方的既有规则。
- Renderer 使用已有 `ConversationImage` 的读取、放大和保存能力；新增画廊组件只处理插槽排布与状态。对失败或取消的插槽显示状态，其他成功图片保留。
- 将本机 `imagegen` Skill 的 `SKILL.md`、参考文档、脚本、图标、代理元数据和 `LICENSE.txt` 完整复制到 `apps/agent-runtime/resources/system-skills/imagegen`。修改主 Skill 及必要的入口元数据，使默认流程调用本地 `image.generate`，不调用 Codex 内置工具；备用 CLI 明确标为非默认参考文件。系统 Skill 名称加入保护列表、初始化播种、桌面系统 Skill 路径识别和 macOS 包验证。

## 验收

1. 生图开始即出现与请求数一致的点阵卡；四张并行乱序完成时各自原位替换，不移动已经完成的图片。
2. 文字在生成中、结束后、重连及历史打开后都位于图片上方。
3. 部分失败和取消留下准确状态；已成功图片可放大、保存；减少动态效果设置有效。
4. 新安装和升级后的应用均含只读 Imagegen 系统 Skill，设置列表可见；文件、许可证及引用资源完整，Skill 默认使用 Action-Driver 工具。
