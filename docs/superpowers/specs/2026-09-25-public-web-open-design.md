# 公网静态网页读取设计

## 目标与裁决

ActionDriver 的 `web_search` 已能找到公开网页，但只返回摘要。新 `web_open` 接收一个 URL，读取单个静态 HTML 页面的标题、正文和最终来源。用户已确认独立静态工具，以及仅允许公网 HTTP(S)；本机、内网与私有地址，包括重定向后的地址，都必须被拒绝。完成标准见 [OpenSpec 行为规格](../../../openspec/changes/add-web-open/specs/public-web-page-reading/spec.md)。

此变更为产品与架构决策型。Battle 检查了搜索摘要不足、Browser Skill 尚未实施、出站网络与提示注入边界。备选是先完成 Browser Skill 再读取 DOM，它可处理动态站点，但明显扩大首版的导航、会话和 UI 范围。推荐并最终裁决独立的单页静态读取。没有用户覆盖项，也没有未解决的关键分歧。

## 用户与运行流程

1. 模型从搜索结果或用户消息得到 URL，调用 `web_open({ url })`。
2. Runtime 校验 URL、解析目标、固定公网连接地址，并对每次跳转重新校验。
3. Runtime 有界读取 HTML，使用 Readability 提取正文；短页面可回退到清理后的 body 文本。
4. 工具把 `{ title, url, text, truncated }` 交回模型，任务活动展示可展开的标题、来源和正文。
5. 不可访问或不可读取的页面返回明确失败，模型可以说明限制；工具不会执行页面脚本或自动打开链接。

## 组件边界

网络适配器只负责公网目标判定、连接、跳转、响应和资源上限。文本提取器只接收有界 HTML 与最终 URL，不自行联网。工具包装层负责输入 schema、取消信号、输出契约与现有工具生命周期。桌面活动组件只读取已持久化的工具结果，显示来源和有限正文；SQLite 结构无需迁移。详细技术决策、替代方案和风险见 [OpenSpec 技术设计](../../../openspec/changes/add-web-open/design.md)。

## 资源与信任边界

首版最多跟随 3 次跳转；单次调用总时限 15 秒；传输体上限 2 MiB、解压体上限 4 MiB、正文输出上限 12,000 个 Unicode 字符。页面文本仅作为不可信工具结果交给模型，不进入系统提示；不发送 Cookie、授权头或代理凭据。HTML 不作为可执行内容渲染。

## 验证重点

用可注入的 DNS 和网络适配器覆盖公网、私网、混合解析、DNS 变化、重定向到本机、压缩超限和取消。用静态文章、短页、空页、脚本内容和长页验证提取与截断。最后验证模型工具循环、归档回放和可读活动卡片。实施顺序见 [OpenSpec 任务](../../../openspec/changes/add-web-open/tasks.md)。
