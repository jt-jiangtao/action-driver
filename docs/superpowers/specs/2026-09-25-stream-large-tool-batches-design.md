# 大批量工具调用与准备阶段反馈设计

## 目标

单条任务可以执行至少 400 次工具调用，覆盖 Shell、Python、Node.js 与 Web Search 各 100 次。模型开始流式生成工具调用后，界面尽早显示工具名及准备状态；参数验证完成前不得执行工具或显示半成品参数。

## 已批准方案

将调用与轮次预算均提高到 512，并同步提高 LangGraph 递归上限。模型适配器识别完整工具名后发出仅包含索引和名称的准备事件；事件经过 Gateway、Graph 和 StreamSession 持久化，桌面端在思考状态行显示“正在准备 <工具名>”。正式工具行仍由经过参数校验的调用创建。正文、取消、失败和终态清除临时状态。

进度事件参与请求内连续序号和 cursor 回放。运行中快照可恢复最近的准备状态；完成任务的归档不保留准备状态。既有工具授权、单次超时和输出上限保持不变。

## 验收

- 假模型返回 400 次混合调用并正常完成；超过 512 次明确失败；逐轮调用可越过旧 LangGraph 递归上限。
- 工具名先于参数终态到达时，界面显示准备状态且没有正式工具行；无原始参数泄露；取消和失败清理状态。
- Shell、包内 Python、包内 Node.js、本地 HTTP Web Search 各实际执行不少于 100 次，并汇总成功计数。
- 单测、类型检查、构建与桌面端到端验证通过。

## 权衡

用户选择单任务 512 次上限，覆盖了 Agent 原先建议的分批验证方案。长任务会增加模型上下文、响应耗时、检查点和事件数量；提供方上下文限制仍可能先于工具预算触发。此时应清晰保留已完成调用和错误，不推断任务成功。

详细接口与风险记录见 [OpenSpec 设计](../../../openspec/changes/stream-large-tool-batches/design.md)。
