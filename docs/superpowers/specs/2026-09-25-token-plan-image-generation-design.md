# Token Plan 生图接入与未配置提示设计

## 目标与现状

用户在对话中请求生成图片时，应在已配置默认生图模型的前提下调用现有 `image_generate` 工具，并在对话流中得到图片。没有默认生图模型时，助手应准确说明需要在“设置 → 模型连接”启用生图并设为默认，而不是声称应用没有生图工具。

当前 Runtime 仅在存在默认生图模型时将工具提供给聊天模型。实际用户配置没有默认生图模型，也没有开启生图能力的模型，因此截图中的回复与模型所见工具列表一致，但没有反映应用可配置的能力。现有适配器调用 OpenAI Images API 兼容的 `/images/generations`；用户连接中的 `wan2.7-image`、`wan2.7-image-pro` 通过阿里云 Token Plan 网关列出，其[官方生图接口](https://help.aliyun.com/zh/model-studio/token-plan-multimodal-gen)使用 `/api/v1/services/aigc/multimodal-generation/generation` 和不同的请求、响应格式。

成功标准：用户可在模型列表将 Wan 模型的生图接口选为 Token Plan、启用并设为默认；发送文字生图请求后使用同一 `image_generate` 工具生成并展示最多四张图片；未配置时助手给出准确的设置指引。用户添加的宽幅图片在输入框和发送后的消息里都能看清完整构图，并可放大。现有 Images API 模型、会话图片存储与历史展示继续工作。

## Battle 结论

- 类型：架构决策。新增提供方协议，涉及模型配置公共接口、SQLite、Runtime 适配器和设置 UI。
- 已核事实：当前默认生图模型为空，所有已配置模型的生图开关关闭；现有适配器只支持 Images API 格式。Wan 的官方 Token Plan 文档给出另一条端点和多模态消息格式。没有证据证明当前网关的 `/images/generations` 可用于这些 Wan 模型。
- 替代方案一：只修正提示，要求用户改用 Images API 兼容服务。改动最小，但无法让现有 Token Plan 连接生图。
- 替代方案二：依据网关地址或模型名自动选择协议。设置简单，但代理地址和模型命名变化会导致错误路由，也不符合已有的手动能力配置方式。
- 最终裁决：接入 Token Plan 生图接口，修正未配置提示；每个模型明确选择 Images API 或 Token Plan 生图协议，继续由用户手动启用生图及选择默认模型。用户选择了显式协议配置方案。
- 主要权衡：设置页会增加一个选项；不进行可能计费的自动生图探测。真实可用性在调用时验证，失败时给出明确错误。

## 架构与数据流

### 模型配置

在 `ModelOptionDto`、本地设置模型和 SQLite 的 `model_connection_models` 行增加 `imageGenerationApi`，取值 `openai-images` 或 `token-plan`。旧行迁移为 `openai-images`，保留原有生图开关及默认模型；刷新模型列表时保留用户配置的接口类型。只有打开生图开关的模型才显示协议选择器，选择器不得自动开启能力或设置默认值。服务端验证协议枚举、模型所属连接及默认模型资格；`token-plan` 首版仅与 OpenAI 兼容模型连接一起使用，以复用该连接的加密 API Key。切换协议不改变聊天模型的调用方式。

设置页的模型行显示生图开关、协议选择器和默认选择；文字应让用户分辨“支持生图”声明、接口协议和“设为默认”三个独立状态。用户仍需自行决定 `wan2.7-image` 或 `wan2.7-image-pro` 哪个作为默认模型，迁移不会代其选择或产生费用。

### 提供方适配

`ModelConnectionService.generateImage` 根据所选模型的 `imageGenerationApi` 分发到独立适配器。既有 Images API 适配器保持现有请求与结果处理。Token Plan 适配器从已配置连接 URL 的 origin 构造官方同步端点 `/api/v1/services/aigc/multimodal-generation/generation`，复用该连接的凭据，发送 `{ model, input: { messages: [{ role: 'user', content: [{ text: prompt }] }] }, parameters: { size: '1024*1024', n: 1 } }`。官方 Wan 2.7 参考允许 `n=1`，Token Plan 接入示例使用 `1024*1024` 尺寸。每个现有工具需求仍是一次独立请求，最多四个并行，沿用工具的部分成功、取消和逐张发布逻辑。

响应从 `output.choices[*].message.content[*].image` 提取图片 HTTPS URL，立即下载、验证字节上限与格式，再交给既有会话图片资产存储。Token Plan 返回的临时 URL 不能作为历史消息引用，也不得将 URL 或 API Key写入日志、遥测和事件。沿用现有请求超时、取消、有限读取与非跳转下载策略。对于 HTTP 错误、缺少图片、无效 URL、下载失败或超限，生成结构化错误；四张中的成功图片保留，全部失败则工具失败。

### 未配置时的对话反馈

继续保持“没有可用默认生图模型时不暴露 `image_generate` 工具”的现有规则，以免模型反复调用必败工具。每轮构造模型请求时，Runtime 将当前能力状态加入系统上下文：没有默认生图模型时明确说明应用支持生图，但需要先在“设置 → 模型连接”启用一个模型的生图能力并设为默认；有可用默认模型时说明模型可使用 `image_generate`。这个说明只描述配置事实，不依靠解析用户意图，也不阻止其他文字任务。模型设置在两轮间变化时读取最新状态。工具调用中默认模型被停用或切换时，工具返回可理解的配置错误。

### 图片预览与用户消息

输入框当前使用 `object-fit: cover` 将图片强制裁为 30×30 方块；宽幅截图可能只剩放大的局部文字。改为有界预览卡片，图片保持原比例、完整显示在预览范围内，留白以浅色背景和边框区分；文件名与移除按钮不遮盖图片。发送后用户消息的图片缩略图也保持完整比例、清晰边界和可点击放大，图片与附带文字各自占据可读区域，避免白色截图在气泡里看似空白。缩略图加载失败时保留明确占位，不把空白当作成功。使用一张宽幅白底文字图做 UI 回归样例，核对输入框、发送后、历史恢复和放大视图显示的是同一张图片。该修复只触及现有图片 UI，不改变资产协议。

## 边界与兼容性

- `image_generate` 的名称、最多四张的输入 schema、会话图片目录与图片展示不变。
- 图片协议是模型能力配置，不改变聊天连接协议；同一连接可同时服务聊天补全和 Token Plan 生图。
- 旧数据库行缺少新字段时迁移为 `openai-images`；原有 Images API 生图配置不需重新设置。
- 仅支持阿里云 Token Plan 的同步文字生图；图片编辑、异步任务轮询、代理自定义端点和自动能力探测不在本次范围。

## 验证

1. 迁移测试：旧模型行默认 `openai-images`，现有能力开关和默认引用不丢失；刷新模型列表保留协议。
2. 适配器测试：校验端点、请求体、鉴权、临时图片 URL 下载、大小/格式、超时、取消、非 2xx 与无图片响应；测试不得调用真实计费接口。
3. 服务测试：同一连接上的 Images API 与 Token Plan 模型分别路由到正确适配器；默认模型切换或停用得到明确错误。
4. 对话测试：无默认模型时模型请求包含准确配置说明且工具不在列表；配置完成时模型能看到工具；四张并行任务保留现有部分成功语义。
5. 设置页测试：选择协议、开关生图、设置默认的状态分离，保存重开后保持；用打包应用核对设置与对话流程。
6. 图片显示测试：宽幅白底文字图在输入预览和用户消息中完整可见，点击可查看原图；网络读取失败时出现错误占位。

## 风险

- Token Plan 可能调整响应字段或参数；适配器只接受已验证的图片字段，失败时报告提供方响应无效，不伪造成功。
- 生成调用可能计费；安装和数据库迁移不主动调用生图，用户需手动启用并选择默认模型。
- 动态系统说明可以降低错误表述，但模型输出仍非确定性的；验收重点是模型实际收到正确工具和状态信息，并用端到端场景观察回复。
- 将网关 origin 用于官方生图路径要求该连接直连 Token Plan；自定义代理端点不在首版范围，界面需要明确这一限制。
