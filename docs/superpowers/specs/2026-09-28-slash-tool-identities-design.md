# 斜杠工具标识设计

## 目标

所有新注册工具以 `/` 表示标识层级，使插件声明、授权、调用事件和界面查找使用同一稳定 ID。验收要求：`tools.local.command.shell.run` 变为 `tools/local/command/shell/run`；所有运行中的工具 ID 不含点号；旧点号工具 ID 和 grants 均不能调用新工具。模型提供方函数名仍为 `tools_local_command_shell_run`。

## 范围与边界

内置工具使用 `tools/<target>/<plugin>/<operation>`；第三方插件的工具贡献也使用斜杠分隔 ID。工具 ID 带外的版本仍为 `@<version>`。插件、Skill、服务、能力和事件类型不是工具 ID，不改它们的点号。工具参数、执行权限与模型名保持现有契约。

## 实现结构

`packages/plugin-contracts` 负责生成和校验工具身份，manifest 的工具贡献与 catalog 均拒绝点号 ID。`packages/plugin-sdk` 导出新生成器。每个内置插件同步修改 manifest、catalog、presentation 键和激活条件；脚手架生成新格式。Runtime Registry 与 Policy Gate 只比较当前声明，不注册旧别名；能力 grants 使用新版本化 ID。Runtime 的活动投影和 Desktop 的工具卡片按新 ID 查找，新旧记录中的未知 ID 使用通用展示回退，不触发执行。

本地插件仓库会在包内容改变时刷新同版本安装目录。验收须覆盖已有点号清单安装目录在新版本启动后的刷新，避免新 manifest 指向旧代码。第三方旧包直接报无效工具 ID，须由作者升级。

## 失败与恢复

旧授权不扩大为新授权，旧模型别名和旧点号工具 ID 均返回不可用或授权失败。历史数据库不迁移，原工具事实保留，但不据此恢复旧工具调用。整体版本回退不保证新斜杠记录可被旧版本执行。

## 验证

定向契约测试覆盖生成、验证、点号拒绝和版本键。插件测试覆盖清单、catalog、内置安装刷新和第三方旧包失败。Runtime 测试覆盖发现、grant、模型名、执行与事件投影。Desktop 测试覆盖工具卡片和图片等专属展示。提交门槛按仓库规则一次性运行类型、Lint、单元测试及必要的真实 Electron 用例。

## Battle 结论

本任务是公共接口与授权边界变更，属于架构决策型。比较过仅改展示、保留别名和一次性切换；用户于 2026-09-28 选择一次性切换，明确不保留兼容，并接受旧授权、外部插件及历史调用无法映射的风险。若出现需要迁移旧数据的新证据，须重新裁决。
