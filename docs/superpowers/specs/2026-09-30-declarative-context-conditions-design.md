# 上下文键与声明式可用条件设计

## 目标与范围

插件可用声明式条件描述现有贡献的可用性。宿主在上下文变化后重新计算发现结果，并在实际调用时再次检查条件。授权、任务 grants、沙箱和凭据检查继续独立执行。并行变更 `extend-declarative-plugin-contributions` 负责菜单与视图贡献的数据结构和界面入口，并消费本变更的求值接口。

成功标准：同一上下文快照下条件求值确定；键变化可更新命令与工具的可用性投影，并提供供菜单与视图使用的求值接口；插件停用或崩溃后其键和贡献失效；未知键与非法表达式不会使贡献意外可用；直接调用不可绕过条件或原有授权。

## 现状

`plugin.json` 的 `contributions` 声明种类和身份，但没有条件。`PluginManager` 负责原子发布与回收；`RuntimeToolRegistry` 注册后提供工具列表，工具实际执行仍经过任务授权。`commands.register/execute` 经插件宿主路由。Desktop 菜单由组件本地逻辑决定，尚无插件菜单贡献点。web 搜索工具目前依配置选择是否注册，说明配置可用性已经存在，但分散在插件激活逻辑中。

## 组件与数据流

1. `plugin-contracts` 定义上下文键名称、JSON 标量值、受限条件语法以及现有贡献上的可选 `when`。旧插件不声明条件时保持现有行为。菜单和视图贡献的具体字段由并行变更定义。
2. Runtime 的上下文服务持有宿主键和按插件归属的键。宿主提供版本化快照与变更通知；插件只能更新自身命名空间中的键，不能写宿主权威键。键在插件实例退出时回收。值只用于可用性判断，不承载凭据或任务私密数据。
3. 纯解析器将条件编译为 AST，支持布尔键、字符串或数字相等比较、`!`、`&&`、`||` 和括号。安装时验证语法；求值使用不可变快照。表达式中引用任何未知键时，整个条件按 false 处理，避免 `!unknown` 意外变为 true。不执行 JavaScript 或插件回调。条件长度、嵌套深度和键数量设上限。
4. 贡献投影层把插件生命周期、条件结果和既有注册状态合并为命令与工具的发现视图，并暴露通用求值接口供并行变更的菜单、视图贡献消费。上下文变化只刷新投影，不重新激活插件。实际命令与工具调用在宿主入口重新求值，随后照旧执行授权检查。

## 失败处理与兼容

非法条件拒绝该插件清单并给出路径与原因；未知键、尚未设置的键和所属插件已停用均按 false 求值。调用前后上下文变化时，以开始调用时再次检查的结果为准；在途调用遵循现有取消与结果未知规则。条件不作为权限系统，调用仍须通过 grants、跨插件路由和工具安全门。

旧清单没有 `when` 时等价于恒真。新增字段保持 SDK 1.x 的向后兼容读取；如果公共 API 的类型或语义要求版本变更，在 OpenSpec 设计中明确迁移。内置插件可逐步迁移已存在的配置门控，避免本次把所有配置和凭据状态公开为上下文键。

## 验证

定向测试覆盖解析优先级、非法语法、未知键、键归属与回收、上下文变化后的投影、直接调用重检、旧插件兼容，以及条件与 grants 同时生效。迭代期只运行相关测试；准备提交时按 `AGENTS.md` 一次性运行完整门槛。

## Battle 结论

- 类型：架构。
- 当前方案：宿主上下文键和受限声明式条件，共用求值器；菜单与视图贡献由并行变更负责，并使用本变更的求值接口。
- 主要质疑：完整复刻 VS Code 表达式和菜单系统会扩大 UI 与跨进程状态同步范围；界面条件不能代替执行授权。
- 替代方案：各入口使用回调判断。实现局部较快，但判断分散，跨进程状态难以一致，也无法纯声明。
- 最终决策：用户确认采用当前方案，要求直接在 `main` 工作区完成，并在发现并行变更后确认以上所有权拆分。
- 主要权衡：首版语法有限；菜单和视图的最终展示取决于并行变更对本接口的接入。
- 用户覆盖：无。
- 重新开启条件：出现需要插件自定义菜单位置、复杂表达式、或条件必须参与权限决策的明确需求。
