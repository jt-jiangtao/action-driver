# 模型连接服务职责拆分设计

## 目标与现状

降低模型连接逻辑的修改波及面、阅读成本和回归定位成本，保持现有用户可见行为与公共契约。当前 `apps/local-runtime/src/model-connections/service.ts` 约 693 行，包含 21 个方法，同时处理连接管理、模型能力探测、聊天调用和生图资格及运行；对应单一测试文件约 1397 行、35 个显式 `it` 定义，参数化展开后实际运行 41 个用例。这些是结构基线，不代表已测得运行时性能问题。

当前装配点位于 local-runtime 的 `runtime-storage.ts`，公共 `ModelConnectionServicePort` 和 `ModelCompletionServicePort` 位于 `packages/model-connections`。持久规格 `model-connections-backend` 仍称 Electron Main 持有连接并要求操作系统保护密钥；当前密钥由 Main 写入用户数据目录的明文文件。这一规格与实现的冲突留待独立的安全与规格变更处理，本轮不得借重构改变密钥或所有权边界。

## 设计

`ModelConnectionService` 保留公共入口和操作编排。连接的读写、加解密错误映射、草稿验证缓存及异步操作前后的状态复查继续由服务持有，避免改变凭据和并发状态的所有权。把能力探测编排与 Token Plan 双接口探测提取到内部能力测试模块；把模型展示、聊天候选、生图资格与接口选择提取到内部纯规则模块。规则模块不读取存储或网络，也不引入新接口、工厂或跨包依赖。生图运行仍由服务在调用前后核对默认模型、连接配置、启用状态和已验证接口。

测试在 `apps/local-runtime/tests/unit/` 按连接管理、能力探测、生图和聊天调用分组。只共享必要的内存存储、传输和密文测试工具；保留现有 41 个实际运行的用例，先检查异步失效及凭据边界是否存在覆盖缺口，再移动实现。根 `tests/` 仅用于真正的跨包边界断言。

## 验收

- `ModelConnectionService` 的公共方法、两个端口、请求与响应 DTO、错误码、持久格式及现有调用顺序不变。
- 凭据密钥来源、存储和进程传递方式不变；本轮不声称现有实现满足持久规格中的操作系统保护要求。
- 现有 41 个用例及确有必要新增的边界断言通过；重点覆盖并发重测、连接或默认模型在操作中变化、停用模型、Token Plan 双接口证据、无凭据泄漏。
- 新模块形成单向依赖；规则可独立测试，服务仍是状态与副作用的唯一编排点。记录拆分前后的文件职责和依赖，不能仅以行数下降声称维护成本改善。
- 只在准备提交时运行仓库要求的完整 typecheck、lint 和 test 门禁；迭代期仅运行相关定向测试。

## 替代方案与风险

只拆测试并抽取少量纯函数的改动较小，但服务内的能力探测与连接操作仍交错。把所有流程拆成独立服务类则可使入口更短，却需要额外注入、状态同步和抽象，增加新的失效面。选择内部模块加单一编排入口，在当前规模下更易验证。

主要风险是异步校验时机改变、生图资格形成两份实现、Token Plan 双接口顺序或失败诊断改变，以及测试工具过度共享掩盖行为差异。实施采用先写定向回归断言、逐块提取、每块运行相关测试的顺序；若出现公共行为差异，回退该块并重新审视边界。

## Battle 结论

用户要求同时改善修改波及面、可读性和回归成本，已于 2026-09-30 明确裁决先处理模型连接服务和测试，保持公共行为不变。优先浏览器只读沙箱的方案未采用：它跨隔离的 `Runtime.evaluate` 边界，虽然文件更长，拆分风险也更高。规划时发现凭据密钥保护与持久规格冲突；用户进一步明确选择本轮只做服务与测试重构，密钥保护和规格纠偏另立变更。用户未覆盖 Agent 的范围控制建议。若实施要求更改端口、数据所有权、存储格式、安全边界或产品行为，重新开启 Battle。
