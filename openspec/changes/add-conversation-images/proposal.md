## Why

当前对话只接受和展示文本，用户无法上传图片让 Agent 识别，也无法在会话中生成、保存和回看图片。首版需要让图片像文本一样参与对话，同时保持现有聊天模型与工具运行机制可用。

Battle 已完成：用户确认首版覆盖上传识别、文字生图和对话展示；生图先接入 OpenAI Images API 兼容端点；图片及附件按会话分目录保存，消息、任务和事件继续使用 SQLite。模型连接列表直接提供能力开关，由用户选择默认生图模型，不增加自动候选筛选或逐个生图探测。一次生图调用最多并行生成 4 张。无未裁决的关键分歧。

## What Changes

- 输入框支持粘贴、选择、预览和移除图片，也可发送只有图片的消息；不支持视觉输入的聊天模型给出明确反馈。
- 现有模型连接列表为各模型增加图片能力开关，并允许从已开启生图能力的模型中指定默认生图模型；生图调用使用 Images API 兼容端点，不替换当前聊天模型。
- 注册 `image_generate` 工具，一次可按最多 4 条图片需求并行生成；在现有工具生命周期中展示准备、运行、完成、部分失败和取消，已成功图片作为助手消息内容逐张展示。
- 为消息和流协议加入有序图片引用；图片字节按会话保存在独立目录，SQLite 保存结构化记录与引用，重开任务时恢复图片。
- 上传和生成图片的字节不进入 WebSocket、模型调用日志或 Phoenix trace；增加大小、格式和错误处理。
- 首版不包含参考图编辑、局部重绘、遮罩或供应商原生生图协议。

## Capabilities

### New Capabilities

- `conversation-images`: 图片上传、视觉输入、生图结果、会话文件目录、图片流事件与历史恢复。

### Modified Capabilities

- `agent-task-experience`: 输入框可发送图片消息，任务流内展示生成和历史图片。
- `model-connections-settings`: 在现有模型列表配置图片能力开关和默认生图模型。
- `agent-tool-runtime`: 图像生成工具结果可以将图片块带入最终助手消息，而不把二进制混入工具正文。

## Impact

影响桌面端输入框与对话组件、模型连接设置、Runtime 模型适配与工具注册、流协议和任务投影、SQLite 图片元数据与会话附件目录、认证的图片读取接口，以及相关恢复和验收测试。现有纯文本记录保留兼容读取。
