## Why

当前任务页只把等待批准的工具调用显示在对话区外，已运行和已结束的工具过程只能到日志页查看，用户无法在最终回答附近判断 Agent 正在做什么或刚完成什么。将所有 Runtime 工具调用以内联活动卡呈现，可让搜索、文件和 Shell 等操作拥有一致、可恢复且不混入 Assistant Markdown 的可见过程。

Battle 已完成：用户裁决所有 Runtime 工具统一采用 Codex 风格卡片，并区分“正在运行中”和“运行结束”；当前最新运行步骤默认展开，终态步骤默认折叠。无未裁决的关键分歧。

## What Changes

- 在任务对话流中新增工具活动区，按调用生命周期将 `waiting_approval`、`queued`、`running` 与终态调用分组为“正在运行中”和“已完成”。
- 使用同一张稳定、可折叠的卡片贯穿批准、执行、成功、失败、拒绝、超时和取消；等待批准时卡片内保留一次性允许与拒绝操作。
- 在运行卡显示工具名称、受限参数摘要、实时状态与可安全展示的进度；在终态卡显示状态、耗时和已清洗结果/错误摘要，且默认折叠。
- 使实时 WebSocket 投影与任务快照保留展示所需的调用顺序、状态、时间和受限结果摘要；Assistant Markdown 保持仅包含最终模型正文。
- 在重载和重连后恢复终态卡片及其折叠状态的可预测默认值，不把原始工具输出、密钥或 transport 元数据引入 UI。
- 按正文阶段切分连续工具组：初始等待显示“正在思考”，正文与工具组交替呈现；结束后将过程折叠归档，仅保留最后一段模型正文展开。Runtime 生成各工具的安全标题，任务组标题与图标随组内工具变化。

## Capabilities

### New Capabilities

- `inline-tool-activity`: 在任务对话流中分组、呈现并恢复 Runtime 工具活动卡。

### Modified Capabilities

- `agent-tool-runtime`: 扩展工具生命周期事件与投影可供 UI 安全展示的受限活动数据。
- `agent-task-experience`: 将工具活动卡加入 Agent 任务页，并维持正文与执行过程的视觉分离。

## Impact

- 影响 Desktop Renderer 的任务页、实时任务投影、工具审批组件、样式与 E2E 交互契约。
- 影响 Runtime 的工具事件/快照投影和共享 contracts 中的工具展示字段；不会改变工具批准策略、模型工具循环、日志保留边界或引入新依赖。
