## Context

动机见 `proposal.md`。目前 `App` 从 `TaskCatalog.listRecentTasks()` 取得侧栏条目，`DesktopTaskCatalog` 经 HTTP `/tasks` 读取 Runtime；`RecentTaskProjection` 没有会话组织字段。Rollout 投影的 `threads` 表有未接入的 `archived` 列，但其日志、fold 和目录查询都没有归档语义。设置侧栏只支持既有页面路由。

## Goals / Non-Goals

**Goals:** 会话级状态重启后可恢复；目录筛选和分页准确；置顶与归档操作独立于聊天打开；页面为键盘和减少动态效果设置提供可用行为。

**Non-Goals:** 项目归属推断、删除聊天、同步到远程服务、通用侧栏搜索，以及重新设计整个设置导航。

## Decisions

### 1. Runtime 持有会话组织状态

最终裁决：用户于 2026-09-30 选择持久化实现，并确认书面设计。会话组织状态随会话保存在 Runtime；客户端只显示已确认结果。真实替代方案是浏览器/renderer 本地状态：只需修改 UI，但重启、换窗口和投影重建后会丢失组织结果，归档页不能可靠恢复，因此不选。用户没有覆盖 Agent 建议。

### 2. Rollout 增加会话级状态行

增加 `session_state` 日志行，记录完整的 `pinned`、`archived`、`archivedAt` 结果值，不依赖之前行之外的隐含 UI 状态；使用现有每会话递增 `seq` 和 fsync 追加。fold 与 `threads` 投影消费同一行。旧日志默认为 `false`、`false`、`null`。写入成功的定义是日志追加和查询投影更新完成；恢复时投影可从日志重建。

替代方案是只更新现有 `threads.archived` 并加 `pinned` 列。它的写入较短，但投影删除后无法恢复，违背 `rollout-persistence` 规范。另一 SQLite 任务仓储实现相同的目录接口和状态语义，以保持测试和非 Rollout 适配路径可替换；产品部署中的权威来源仍是 Rollout。

### 3. 目录以会话为单位查询

目录每个会话只返回最新任务的 task ID，同时返回 session ID、标题、更新时间、状态和组织字段。新目录读接口分别查询未归档与已归档记录，先执行归档/标题筛选，再执行排序和限制，并提供稳定游标。未归档排序键为置顶优先、`updatedAt` 倒序、session ID；归档目录按 `archivedAt` 倒序和 session ID。标题搜索在 Runtime 进行，不依赖客户端已加载的页。置顶和归档写接口使用 session ID 和目标布尔值，重复 set 幂等；再次设置 `archived=true` 不刷新原归档时间，恢复则清空时间。

替代方案是在桌面端拿固定数量的 `/tasks` 结果后过滤和排序。这会在归档数量超过限制时漏掉聊天，也会导致搜索后续页中的标题失败，故不选。现有 `task.get` 按 task ID 打开的契约保持不变。

### 4. 界面状态与导航

`RecentTaskItem` 将打开聊天的主按钮与两个操作按钮分开，使用 `:hover` 和 `:focus-within` 显示操作。标题测量仅用于计算实际溢出距离；单次左移后保持终点，不适用时保持省略号与完整文本提示。设置页新增独立的归档列表路由，复用 `SettingsSidebar` 和页面壳层；搜索变化重置游标，后续页由“加载更多”读取。一次操作只禁用对应行；成功后刷新最近与归档查询，失败时保留行并显示错误。运行中/排队中归档在 UI 禁用且由 Runtime 再次校验。

替代方案是把归档内容放进侧栏可展开分组，可减少路由，但使侧栏更拥挤，且不符合用户确认的设置页入口，故不选。

## Risks / Trade-offs

- [日志已追加但投影更新失败] → 请求报告失败并在下一次恢复时重放日志；UI 刷新目录后显示权威状态，避免覆盖已提交行。
- [目录在翻页间发生新活动] → 游标包含排序键和稳定 session ID，避免重复；新活动在下一次从首页刷新时出现。
- [当前运行状态在用户点击后改变] → Runtime 在写入前检查会话最新状态；拒绝时 UI 保留原行。
- [长标题动画干扰阅读] → 只处理实际溢出，单次运行后停住，支持焦点与减少动态效果。
- [现有根测试失败] → 迭代期间使用定向测试；最终提交前一次运行全量验证，记录与本次变更无关的失败。
- 用户覆盖：无。若后续要求项目分组或永久删除，需另行裁决，不从截图推断数据所有权或删除恢复策略。

## Migration Plan

1. 扩展日志模型与投影列，使旧日志可按默认值读取和重建。
2. 扩展目录仓储、HTTP 查询与状态变更接口，再接入桌面目录适配器。
3. 接入侧栏与归档设置页；以 Mock 和真实 Runtime 定向测试覆盖行为。
4. 验证后发布。回滚界面仍可保留新增日志行；旧版本若不识别新行会停止在该行，因此发布回滚必须使用能忽略或识别 `session_state` 的兼容读取器，不能直接降回不兼容二进制。
