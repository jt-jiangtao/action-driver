## Purpose

定义 ActionDriver 开发 Agent 在产品与架构决策前必须执行的逻辑审查、方案 Battle、用户裁决和决策留痕规则，使重要决策在进入设计与实现前经过可验证的反驳与权衡，同时允许低风险执行任务高效推进。

## ADDED Requirements

### Requirement: Agent 必须先分类任务
开发 Agent MUST 在开始改变项目状态前，将任务分类为“决策型”或“执行型”，并说明分类依据。只读探索、收集证据和检查现状不视为开始实施。

#### Scenario: 识别决策型任务
- **WHEN** 请求涉及产品方向、用户价值、系统边界、技术选型、数据所有权、公共接口、安全约束或高返工成本变更
- **THEN** Agent 将任务标记为决策型，并进入 Battle 门禁

#### Scenario: 识别执行型任务
- **WHEN** 请求是低风险、可逆、机械性且完全处于已批准决策范围内的工作
- **THEN** Agent 可将任务标记为执行型并直接推进，无需制造形式化争论

### Requirement: 决策型任务必须完成 Battle
Agent MUST 在决策型任务的设计或实施开始前质疑用户观点及自身默认假设，不得仅复述或无条件接受用户提出的产品方案与架构。

#### Scenario: 产品决策 Battle
- **WHEN** 请求包含产品功能、交互流程、范围或优先级决策
- **THEN** Agent 从用户问题、目标用户、使用场景、价值强度、替代方案、复杂度和范围控制等维度提出有依据的质疑与建议

#### Scenario: 架构决策 Battle
- **WHEN** 请求包含组件边界、部署位置、技术栈、数据流、持久化、接口或运行时决策
- **THEN** Agent 从职责边界、耦合、可替换性、失败模式、可测试性、运维成本和演进路径等维度提出有依据的质疑与建议

#### Scenario: 没有实质性反对意见
- **WHEN** Agent 完成审查后未发现足以改变方案的反例或风险
- **THEN** Agent 明确报告已检查的维度和“无实质性异议”的结论，而不是虚构反对意见

### Requirement: Battle 必须比较可执行替代方案
Battle MUST 至少包含当前方案与一个真实可执行的替代方案，并说明各自的证据、收益、成本、风险和适用条件；Agent MUST 给出自己的推荐结论。

#### Scenario: 用户方案存在更优替代
- **WHEN** Agent 发现替代方案在目标约束下明显更优
- **THEN** Agent 明确反对原方案，展示比较依据并推荐替代方案

#### Scenario: 方案取舍依赖用户偏好
- **WHEN** 多个方案不存在客观占优且取舍依赖产品偏好或风险承受能力
- **THEN** Agent 明确指出分歧轴和后果，由用户作出裁决

### Requirement: Battle 必须形成可判定的结束状态
Battle MUST 在目标与成功标准明确、关键假设已检查、替代方案已比较、主要风险已公开且用户完成裁决后才能结束。模糊确认、未回应的关键风险或仅重复原观点不得视为 Battle 完成。

#### Scenario: 接受 Agent 建议
- **WHEN** 用户接受 Agent 的推荐或修订方案
- **THEN** Agent 总结最终决策、被否决方案和主要理由，随后才可进入规划或实施

#### Scenario: 用户覆盖 Agent 建议
- **WHEN** 用户理解已公开风险后仍选择原方案
- **THEN** Agent 尊重用户最终决定，记录覆盖项、已知风险和用户裁决，不得继续循环争论

#### Scenario: 关键分歧尚未解决
- **WHEN** 尚有会改变范围、接口或实施路径的关键分歧
- **THEN** Agent MUST 暂停设计或实施，并继续收集证据或请求明确裁决

### Requirement: 决策结论必须留痕
与 OpenSpec 变更相关的 Battle 结论 MUST 记录在规划产物中，至少包含最终决策、替代方案、主要权衡和被用户覆盖的 Agent 建议；仓库级协议 MUST 为其他类型工作提供统一的简明记录格式。

#### Scenario: 创建产品或架构 OpenSpec
- **WHEN** Agent 为已完成 Battle 的决策型任务创建或更新 OpenSpec
- **THEN** 对应设计产物包含与 Battle 一致的 Decisions 和 Risks / Trade-offs，且任务不得重新打开已裁决问题

#### Scenario: 决策发生变化
- **WHEN** 新证据导致已记录决策需要改变
- **THEN** Agent 重新进入 Battle，更新决策记录并说明替代旧决策的原因

### Requirement: 执行中发现隐藏决策必须升级
执行型任务 SHALL 在不改变已批准决策时直接推进；若执行过程中发现架构冲突、产品歧义、不可逆影响或显著扩张范围，Agent MUST 停止相关写操作并将任务升级为决策型 Battle。

#### Scenario: 机械修改保持在既有边界内
- **WHEN** 实施仅调整已批准设计中的文案、样式、测试或局部实现且不改变外部行为
- **THEN** Agent 继续工作并按正常验证流程完成任务

#### Scenario: 实施暴露新的系统边界问题
- **WHEN** Agent 发现完成任务需要新增跨模块依赖或改变数据所有权
- **THEN** Agent 暂停该变更，说明升级原因并启动架构 Battle
