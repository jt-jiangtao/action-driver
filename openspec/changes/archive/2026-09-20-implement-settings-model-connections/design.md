## Context

现有 Electron renderer 使用 React、本地组件、全局 CSS 和 Inversify 管理 Mock 服务；路由由 `App` 内部状态控制，侧栏同时服务首页与任务页。Figma 节点 `273:5` 定义页面，`215:6839` 及其子组件定义模型状态、模型行、连接卡片、空状态和添加流程。参见 proposal.md 与本变更的 capability specs。

## Goals / Non-Goals

**Goals:**

- 以现有 React/CSS 体系复刻已确认设计，不把页面强行映射为 Ant Design 组件。
- 将页面容器、模型集卡片、状态胶囊、添加对话框和 Mock 数据能力拆成可独立测试的单元。
- 通过类型化的 renderer 内 Mock 服务驱动全部状态和交互。
- 让新增 Settings 导航不改变首页与任务页现有布局和行为。

**Non-Goals:**

- 不接入真实模型提供商、系统密钥链、持久化数据库或 main/preload IPC。
- 不实现 Settings 其他栏目、Skills 或 MCP 页面。
- 不引入新的 UI 或图标依赖。

## Decisions

### 1. 复用现有 renderer 架构并增加独立 Settings 页面

在 `App` 的轻量路由状态中增加 Settings 路由，扩展 `Sidebar` 的受控导航 API；页面内容由独立 `SettingsPage` 和聚焦的模型连接组件组成。替代方案是引入路由库，但当前只有三个本地页面，引入依赖与迁移成本高于收益，因此不采用。

### 2. 使用内存 Mock 服务作为单一事实来源

定义模型集、模型测试状态与添加草稿的类型，由内存 Mock 服务提供列表、发现、刷新、测试、切换、添加和删除方法；React 页面只维护视图瞬时状态并在操作后读取服务结果。替代方案是把所有数据直接写在组件 state 中，但会让接口行为和视图耦合，难以单测状态转换，因此不采用。

### 3. CSS 与现有 Token 优先，Lucide 图标按语义选择

复用 `--ad-*` Token，并用页面作用域 CSS 复刻 Figma 的尺寸、间距和状态色。连接/网关采用 `Network` 或 `Cable`，具体模型采用 `Box`/`Cpu`，添加采用 `Plus`；不复用截图中语义过泛的 `Server`。替代方案是复制 Figma 的临时 SVG URL，但资源会过期且与仓库已有 Lucide 体系重复，因此不采用。

### 4. 用可控短延迟暴露异步状态

Mock 测试和刷新返回 Promise，并以可控短延迟让 UI 可观察“测试中”；测试夹具可注入确定结果以覆盖部分失败和全部成功。替代方案是立即同步返回，但无法可靠验证加载状态，因此不采用。

本任务是已批准范围内的执行型变更，无需 Battle；已检查产品范围、公共接口、数据所有权、跨进程边界和依赖成本，未发现实质性异议。

## Risks / Trade-offs

- [页面状态较多导致组件膨胀] → 按页面、卡片、对话框、状态胶囊和服务拆分，并以行为测试约束接口。
- [异步 Mock 测试易产生计时不稳定] → 使用可注入延迟和 Testing Library 的异步查询，避免依赖真实时间。
- [Settings 导航破坏既有页面] → 保留 `Sidebar` 固定宽度与现有回调，增加首页/任务页回归测试。
- [Figma 原始 Server 图标语义不足] → 按用户补充意见改用连接、模型和 Plus 的差异化 Lucide 图标；这是对视觉细节的已确认修正，不改变交互结构。

## Migration Plan

以 renderer 层增量发布：先增加测试和 Mock 服务，再接入页面与导航，最后运行类型检查、完整测试和构建。若需回滚，可移除 Settings 路由与新增文件，原首页和任务页 API 保持兼容。
