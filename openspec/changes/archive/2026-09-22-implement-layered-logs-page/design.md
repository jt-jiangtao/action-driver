## Context

参见 `proposal.md` 的 Why。Renderer 已有 `LogsPage`、`InteractionLogService`、桌面真实实现 `DesktopInteractionLogService` 和测试用 `MockInteractionLogService`；本地桌面组合根会把真实服务注入页面。现有页面把筛选、控制台列表和单条详情集中在一个组件中，领域模型只覆盖接口交互记录，不包含模型会话、任务或动态调用链。

设置页已经使用 `SettingsSidebar`，并已有“模型连接”和“日志”入口。实现必须保留这一组件边界和模型连接入口，但具体日志内容组件不必为了组件化牺牲已确认视觉还原。现有真实接口日志契约没有完整的 sessionId、taskId、请求正文和响应正文，因此本次只能展示服务当前可提供的真实字段；不得用 Mock 补齐缺失字段并冒充真实数据。

## Goals / Non-Goals

**Goals:**

- 用清晰的数据边界同时呈现真实接口日志和 Mock 模型日志。
- 将日志列表、接口详情、模型会话列表和模型会话详情拆成可独立测试的组件。
- 完整表达已确认的展开、收起、选中、返回、自动刷新、空态、错误态和多结果状态。
- 保持现有依赖注入与设置侧栏导航，不引入新的运行时依赖。

**Non-Goals:**

- 不实现真实模型日志采集、存储、查询或跨进程协议。
- 不扩展 `InteractionLogRecord` 的持久化字段来伪造 sessionId、taskId 或请求/响应正文。
- 不修改 Main/Preload/服务端日志链路、文件轮转、日志级别或脱敏与凭据安全策略。
- 不在本次实现中迁移到新的路由库或设计系统。

## Decisions

### 1. 接口层继续依赖现有服务契约，模型层使用独立 Mock 契约

接口层由 `LogsPage` 接收的 `InteractionLogService` 提供数据；生产组合根继续注入 `DesktopInteractionLogService`，测试注入可控实现。模型层新增独立的会话、任务、调用节点类型和确定性 Mock 数据源，避免把两种语义塞入 `InteractionLogRecord`。

替代方案是扩展单一日志记录类型并给接口与模型数据增加大量可选字段。该方案会让字段归属、真实/模拟边界和详情渲染都变得含糊，因此不采用。最终裁决：两个数据契约、一个统一页面壳层。

### 2. `LogsPage` 只负责层级与页面态编排，内容拆成聚焦视图

`LogsPage` 维护当前层级与模型列表/详情状态；接口层视图拥有真实查询、筛选、轮询和选中记录；模型层列表拥有筛选、会话展开与详情入口；模型详情拥有调用选择和各数据区块的开合状态。共用的状态徽标、折叠区块和空态可提取为小组件，设置侧栏继续复用现有 `SettingsSidebar`。

替代方案是继续把全部行为保留在单个组件。虽然初始改动较少，但测试隔离和状态恢复会快速恶化，也容易让一次刷新重置不相关视图，因此不采用。

### 3. 模型详情使用页面内显式视图状态，不引入路由依赖

打开模型详情时，以 `selectedSessionId` 和可选 `selectedTaskId` 将日志主内容切换为全页详情；返回时清除详情选择，恢复模型列表的筛选和展开集合。调用导航按 Mock 数组顺序渲染，不硬编码步骤名称或数量。

替代方案是为详情引入 URL 路由。当前桌面应用仍使用轻量页面状态，单独引入路由库会扩大迁移范围；本次没有深链接要求，因此不采用。若未来日志详情需要可分享地址，再单独决策路由策略。

### 4. 真实接口详情只展示契约中实际存在的数据

详情面板将现有字段组织为摘要、请求/操作信息、结果/错误信息和原始记录 JSON。若没有请求正文或响应正文，区块显示“当前日志源未记录正文”或相应摘要，而不是生成示例正文。关闭详情仅清除选择，不重置筛选、搜索和自动刷新。

替代方案是同步扩展主进程与服务端日志协议以采集完整正文。该方案涉及数据所有权、敏感信息和存储体积，是新的架构与安全决策，超出已批准范围，因此不采用。

### 5. 自动刷新以单飞读取和稳定选择为约束

接口层沿用定时刷新，但用进行中标记避免请求重叠；刷新后若选中记录仍存在则保持详情，否则关闭详情并回到列表。模型 Mock 视图可以呈现自动刷新控件和可预测状态，但不以计时器随机改变数据，以保持测试与视觉验收稳定。

替代方案是让 Mock 数据随时间随机变化以模拟运行。该方案造成不可重复测试和截图漂移，因此不采用。

### 6. 测试先行覆盖行为与数据来源边界

先修改或新增组件测试，使其在实现前因缺失行为失败：层级切换、真实服务调用、错误不回退 Mock、会话开合、全页详情返回、动态调用导航、各折叠区块以及设置侧栏入口。实现完成后再运行日志页定向测试、Renderer 测试集、交互契约校验和构建。

替代方案是先完成视觉实现再补快照。快照不能证明真实/Mock 数据边界和状态迁移，且与仓库 TDD 约束冲突，因此不采用。

## Risks / Trade-offs

- [模型层 Mock 与未来真实协议发生漂移] → 把 Mock 限制在独立服务边界，使用稳定领域类型；未来接入真实服务时替换适配器而不是重写视图。
- [现有真实接口日志字段不足以完全还原设计稿中的请求/响应正文] → 明确显示当前数据源可用内容和缺失提示，不伪造数据；协议扩展另立决策型变更。
- [自动刷新导致用户正在查看的详情跳动或消失] → 以稳定记录键恢复选择；记录不再存在时才关闭详情，并保持筛选条件。
- [大量原始 JSON 影响渲染性能] → 默认收起重内容区块，仅在用户展开时渲染格式化内容；本次不引入虚拟列表依赖。
- [“不需要脱敏”的早期设计意见与仓库既有凭据安全约束冲突] → 本次不改变采集与脱敏策略，只展示真实服务已经返回的字段；任何取消脱敏的实现必须另行完成安全 Battle。
- [并行的 HTTP 迁移改变真实日志实现] → 页面只依赖 `InteractionLogService`，不直接读取文件或绑定传输细节，使实现可随组合根替换。

## Migration Plan

1. 先以失败测试固定新页面行为与真实/Mock 数据边界。
2. 添加模型层领域类型和确定性 Mock 数据，再拆分日志视图组件。
3. 将接口层现有查询能力迁入新的接口视图，保持服务契约和生产注入不变。
4. 完成样式、交互契约与视觉验证；若回滚，只需恢复 Renderer 页面与样式，不涉及数据迁移。
