## Context

现有活动卡以安全摘要和运行/完成分组呈现；本变更改为由 Runtime 驱动的正文与动态活动任务时间线，并在结束态归档。见 proposal.md。

## Goals / Non-Goals

**Goals:**
- 以 Codex 风格呈现动态活动任务、正文、工具、脚本 I/O、结论和产物。
- 让结束态默认聚焦结论，过程可按需展开。

**Non-Goals:**
- 不改变模型工具循环、权限策略或远程部署边界。

## Decisions

### 1. 动态活动任务替代固定工具分组

一个 Turn 的过程由按 cursor 排列的正文片段和动态 `ActivityGroup` 组成。活动任务拥有稳定 `activityId`、`title`、单调递增的 `titleRevision` 与终态；其内部可混排正文、网页搜索、文件读取、Shell 与文件编辑。任务名称来自 Agent Graph 的受控、面向用户摘要，允许由“正在调研”更新为“已完成 Codex 事件模型调研”，但不得展示原始思维链。替代方案是按固定工具族或每次 LLM 调用分组；前者不能表达异构工作目标，后者会造成不稳定且噪声过多的 UI。用户裁决动态活动任务。

Runtime 发布 `activity.started`、`activity.updated`、`activity.text` 与 `activity.completed` 事件，并把 `activityId` 关联到工具和文件事件。标题更新只更新同一 id 的展示属性，不重新排序，也不重置 Renderer 的展开状态。正文可带 `activityId` 进入任务内部，也可不带归属而成为两个任务之间的独立时间线项。

Agent Graph 通过仅内部可见、无外部副作用的 `activity.update` 元操作接收模型生成的 `activityId`、标题和 `titleRevision`。Graph 拦截该元操作并发布活动事件，而不是把它呈现为普通工具调用或交给外部执行器；后续可见正文、工具和文件事件继承当前活动任务归属。

### 2. “正在思考”是尾部状态行

“正在思考”不是任务标题或容器。初始生成、一个活动任务结束后等待下一次模型输出、或工具结果已返回而下一轮模型尚未开始时，Renderer 在时间线末尾显示这一临时状态行并播放低强度扫光。新的正文、活动任务或最终结论到达后取代它；终态历史中不保留空的“正在思考”条目。

### 3. 结束态归档而非完成卡列表

结束后将事件树收进“用时”折叠项，结论和文件产物显示在外层。替代方案是保留完成卡列表；其会分散结论焦点。用户裁决归档。

### 4. 审批位于输入框上方

`tool.waiting_approval` 仍是 Runtime 的持久化工具状态，但 Renderer 将其映射为输入框上方的阻塞审批条，而不是过程时间线的一行。批准、拒绝、超时或取消后，审批条消失，结果回写到所属活动任务内的工具项。替代方案是把审批作为过程节点；其会把需要立即决策的操作淹没在历史中。用户裁决输入区审批条。

### 5. 本地 Runtime 原始 I/O

本地 Runtime 活动投影可显示原始输入输出，使用滚动容器和底部渐隐，且不以 `NODE_ENV` 区分。替代方案是环境变量门控或受限摘要；前者会让相同本地链路因打包方式产生不同体验，后者能降低泄露面。用户明确裁决移除环境门控，并接受路径、凭据和敏感响应可见风险。

## Risks / Trade-offs

- [原始 I/O 泄露] → 限于本地 Runtime 链路，明确显示风险边界；不以 `NODE_ENV` 作门控。
- [超大输出影响性能] → 虚拟/上限输出和滚动渐隐。
- [扫光降低可访问性] → 遵循 reduced-motion 偏好。
- [标题更新乱序] → `activityId` 与递增 `titleRevision`，拒绝过时更新。
- [任务边界被 UI 猜错] → Runtime/Agent Graph 是活动事件唯一来源；前端不按工具类型或 LLM 调用次数推断。
- [日志范围扩大] → 每次 LLM 调用与工具结果的原始记录、脱敏、保留期和 UI 暴露策略尚未裁决，不纳入本次活动分组实现。

## Migration Plan

1. 扩展活动事件、持久化投影与重连过程树。
2. 替换任务页运行、输入区审批与结束态视图。
3. 覆盖动态标题、正文交错、I/O、折叠、动画和重连 E2E；回滚到摘要卡。
