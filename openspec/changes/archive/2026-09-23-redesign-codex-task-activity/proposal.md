## Why

当前工具活动以受限摘要卡呈现，不能表达本地开发时脚本的完整输入输出，也无法保留正文、异构工具调用与动态工作任务之间的真实时序。开发者需要在运行中检查真实执行细节与阶段性说明，并在结束后把过程收纳为可回看的记录。

Battle 已完成：用户裁决本地 Runtime 链路允许原始 I/O 显示，且不以 `NODE_ENV` 区分，并接受凭据、路径和敏感响应可能进入 UI、截图与会话历史的风险；生成中采用按真实时序平铺的正文片段与动态活动任务，生成结束将过程收进“用时”折叠项并保留结论与产物。活动任务使用 Agent Graph 生成的受控、面向用户的摘要，可在进展中更新名称；这不展示原始思维链。完整 LLM 调用与工具结果的日志保留范围、脱敏、保留期和 UI 暴露方式仍为未决项。

## What Changes

- **BREAKING** 将任务页的“运行中 / 运行结束”工具卡替换为 Codex 风格的任务活动记录。
- **BREAKING** 以 `Turn → 正文片段 / 动态活动任务 → 单条事件 → 最终结论` 替代平行的正文与工具数组投影；活动任务可混合正文、网页搜索、文件读取、Shell 与文件编辑。
- 初始或上一个活动任务结束且等待下一次模型输出时，在时间线尾部显示“正在思考”临时状态；它不是活动任务标题。运行中的活动任务和工具使用低强度扫光动画。
- 活动任务由 Runtime/Agent Graph 提供稳定 id 与可修订标题；标题更新不改变既有条目顺序或展开状态。运行中按时间平铺正文和任务内事件；展开项显示本地原始输入、输出、滚动区和底部渐隐。
- 将等待审批从过程时间线移至输入框上方的阻塞审批条；批准、拒绝、超时或取消结果仍回写对应工具项。
- 结束后把完整过程归档至“用时 N 秒”的折叠记录，结论正文和文件变更等产物显示在其后。
- 为本地开发 I/O 建立显式展示模式与数据边界，不影响模型工具循环。

## Capabilities

### New Capabilities

- `codex-task-activity`: 定义 Codex 风格动态活动任务、正文时间线、结束态归档、原始 I/O 和扫光反馈。

### Modified Capabilities

- `agent-tool-runtime`: 扩展有序事件投影，使本地开发活动记录可关联活动任务、正文、原始输入、输出和脚本层级。
- `agent-task-experience`: 调整任务页的生成中、生成结束、状态行、审批、结论与产物呈现。

## Impact

- 影响 Runtime 活动/工具事件、持久化/重连投影、Desktop Renderer 的任务页与输入区及其样式、测试与 E2E 契约。
- 本地 Runtime 增加敏感数据展示风险；不新增远程服务或第三方依赖。
