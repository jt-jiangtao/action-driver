## Why

真实模型工具流未发送 `activity.update` 时，任务页会回退到旧的“运行中 / 运行结束”工具卡，违背已发布的 Codex 风格活动时间线契约。快照恢复也未重建活动过程，导致已完成任务重新打开后无法稳定回看过程。当前页面还将累计助手正文放在整个活动时间线之前，因而工具之间的正文失序。

原回归修复属于执行型；用户随后裁决将 `activity_update` 从模型工具移入运行流程，并要求工具关联及正文顺序在实时、重连和恢复后完全一致。此部分改变模型工具契约与投影职责，升级为架构决策型。Battle 已比较模型元工具、额外 LLM 标题调用、运行时规则，以及复制 OpenAI 式额外序号；用户选择运行时规则并允许移除冗余字段。主要权衡是标题较泛化，但不增加调用延迟，且由持久化 `cursor` 保证顺序。

## What Changes

- Runtime 在任务启动时生成受控的默认活动记录；工具调用缺少模型显式活动更新时仍强制归属该活动，并将一个连续工作阶段的 `n` 条工具调用与其间正文关联到同一任务。
- 不再向模型暴露 `activity_update`；运行时在每次外部工具调用前按规则修订活动标题，工具结果不再包含合成的活动工具回复。
- 以持久化事件 `cursor` 统一投影正文、活动及工具顺序，实时流、重连和快照共用同一顺序规则。
- 活动过程成为快照与恢复投影的一部分，确保重连和重新打开任务后仍保留任务、工具、正文及原始 I/O 的顺序。
- Desktop 任务页停止将存在工具记录的真实任务回退为旧的分组工具卡；活动时间线以 Codex 风格的扁平行呈现运行态、归档态与原始 I/O。
- 按参考截图校准活动与子工具行的图标、左侧对齐和展开箭头，并将 Shell I/O 展示为终端记录；本轮不移除审批流程。
- 补充真实普通工具流与快照恢复的单元及桌面 E2E 回归覆盖。
- 修复 Renderer 刷新后丢失当前任务导航状态的问题：只在会话存储中记住当前任务 ID，页面重建时从 Runtime 持久化快照恢复标题、消息和活动过程；任务列表加载失败不阻断详情恢复。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `codex-task-activity`: 要求所有实际工具流与恢复投影均呈现动态活动任务，而非旧工具类别卡。
- `agent-tool-runtime`: 要求每次工具调用获得受控活动归属，且活动过程可按原始顺序在快照中恢复。

## Impact

- 影响 Agent Graph、Stream Session 的事件与快照投影，以及 Desktop Renderer 任务页和相关单元/E2E 测试。
- 不新增第三方依赖，不改变工具权限或远程服务边界；模型工具列表将移除内部活动元工具。
