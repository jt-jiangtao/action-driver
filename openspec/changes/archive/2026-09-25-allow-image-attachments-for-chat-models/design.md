## Context

参见 proposal.md 的 Why。现有 `ModelKind`、`testState` 和 `imageGenerationApi` 分别承载互斥类型、单一测试结果和手工生图路由。Runtime 已有聊天、Images API 与 Token Plan 适配器，桌面已有添加模型与默认生图设置。现有图片上传、会话资产和失败任务展示应保留。

## Goals / Non-Goals

**Goals:** 逐模型、逐能力记录真实测试；设置页清楚区分目录提示与测试结论；用测试结果约束聊天、附图和默认生图；根据连接自动选择生图接口；迁移旧数据并保留图片展示修复。

**Non-Goals:** 不测试或调用语音、Realtime、视频；不保证任意第三方接口都有可验证的推理信号；不自动测试所有已发现模型；不改图片资产目录或历史消息内容。

## Decisions

1. **目录只决定候选探测，不充当成功证据。** Runtime 维护用户列出的 Token Plan 模型能力目录，发现列表仍以提供方为准，手工 ID 继续可添加。测试时对目录声明的文本、推理、视觉、生图能力运行对应真实探测；未知模型在协议支持时尝试文本、视觉、生图，推理仅在存在明确请求和响应契约时尝试。旧类型与目录声明均不产生测试成功状态。替代方案是继续手工分类，成本低却重复用户误配置；另一方案是每个模型盲测全部接口，会对已知音视频模型产生无意义请求和额外计费。用户选择目录引导的逐项测试。
2. **每种能力独立持久化。** `text`、`reasoning`、`vision`、`image_generation` 各有状态、来源、测试时间及安全的错误摘要。状态包括未测试、测试中、成功、不支持、失败、无法判定。HTTP 成功但内容不足不算成功；鉴权、限流、网络和超时失败不等同于“不支持”。单项重测只覆盖本项，不清除其他成功项。目录排除与提供方明确拒绝的来源分开显示；实际成功优先于目录提示。替代方案是扩展单个 `testState`，不能表达模型兼具多项能力。
3. **真实探测的完成条件。** 文本要求非空有效回复；视觉提交内置图片并要求回答与图片内容相符；生图实际生成一张图片并校验图片字节；推理只在提供方公开的推理字段或等价证据出现时判成功，普通最终文本为“无法判定”。每项有超时和取消，结果独立保存，测试图不进入会话。音频和视频只显示目录标签“未接入测试”。替代方案是只发 `ping`，无法证明视觉或生图可用。
4. **严格视觉门槛。** 桌面端提交前与 Runtime 最终校验都读取当前模型的视觉成功状态。未测试、不支持、失败、无法判定均阻止附图并保留输入草稿，给出模型测试入口；纯文字仍依据文本成功状态。替代方案是所有模型都尝试发送并由提供方报错；用户看到 `qwen3.7-max` 的真实 400 后最终裁决采用预先阻止，接受需要先测试的代价。测试成功后提供方行为变化而拒绝时，任务页继续展示真实错误。
5. **生图路由由 Runtime 选择。** 官方 Token Plan 网关使用现有 Token Plan 生图适配器，其他 OpenAI 兼容连接使用 Images API 适配器。设置页仅提供已通过生图测试模型的“设为默认生图”，无手工类型或接口字段。同一模型允许文本与生图都成功；停用、删除、测试失效时清除默认引用。替代方案是用户手工指定接口，可覆盖非标准网关，但会重现当前配置错误；本轮按用户裁决先采用自动路由。
6. **渐进迁移。** SQLite 增加能力测试记录；旧文本测试成功与旧生图类型或默认引用只迁为待重测提示，不视为新验证成功。连接密钥、模型 ID、启用状态、原默认引用及会话资产保留；原默认引用在重测前显示为待验证且不可执行生图。刷新不删除未变化模型的测试记录；连接凭据或地址变化时结果失效。替代方案是直接把旧单一状态当新能力成功，无法证明视觉与生图。
7. **保留已完成图片交互修复。** 输入附件仍在卡片内文字上方；用户消息同一气泡内图片在文字上方，使用 104×104 方框完整缩放并可放大；提供方拒绝时错误出现在该轮回复位置。此项属于此前已裁决并实现的范围，不因能力模型改造回退。

## Risks / Trade-offs

- [真实生图测试可能计费或耗时] → 只在用户主动测试时生成一张图片；每项有超时和取消，不在发现或刷新时自动探测。
- [旧模型升级后暂不可用] → 保留数据并突出显示“需要重新测试”；仅成功测试后进入聊天和生图候选，避免把旧 `ping` 误当新能力证据。
- [视觉测试误判] → 使用固定图片内容与可核验回复，只有明确成功才放行；失败详情可查看并允许重测。
- [推理接口缺少可验证证据] → 显示“无法判定”，不以普通文本回复推断推理能力。
- [提供方测试后能力变化] → 运行时继续处理并展示实际错误，不伪造成功。
- [自动路由不适合非标准网关] → 显示测试失败与路由说明；若出现真实兼容例外，再开启新的接口选择决策，不在本轮加入手工覆盖。

## Migration Plan

使用加法 SQLite 迁移保存每项能力状态和来源，读取旧列作待重测提示；部署后保留旧列用于回滚读取。设置页显示旧默认生图引用但标记待验证，重测通过后恢复可用；重测失败或删除模型时清理该引用。回滚到旧版时，新能力记录被旧版忽略，原连接与图片仍可读取。
