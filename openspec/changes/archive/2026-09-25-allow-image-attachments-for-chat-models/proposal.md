## Why

模型列表目前要求用户手工指定“聊天/生图”类型和生图接口，单一测试状态又无法表达文本、推理、视觉、生图之间的差异。真实含图请求曾被提供方拒绝，并在界面中留下空白回复；用户需要依据逐项测试结果选择可用模型，且仅允许通过视觉测试的模型接收图片。

Battle 已完成：比较了继续手工分类、对所有模型盲测所有接口、由模型目录引导并以真实逐项测试为准三种方案。用户选择第三种，并裁决未测试、结果不确定或失败的视觉模型不得发送附图；音频与视频只展示目录能力，不发起测试。书面设计见 `docs/superpowers/specs/2026-09-25-model-capability-probes-design.md`，无未裁决关键分歧。

## What Changes

- 保留已经完成的输入卡片置顶附件、同一用户气泡中图片在文字上方、小正方形完整缩放及失败回复就地展示。
- **BREAKING**：模型不再由用户指定互斥的聊天/生图类型，设置页不再显示生图接口或识图、生图开关；逐项展示文本、推理、视觉、生图的目录提示和实际测试结果。
- 用户主动测试模型时，根据模型目录与连接类型执行适用的真实测试；音频、视频模型仅展示其能力标签与“未接入测试”，不提供调用或成功状态。
- 已通过文本测试的模型进入聊天选择器；已通过生图测试的模型可被用户设为全局默认生图模型。Token Plan 与 Images API 的路由由 Runtime 决定。
- 附图发送前，桌面端与 Runtime 均要求当前聊天模型的视觉测试成功；不满足时保留草稿并提示测试。测试后提供方再次拒绝时仍展示真实错误。
- 旧连接和模型数据保留，旧单一测试状态及手工类型只作为迁移提示；旧模型重新测试后才用于聊天或生图。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `conversation-images`：含图提交改由成功的视觉测试决定，并保留失败反馈与紧凑图片布局。
- `model-connections-settings`：以逐项能力测试和默认生图选择替代手工模型类型与生图接口配置。

## Impact

影响模型连接 DTO/HTTP/SQLite、提供方探测、设置页与模型选择器、桌面提交与 Runtime 校验、默认生图路由及迁移测试。生图测试会实际生成一张可能计费的图片，但仅在用户主动测试时执行；不新增音视频调用能力，不改变会话图片按目录存储。
