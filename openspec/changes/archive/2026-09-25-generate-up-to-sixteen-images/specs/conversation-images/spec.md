## MODIFIED Requirements

### Requirement: 生图进度与结果进入对话
系统 SHALL 在 Agent 调用生图工具时展示运行状态。单次调用 MUST 支持 1 至 16 条独立图片需求，每条需求可使用不同提示词；同一次调用最多同时执行 4 条，其余排队。已配置 `Images API` 或 `Token Plan` 接口的默认生图模型 SHALL 通过对应接口生成图片。每张成功图片 SHALL 在完成后作为该轮助手消息的图片内容出现。失败、取消与超时 SHALL 显示明确状态，不得出现空白成功图片。助手回复的文字区 MUST 始终显示在生成图片区上方，运行中与完成后顺序不得跳变。

#### Scenario: 文字生图完成
- **WHEN** Agent 使用已配置的生图模型生成图片
- **THEN** 任务过程显示生图工具的状态，最终助手消息显示可放大和保存的图片

#### Scenario: Token Plan 模型生图
- **WHEN** 默认生图模型选择了 `Token Plan` 接口且提供方返回图片
- **THEN** 系统使用 Token Plan 同步生图接口获取图片，将其保存为本会话资产并在对话中展示，历史消息不依赖提供方临时图片地址

#### Scenario: 并行生成多张图片
- **WHEN** Agent 在一次生图调用中提交 2 至 16 条图片需求
- **THEN** Runtime 在同一次调用中保持最多 4 条需求同时执行，已完成一条才启动下一条；对话在开始时显示同数量的稳定占位卡，每张图片完成后按输入插槽原位替换，最终显示所有成功图片

#### Scenario: 超过单次上限
- **WHEN** 生图工具收到第 17 条图片需求
- **THEN** 工具在发起任何生图网络请求前拒绝该调用，并向 Agent 返回输入无效状态

#### Scenario: 一张失败但其他图片成功
- **WHEN** 并行生成中部分请求失败
- **THEN** 已成功图片继续展示，失败插槽显示失败状态，工具显示部分失败与失败数量，不把整批结果伪装为全部成功

#### Scenario: 取消并行生图
- **WHEN** 用户在多张图片生成期间取消任务
- **THEN** Runtime 中止仍在运行的请求、不启动排队中的请求，已经完成并持久化的图片保留，未完成的插槽显示取消状态，不显示为成功

#### Scenario: 生图失败
- **WHEN** 提供方返回错误或生成超时
- **THEN** 工具显示失败原因，助手消息不包含无效图片，模型可继续给出文字反馈

#### Scenario: 生图占位动画
- **WHEN** 生图工具开始执行 1 至 16 条图片需求
- **THEN** 对话在助手文字下方显示同数量的圆角浅灰点阵占位卡，以柔和动画标识进行中；卡片数量与位置在完成前保持稳定

#### Scenario: 减少动态效果
- **WHEN** 系统启用减少动态效果且生图正在运行或图片刚完成
- **THEN** 占位卡和图片无连续动画或淡入，进度及结果仍可辨认

#### Scenario: 完成前后文字与图片顺序一致
- **WHEN** 助手在生图前或生图期间写入文字，随后部分或全部图片完成
- **THEN** 文字始终位于生成图片画廊上方；响应结束、重连及历史打开后顺序不变化，用户上传图片气泡的顺序不受影响

### Requirement: 传输与日志不携带图片字节
系统 MUST 在对话流、快照和持久化事件中传递图片标识与元数据，不得直接传递图片 base64；模型调用日志与遥测 MUST 排除上传和生成图片的字节。生图进度 MAY 传输请求张数、调用标识和插槽编号，但 MUST NOT 依赖传输提示词正文或图片字节来建立占位卡。

#### Scenario: 图片生成后断线重连
- **WHEN** 客户端在图片生成后重连或恢复快照
- **THEN** 它通过持久化图片引用恢复同一结果，事件中不包含图片字节，也不会重新运行生图工具

#### Scenario: 并行生成期间断线重连
- **WHEN** 部分图片已完成、其他图片仍在生成时客户端重连
- **THEN** 快照恢复已完成图片及未完成数量，后续成功图片继续按持久化事件出现

#### Scenario: 乱序完成后恢复插槽
- **WHEN** 16 张图片以不同于请求顺序的次序完成，随后客户端断线并恢复
- **THEN** 已完成图片仍占据各自原有插槽，未完成插槽继续显示进行中状态，事件与快照不包含图片字节
