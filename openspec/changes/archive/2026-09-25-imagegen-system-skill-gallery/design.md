## Context

`image.generate` 已按 1–4 条需求并行执行，`tool.asset` 带有调用 ID 和输入索引。界面目前只看到已完成图片，运行中没有每张图片的稳定位置。更明显的是 Runtime 和桌面投影在 `response.end` 都把图片移到文字前面，导致结束时跳位；持久化记录继承这一顺序。

系统 Skill 已从随包资源播种到 `~/.action-driver/skills/.system`，可在设置中查看及启停。Codex Imagegen Skill 的原始执行说明依赖 Codex 内置生图工具，不能直接成为 Action-Driver 的默认调用路径。

## Goals / Non-Goals

**Goals**

- 开始生图即显示 1–4 个稳定插槽，以柔和点阵动画提示进行中，逐张原位替换。
- 助手文字在流式、结束、快照、重连和旧记录展示时都位于生成图片上方。
- 完整随包复制 Imagegen Skill 的文件与许可证，并使默认执行说明指向现有 `image.generate`。
- 保留图片资产引用和用户消息样式的现有兼容性。

**Non-Goals**

- 新增生图提供方、模型配置流程或新的图片编辑 API。
- 让随附的备用 Python CLI 成为默认执行路径，或自动安装其可选依赖。
- 改变用户上传图片在用户气泡内的既有顺序和 104×104 缩略图布局。

## Decisions

### 1. 以非敏感元数据建立固定插槽

生图工具进入执行态时将 `images.length` 作为可选 `imageCount` 传给工具流事件及任务快照；`tool.asset` 和 `response.image` 的已有索引继续表示输入位置。持久化助手图片部件增加可选的 `{callId, index}` 来源信息，供快照与历史恢复。调用 ID 区分同一轮内多次生图；旧数据没有这些字段时按原图片相对顺序展示。

**替代方案：** 从 `rawInput` 解析张数。该字段可能因用户设置而不可用，且会让 UI 依赖提示词正文，因此不采用。

### 2. 统一归一助手内容顺序

Runtime 生成持久化内容以及桌面投影读取流式、结束和历史消息时，均使用同一个“助手文字区在前、生成图片区在后”规则。旧版图片在前的记录在读取投影时也归一；不改变用户消息。图片插槽按 `(callId, index)` 排列，同一插槽重复事件按资产 ID 与来源键去重。这样修复的是助手生成媒体的通用呈现不变量，而非按模型或请求特判；不依赖 CSS `order` 掩盖数据顺序错误。

**替代方案：** 只改完成事件或用 CSS 调换视觉顺序。前者仍会在历史和重连出现跳位，后者让屏幕阅读器与持久化顺序不一致，因此不采用。

### 3. 画廊组件负责进度与插槽状态

对话中的助手文字区后渲染画廊。每次生图调用产生自己的 1–4 个卡片，开始时即保留数量与位置；成功则原位替换为既有 `ConversationImage`，失败、取消或缺失显示对应状态，已经成功的图片保留。最多两列，窄容器单列。动画仅使用低幅度不透明度变化和轻微淡入，并对 `prefers-reduced-motion` 完全关闭。

**替代方案：** 只保留一个等待卡，完成后追加图片。虽然改动较少，但不能展示并发数量或保证逐张原位替换，不符合已确认的交互。

### 4. 完整复制并适配 Imagegen 系统 Skill

将本机 `.codex/skills/.system/imagegen` 下的 `SKILL.md`、`references`、`scripts`、`assets`、`agents` 和 `LICENSE.txt` 全部复制到随包 `system-skills/imagegen`。保留许可证与引用关系；把主 Skill 和必要入口元数据中的默认执行步骤改成 Action-Driver 的 `image.generate`，明确附带 CLI 仅供参考且并非隐式回退。加入系统 ID 保护、初始化播种及打包资源校验；继续使用现有启停逻辑和模型权限。

**替代方案：** 原样复制。它默认调用本应用不存在的 Codex 内置工具，用户启用后仍无法生图，因此不采用。

## Risks / Trade-offs

- 事件与消息部件增加可选字段。所有旧记录和旧快照都必须继续可读；协议测试覆盖新旧两种载荷。
- 四张图可能乱序完成或部分失败。工具和投影须用调用 ID 加索引定位，不能依据到达顺序；取消后不把占位误判为成功。
- 历史数据只有图片数组，没有原始插槽信息。可以保证文字在前和旧图片相对顺序，无法推断缺失的原始插槽。
- 完整 Skill 包含备用 CLI 及参考资料，但其 Python 依赖不随本功能安装。主路径必须显式指向现有生图工具，避免误导 Agent。
- 生图事件仍不得携带图片字节或提示词正文；只传张数、索引及资产引用。

## Migration Plan

无需数据库表迁移。协议新字段可选，读取旧消息时执行助手内容顺序归一。升级时通过现有系统 Skill 播种逻辑增加 `imagegen`，保留已有 Skill 启停状态。打包验证检查所有复制文件与许可证。出现回退时仍能读取原图片资产；新元数据不会改变资产文件布局。

## Open Questions

无。用户已裁决画廊交互与完整复制适配方向。
