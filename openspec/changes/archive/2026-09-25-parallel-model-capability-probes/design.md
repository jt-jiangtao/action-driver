## Context

参见 proposal.md。当前设置页逐个调用 `testConnectionModels`；Runtime 的 `probeModelCapabilities` 又逐项等待 `probeCapability`，返回整模型结果后才更新。能力目录在 Runtime，Renderer 只拿到旧结果和音视频展示标签，因此新模型开始测试时无法准确画出每个待测能力的加载态。重测结果与旧能力对象合并，留下不适用的标签。

## Goals / Non-Goals

**Goals:** 模型与其能力项并行；每个适用能力项有明确加载态；完成后的可见终态只有成功/失败；清除旧的无关能力标签。已启用聊天候选无须先通过测试即可选择与发送；实际调用失败在对话中展示。

**Non-Goals:** 不测试音视频，也不展示音视频能力标签；不向聊天列表加入纯生图模型或已停用模型；不改变默认生图模型必须测试成功及生图测试真实生成图片的规则；不新增用户可调并发配置。

## Decisions

1. **双层并发、限定峰值。** Renderer 为一次刷新同时运行最多 4 个模型测试；Runtime 在每个模型内以 `Promise.all` 并行探测当前候选能力。每模型当前最多 4 项，因此峰值不超过约 16 个探测请求。添加连接时“测试全部”也由 Runtime 以最多 4 个模型的工作池运行。替代方案是最多 4 个模型并发、模型内逐项测试，峰值更低但模型内等待更久。Agent 推荐该替代方案，用户明确选择双层并发并接受更高请求峰值。
2. **Runtime 提供候选能力，Renderer 负责瞬时加载态。** 在 `ModelOptionDto` 中增加可选 `probeCandidates`，由 Runtime 对发现、刷新和读取结果补全，不进入持久化格式。Renderer 在模型运行时把这些候选项画为加载态；旧客户端或 Mock 缺失字段时退回已有能力键，若仍为空则画单个测试中提示。替代方案是在 Renderer 复制模型目录规则，容易与 Runtime 不一致；实时推送每项进度则需要新的流协议，当前无需该复杂度。
3. **结果原子替换与缓存合并。** 单模型探测结束后以本次候选能力结果替换该模型原有能力对象，避免旧候选残留。多个模型的请求分别落库时，Runtime 在写入前重新读取最新连接再合并各自模型结果。Renderer 将每个返回结果合并进查询缓存，让并发完成的行及时更新；批次结束后再从 Runtime 同步一次，避免并发重新获取列表时旧快照覆盖新结果。
4. **二态仅限设置页呈现。** `success` 显示“成功”；`failed`、`unsupported`、`inconclusive` 显示“失败”。未开始的模型仍显示“待测试”，运行中的适用能力项显示加载态。失败代码、具体信息与内部状态继续保存，但设置页不通过提示或行内文本展示测试原因；这些内部信息只用于诊断与默认生图资格。替代方案是把底层状态也压成布尔值，会丢失失败性质。测试时整请求抛错，也应把对应候选项标成失败，不留下旧的成功或待测试标签。
5. **音视频模型行保留，能力标签隐藏。** Runtime 目录继续识别语音和视频模型，从而明确不探测这些接口；Renderer 不显示对应的目录能力标签。仅有语音或视频目录能力且没有当前可探测能力的模型行保留名称、启用状态和操作入口，能力区域留空。替代方案是完全隐藏整行，但用户明确要求保留模型行。
6. **聊天选择改为尝试调用。** 下拉列表展示已启用、当前支持聊天调用协议、且并非纯生图或纯音视频目录模型的候选；未测试与测试失败的候选都可选，选择时不显示能力提示。Runtime 保留模型存在、启用和协议校验，移除文本及视觉测试成功的前置门槛，实际接口错误由任务失败状态进入现有对话错误区域。桌面端移除附图视觉测试拦截，用户消息先进入会话，再由提供方决定是否支持图片。替代方案是维持测试成功门槛，优点是减少必然失败请求，但与用户要求的发送后报错相冲突。已停用与纯生图模型仍不进入聊天候选；默认生图模型资格继续只认生图测试成功。

## Risks / Trade-offs

- [高并发触发服务商限流，图片测试可能收费] → 限制每批最多 4 个模型同时运行，保留真实错误供查看，失败不阻断其余模型；用户已选择双层并发并接受该代价。
- [并发请求完成顺序不固定] → 每个模型独立锁与结果合并；批次计数在每项结算后增加，最终同步服务端事实来源。
- [旧记录能力候选过时] → 每次列表读取补充最新候选；重测只保留当前候选的结果。若模型未重新测试，旧结果继续标记为待验证，但仍可尝试聊天调用。
- [请求级异常没有逐能力返回值] → 相关候选项显示失败并保留可重试入口，避免把旧结果当成本次成功；设置页不展示技术原因。
- [未测试或测试失败的模型可能再次产生请求费用与提供方错误] → 选择时不做能力提示；实际调用错误进入任务失败视图并与用户消息同轮显示。用户明确选择该行为。
- [语音视频模型保留行但无能力状态] → 行内仍显示模型名称与启用状态，不将“未接入测试”当作成功或失败。

## Migration Plan

`probeCandidates` 为可选 DTO 字段，不迁移数据库。旧版本前端忽略该字段；新版本对缺失字段有降级展示。回滚前后均可读取原持久化记录。
