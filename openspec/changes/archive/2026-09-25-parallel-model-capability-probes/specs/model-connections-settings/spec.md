## MODIFIED Requirements

### Requirement: 管理模型集
系统 SHALL 允许用户展开或收起模型集、打开更多菜单、通过一次刷新操作重新发现并测试可测试模型、启用或停用模型，并在确认后删除模型集。

#### Scenario: 刷新模型
- **WHEN** 用户点击已保存模型集的“刷新并测试”操作
- **THEN** 系统重新发现模型，随后并行测试该模型集内多个模型及其文本、推理、视觉或生图候选能力，并显示发现与测试进度；该操作不要求用户再逐个点击测试

#### Scenario: 启用或停用模型
- **WHEN** 用户切换模型的启用状态
- **THEN** 系统通过 Mock 接口保存新状态，并同步更新模型集的已启用数量

#### Scenario: 删除模型集
- **WHEN** 用户在更多菜单中选择删除并确认
- **THEN** 系统通过 Mock 接口移除模型集，并在最后一个模型集被删除后显示空状态

#### Scenario: 取消删除
- **WHEN** 用户在删除确认中取消
- **THEN** 模型集及其展开、启用和测试状态保持不变

### Requirement: 添加并验证模型集
系统 SHALL 提供连接配置和选择模型两步流程，并通过 Mock 接口支持发现模型、测试连接和测试单个模型；流程 SHALL 覆盖 Figma 节点 `273:126`、`273:162`、`273:198`、`273:234` 和 `273:270`。模型测试 SHALL 在同一模型行分别展示适用的文本、推理、视觉和生图能力结果，不要求用户先指定互斥类型。

#### Scenario: 配置连接
- **WHEN** 用户填写模型集名称、接口地址和 API Key 并测试连接
- **THEN** 系统展示连接测试进度与结果，成功后允许进入选择模型步骤

#### Scenario: 发现与手动添加入口
- **WHEN** 用户进入选择模型步骤
- **THEN** 系统展示发现的模型，并提供纯图标的手动添加入口，但 MUST NOT 展示固定的“手动添加模型”行

#### Scenario: 未测试状态
- **WHEN** 用户刚进入模型选择步骤
- **THEN** 页面按节点 `273:162` 显示模型选择和逐项未测试状态，不把目录提示显示为成功结果；语音和视频目录能力不显示标签

#### Scenario: 测试模型状态
- **WHEN** 用户测试发现的模型
- **THEN** 页面按适用能力项呈现加载态；完成后各项只显示“成功”或“失败”，不在设置页展示失败原因；一个能力失败不清除其他能力的成功结果

#### Scenario: 保存模型集
- **WHEN** 用户选中至少一个模型并保存，其中模型可能只有本轮不测试的音频或视频目录标签
- **THEN** 系统通过 Mock 接口添加模型集，并返回模型集列表页展示新数据；已启用的聊天候选即使未完成文本测试仍可在聊天选择器尝试调用，默认生图候选仍须通过生图测试

#### Scenario: 步骤间保留数据
- **WHEN** 用户在连接配置和模型选择步骤之间前进或返回
- **THEN** 已填写连接字段、选择的模型和已有逐项测试结果均保持不变

### Requirement: 已保存模型的测试反馈
系统 MUST 在已保存模型集的单项测试和刷新批量测试中按适用能力项即时显示加载态，并在完成后仅以“成功”或“失败”展示每项结果。测试失败或请求异常时 MUST 保留内部诊断信息，但设置页 MUST NOT 展示错误原因，也不能继续呈现为未测试或静默结束。批量测试中一个模型失败 SHALL 不阻止其他模型继续测试；语音和视频目录模型 SHALL 保留模型行但不显示能力标签，也不得发起真实探测。

#### Scenario: 单项测试进行中
- **WHEN** 用户点击已保存模型的一行测试按钮
- **THEN** 该行的每个适用能力项立即显示加载态并避免重复发起，完成后刷新逐项二态结果；若请求异常，该行显示失败而不展示原因，仍可重试

#### Scenario: 批量测试部分失败
- **WHEN** 刷新后一个模型的能力测试失败或请求异常，而其他模型仍可测试
- **THEN** 页面显示已完成数量及对应行的成功或失败状态，不展示错误原因，并继续处理其余模型，最终结果不将失败模型伪装为已通过

#### Scenario: 音视频只展示
- **WHEN** 刷新发现的模型只有音频或视频目录能力
- **THEN** 该行保留模型名称与启用状态，能力区域不显示语音、视频或“未接入测试”标签，批量测试不对它发起音频或视频请求

#### Scenario: 重复点击刷新
- **WHEN** 同一模型集刷新及测试尚未完成，用户再次点击刷新操作
- **THEN** 系统不启动第二批重复请求，已有进度与结果继续可见

#### Scenario: 批量与单项测试互斥
- **WHEN** 模型集正在刷新测试或其任一模型正在单项测试
- **THEN** 页面禁用会与当前测试重叠的入口，不同时发起该模型的重复探测

#### Scenario: 并行测试模型和能力
- **WHEN** 用户刷新模型集或在添加模型集时测试全部模型
- **THEN** 系统并行探测多个模型，且并行探测同一模型的适用能力；单个模型失败不阻止其他模型和能力完成

#### Scenario: 清理不再适用的旧结果
- **WHEN** 本次测试得到的能力候选与旧测试记录不同
- **THEN** 该模型只展示本次适用能力的结果，不继续展示旧候选能力的“需重新测试”或旧成功状态

#### Scenario: 测试终态只展示成功或失败
- **WHEN** 能力探测完成并在内部判定为成功、失败、不支持或无法判定
- **THEN** 设置页仅显示“成功”或“失败”，不支持与无法判定均显示失败，且不展示错误原因；内部判定保持原值，用于默认生图资格与诊断

### Requirement: 配置图片相关模型能力
系统 SHALL 根据用户主动发起的真实测试，分别记录模型的文本、推理、视觉和生图结果。模型目录 MAY 指导应运行哪些测试，但目录声明或旧手工类型 MUST NOT 被显示为测试成功。设置页 SHALL 不显示聊天/生图类型选择、识图或生图开关、生图接口选择；用户只选择全局唯一默认生图模型。已启用的聊天候选 SHALL 无论文本测试是否运行或成功都出现在聊天选择器，选择时不显示测试提示；纯生图和纯语音视频目录模型不进入聊天选择器。生图测试成功的已启用模型 SHALL 可设为默认生图模型；两项可同时成立。系统 MUST 允许仅生图测试成功的连接被保存。未配置已验证的默认生图模型时，生图工具不可用。

#### Scenario: 多能力模型
- **WHEN** 同一模型的文本和生图测试均成功
- **THEN** 该模型同时可用于聊天和默认生图候选，设置页逐项显示两项成功，不要求用户选择单一类型

#### Scenario: 未测试聊天模型仍可选择
- **WHEN** 已启用的聊天候选尚未测试，或文本测试失败、无法判定
- **THEN** 聊天下拉列表仍允许选择该模型且不显示测试状态提示；发送后若提供方拒绝，错误出现在该轮对话中

#### Scenario: 非聊天模型不进入下拉列表
- **WHEN** 模型已停用，或目录只含生图、语音、视频能力，或连接协议尚不支持聊天调用
- **THEN** 它不作为可选聊天模型出现，但保留在模型设置列表中

#### Scenario: 选择视觉聊天模型
- **WHEN** 模型的文本测试成功但视觉测试失败、不支持或无法判定
- **THEN** 它仍可尝试纯文字或附图聊天，设置页分别显示两项测试结果；实际模型调用失败在对话中展示

#### Scenario: 推理结果缺乏证据
- **WHEN** 推理测试收到普通最终文本但没有可验证的推理证据
- **THEN** 内部记录“无法判定”，设置页只显示“失败”而不展示原因，不得显示推理测试成功或抹除该模型已成功的文本测试

#### Scenario: 配置默认生图模型
- **WHEN** 用户在已保存、已启用且生图测试成功的模型行将其设为默认生图模型
- **THEN** 系统保存该选择，之后的生图工具调用使用经测试的接口，当前聊天模型选择不改变

#### Scenario: 为模型选择生图接口
- **WHEN** 用户测试或使用生图模型
- **THEN** Runtime 对官方 Token Plan 网关使用 Token Plan 生图接口，对其他受支持的 OpenAI 兼容连接使用 Images API；用户无需手工选择接口

#### Scenario: 迁移已有生图配置
- **WHEN** 应用读取升级前有单一测试成功、手工生图类型或默认生图引用的记录
- **THEN** 原连接、启用状态、模型 ID 和默认引用得以保留，但旧结果仅显示“待测试”，不得自动当作文本、视觉或生图已验证成功；已启用聊天候选仍可尝试调用

#### Scenario: 默认生图模型被关闭或删除
- **WHEN** 默认生图模型被停用、删除或生图重测不再成功
- **THEN** 系统清除可用默认选择或标记为待验证，Agent 不把生图工具暴露为可用能力

#### Scenario: 音频视频能力只展示
- **WHEN** 模型目录包含语音识别、实时语音、语音合成或视频生成模型
- **THEN** 设置页保留模型行但不显示语音、视频能力或“未接入测试”标签，不发起音频或视频请求，不把该模型加入聊天或默认生图候选

#### Scenario: 提供方不支持生图请求
- **WHEN** 用户主动测试生图能力而提供方拒绝、超时或返回无效图片
- **THEN** 设置页只显示该能力“失败”且不展示具体原因，其他能力的成功结果不变，不把测试图加入会话

#### Scenario: 添加仅支持生图的连接
- **WHEN** 用户手动添加仅支持 Images API 的模型并主动测试生图
- **THEN** 生图测试实际验证一张图片；测试成功后可保存连接并设为默认，不要求聊天补全成功

#### Scenario: 逐模型区分类型与测试接口
- **WHEN** 同一连接同时包含文本模型和生图模型，用户分别点击测试
- **THEN** Runtime 按每个模型的候选能力选择相应接口并逐项显示结果，页面不要求用户为模型选择类型

#### Scenario: 修改已保存模型类型
- **WHEN** 用户在已保存模型列表中查看或重测一个模型
- **THEN** 页面不提供聊天或生图类型修改控件；该模型的可用用途随逐项测试结果更新
