## Context

见 proposal.md。Runtime 启动时先注册 `createSandboxTools` 返回的 `sandbox.fs.list/read`，再注册 Shell/Python/Node 工具。历史工具行通过工具 ID 格式化，与执行器注册分离。

## Goals / Non-Goals

**Goals:** 新调用面只保留通用执行工具等现役工具；删除专用文件执行和展示代码。

**Non-Goals:** 不改变 Shell 的授权、超时、输出上限或工作区默认目录；不主动清空数据库历史记录，也不维持旧文件工具的专用展示。

## Decisions

- **最终方案：全部删除专用路径。** Runtime 只注册脚本工具与其他现役工具，并删除文件工具、私有路径守卫和活动标题中的 `sandbox.fs.*` 分支。替代方案是仅不注册、保留旧实现及历史展示；维护面更大，用户明确否决。
- **不做旧文件工具兼容。** 不迁移或主动删除数据库记录；若旧记录仍被普通读取流程取出，只能使用通用未知工具回退展示。用户明确覆盖 Agent 原先保留专用历史展示的建议。
- **测试按现役行为更新。** 模型调用与桌面 E2E 通过 `shell_run` 测试文件读取；删除只验证废弃 `sandbox.fs.*` 行为的测试，通用协议测试使用现役工具 ID。

## Risks / Trade-offs

- [新模型失去结构化目录与按范围读取] → `shell_run` 可运行 `ls`、`rg`、`cat` 等命令；结果受既有超时和输出上限约束。用户已接受此代价。
- [旧任务记录失去文件工具专用展示] → 用户明确接受；保留通用未知工具回退，不专门迁移旧记录。
- [旧测试仍期望专用文件工具] → 改用现役工具样本，删除仅验证废弃能力的测试。
