## Context

见 proposal.md。当前 Agent Graph 在 8 轮或 16 次调用后返回 `TOOL_BUDGET_EXCEEDED`，LangGraph 仍使用默认递归上限。OpenAI 兼容适配器逐块接收工具名与参数，却只在模型响应结束后把完整调用交给 Graph。StreamSession 与桌面投影已经有按请求序号持久化、回放和快照的机制。

## Goals / Non-Goals

**Goals:** 让单任务容纳至少 400 次工具调用；在模型准备工具参数期间提供可读且有序的实时反馈；四类工具各完成至少 100 次实际执行验证。

**Non-Goals:** 不向用户展示原始思维链或半成品参数，不并行执行模型同批工具，不承诺第三方模型一定能在其上下文限制内完成 400 次循环，不更改每个工具的授权、超时与输出上限。

## Decisions

- **预算与递归上限一起调整。** 将单任务最大调用数、最大轮次均设为 512，同时设置足以走完 512 次 `plan → executeTools` 的 LangGraph 递归上限；到达预算仍产生明确错误。替代方案是保留 16/8 并由独立批次测试，成本和上下文更可控，Agent 原本推荐此方案；用户裁决选择单任务支持 400 次以上调用。
- **准备状态单独传输。** 适配器在工具名称完整且可识别时只发送工具索引与名称，不发送参数文本；Gateway/Graph 转发，StreamSession 持久化为独立进度事件，Renderer 在“正在思考”位置显示“正在准备 <工具名>”。参数完整后仍由现有工具验证与生命周期创建正式行。替代方案是流式展示原始 JSON 参数，调试信息更丰富但容易闪烁、误导和泄露未完成输入；用户选择可读准备状态。
- **准备事件遵守请求序号。** 进度事件走现有事件存储、cursor 和 WebSocket 广播；模型输出正文、正式工具事件、失败或取消时清除临时状态，完成快照不保留它。重连期间运行中任务可从最近准备事件恢复尾部状态，且事件重放绝不触发执行。
- **刷新后重新订阅运行中的请求。** HTTP 任务快照只在运行中携带请求和响应标识。桌面端恢复任务时以快照的 cursor/sequence 建立投影，并发送 `request.resume`，接收随后实时事件；已完成任务只展示归档。恢复过程幂等，避免重复行与重复工具执行。
- **压力验证分层。** 真实 Shell/Python/Node 解释器各跑至少 100 个短调用，Web Search 对本地可控的 SearXNG 兼容服务跑至少 100 次 HTTP 调用；另用假模型与桌面端到端测试验证分片准备、400 次混合调用、取消、终态和重连。测试服务只模拟搜索返回，不替代生产搜索实现。若本机 SearXNG 可用，再补少量真实搜索冒烟。

## Risks / Trade-offs

- [用户覆盖 Agent 的分批建议，单任务可能增长到大量模型请求、工具消息与检查点] → 保留 512 上限、取消和明确错误；不声称提供方上下文容量足以保证每个请求成功。
- [准备进度可能比正式工具调用先到达，随后模型失败] → 进度只作临时状态；失败、取消与正文到达时清除，未完整调用不执行。
- [大量工具输出和 UI 行造成内存或渲染压力] → 压力测试使用小输出并检查任务终态与事件顺序；现有单工具输出上限保持不变。
- [外部搜索服务对 100 次查询限流] → 确定性压力验证使用本地服务；真实服务只作可选冒烟，不把外部可用性当作 Runtime 正确性。
