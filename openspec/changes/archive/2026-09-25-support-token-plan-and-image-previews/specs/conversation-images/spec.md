## MODIFIED Requirements

### Requirement: 接收并展示会话图片
系统 SHALL 允许用户选择或粘贴受支持的图片，发送前预览和移除；发送后 SHALL 在用户消息中展示图片。预览与消息缩略图 SHALL 保持完整图片比例和清晰边界，允许放大查看，不得把宽幅图片裁成难以识别的局部。图片消息 SHALL 允许没有文字。

#### Scenario: 发送单张图片
- **WHEN** 用户选择有效图片并发送，不输入文字
- **THEN** 任务接受该消息，用户消息显示完整比例的图片，视觉模型收到图片输入

#### Scenario: 图文混合消息
- **WHEN** 用户同时输入问题并附加图片
- **THEN** 模型按同一消息收到文字和图片，界面按提交顺序展示可读文字和完整比例图片

#### Scenario: 宽幅白底文字图片
- **WHEN** 用户添加宽幅白底文字图片，随后发送并重开会话
- **THEN** 输入预览、用户消息及历史会话都能辨认图片完整构图，点击缩略图可放大原图

#### Scenario: 无效或过大的图片
- **WHEN** 用户选择不支持、损坏或超出限制的文件
- **THEN** 系统在发送前显示明确错误，不创建可发送的图片引用

### Requirement: 生图进度与结果进入对话
系统 SHALL 在 Agent 调用生图工具时展示运行状态。单次调用 MUST 支持最多 4 条独立图片需求并行生成，每条需求可使用不同提示词；已配置 `Images API` 或 `Token Plan` 接口的默认生图模型 SHALL 通过对应接口生成图片。每张成功图片 SHALL 在完成后作为该轮助手消息的图片内容出现。失败、取消与超时 SHALL 显示明确状态，不得出现空白成功图片。

#### Scenario: 文字生图完成
- **WHEN** Agent 使用已配置的生图模型生成图片
- **THEN** 任务过程显示生图工具的状态，最终助手消息显示可放大和保存的图片

#### Scenario: Token Plan 模型生图
- **WHEN** 默认生图模型选择了 `Token Plan` 接口且提供方返回图片
- **THEN** 系统使用 Token Plan 同步生图接口获取图片，将其保存为本会话资产并在对话中展示，历史消息不依赖提供方临时图片地址

#### Scenario: 并行生成多张图片
- **WHEN** Agent 在一次生图调用中提交 2 至 4 条图片需求
- **THEN** Runtime 同时执行这些需求，每张图片完成后按完成顺序进入对话，最终显示所有成功图片

#### Scenario: 一张失败但其他图片成功
- **WHEN** 并行生成中部分请求失败
- **THEN** 已成功图片继续展示，工具显示部分失败与失败数量，不把整批结果伪装为全部成功

#### Scenario: 取消并行生图
- **WHEN** 用户在多张图片生成期间取消任务
- **THEN** Runtime 中止仍在运行的请求，已经完成并持久化的图片保留，未完成的图片不显示为成功

#### Scenario: 生图失败
- **WHEN** 提供方返回错误或生成超时
- **THEN** 工具显示失败原因，助手消息不包含无效图片，模型可继续给出文字反馈

## ADDED Requirements

### Requirement: 未配置生图模型时准确说明能力状态
系统 MUST 在没有可用默认生图模型的对话中向 Agent 提供准确的生图配置状态；Agent 不得被告知应用完全没有生图能力。设置状态变化 SHALL 在后续模型请求中生效。

#### Scenario: 用户请求生图但未配置默认模型
- **WHEN** 用户请求生成图片且当前没有可用默认生图模型
- **THEN** 生图工具不在可用工具列表中，Agent 收到需要在“设置 → 模型连接”启用生图并选择默认模型的明确说明

#### Scenario: 配置完成后再次请求生图
- **WHEN** 用户启用生图模型并设为默认，然后发送新的生图请求
- **THEN** Agent 收到可用生图工具，不再收到未配置说明
