## Context

参见 `proposal.md`。当前 `ImageGallery.tsx` 在每个未完成插槽渲染一个 `.image-gallery-dots`，`agent.css` 将其设为卡片的 72% 并用数个固定方向的关键帧移动整层及改变整层透明度。画廊已有稳定插槽、原位替换、失败与取消状态，以及减少动态效果样式；本设计只更换等待态的视觉实现。规范见 `specs/conversation-images/spec.md`。

## Goals / Non-Goals

**Goals:**

- 在不同卡片尺寸下让约 80–96 px 的点云平滑漫游，活动区域跨越卡片的大部分面积，但点云始终留在圆角边界内。
- 1–16 张的等待卡保持各自稳定位置，点云相位错开，完成、失败或取消时立即停止对应动画。
- 不增加持续触发 React 渲染的计时器，不引入生图接口或存储变更。

**Non-Goals:**

- 不模拟生成百分比，不展示提供方未返回的中间图片。
- 不更改画廊排序、批次锚点、图片请求并发上限或图片点击操作。

## Decisions

### 1. 小点云使用平滑二维轨迹

**当前方案：** 提取等待点云为轻量组件，以卡片实际尺寸计算归一化的闭合曲线采样点，并通过 Web Animations API 只动画化点云元素的 `transform`。曲线在卡片内覆盖上、下、左、右不同区域，转向处保持连续；每次尺寸变化重新计算轨迹，点云半径与圆角留出安全距离。移动周期约 10–12 秒，循环衔接无跳变。点云是一个小型径向点阵，不铺满卡片。

**替代方案：** 保留 CSS 中几个 `translate` 关键帧，开发成本低，但相邻点之间仍呈固定方向分段运动，缩放时百分比相对点云自身尺寸，难以控制全卡活动范围。整卡扫光能更快实现，但与用户已选择的视觉目标不符。基于真实生成预览逐步显现需要提供方持续提供中间帧，现有接口没有该能力。

**裁决：** 用户选择小点云漫游；采用按实际尺寸计算的连续轨迹，避免再用大块点阵与固定横纵扫动。

### 2. 点云内部闪动与多卡片错峰

点阵纹理用单个 DOM 元素和 CSS 渐变形成；局部遮罩或纹理明暗缓慢变化，使亮度变化只发生在小点云内，卡片底色保持稳定。以 `callId` 与插槽索引导出稳定相位，给不同卡片错开的起点与轻微不同的周期，避免 16 张卡片同步闪烁。运动只改变合成层属性，不为每个点创建节点，也不按帧调用 React 状态更新。

**替代方案：** 为每个点创建独立元素并随机移动，可获得更强随机感，但 16 张卡片下元素与动画数量明显增加，且更难保持统一的视觉尺度；本次不采用。

### 3. 生命周期、可访问性与结果替换

组件只在插槽等待时挂载；成功图片、失败或取消状态替换它时清理动画与尺寸观察。保留现有 `role="status"` 与可读状态文案。检测 `prefers-reduced-motion: reduce` 时不启动连续运动与内部闪动，显示居中的静态小点云；运行中切换系统偏好也应立即停启相应动画。成功图片沿用现有短淡入，减少动态效果时禁用淡入。

**替代方案：** 仅用 CSS 媒体查询隐藏运动，虽然视觉上静止，但 JavaScript 动画可能继续运行；明确在生命周期中暂停或取消更节省资源。

## Risks / Trade-offs

- [同时显示 16 张等待卡会增加合成层工作量] → 每卡仅一个点云元素，不创建逐点动画；只动画化合成友好的属性；验证多卡片时的滚动与交互响应。
- [窗口尺寸变化可能让旧轨迹越过圆角] → 观察卡片尺寸，按内边距和点云尺寸重新计算，并测试宽窄布局。
- [不同机器的动画节奏可能显得过快或过亮] → 用较慢周期、低对比点阵与小幅局部闪动；按实际桌面截图审查亮度和覆盖范围。
- [用户选择不显示真实生成进度] → 等待动画仅表示仍在生成，不表达百分比或完成时间；这是现有接口只在完成后返回图片的已知限制。

## Migration Plan

无数据迁移。替换等待态组件与样式后，新旧会话中的未完成插槽使用同一呈现；已完成图片和持久化记录保持原样。若需回退，只需恢复原等待态样式与组件，不改存储数据。
