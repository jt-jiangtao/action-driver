## MODIFIED Requirements

### Requirement: 生图进度与结果进入对话
系统 SHALL 在 Agent 调用生图工具时展示运行状态。单次调用 MUST 支持 1 至 16 条独立图片需求，每条需求可使用不同提示词；同一次调用最多同时执行 4 条，其余排队。已配置 `Images API` 或 `Token Plan` 接口的默认生图模型 SHALL 通过对应接口生成图片。每张成功图片 SHALL 在完成后作为该轮助手消息的图片内容出现。失败、取消与超时 SHALL 显示明确状态，不得出现空白成功图片。每次生图调用的画廊 MUST 固定在该调用发生的位置；不同批次 MUST 按调用顺序展示，每批图片 MUST 按输入索引展示，最终回复文字 MUST 按其生成位置展示。过程文字继续归档于任务过程。

#### Scenario: 文字生图完成
- **WHEN** Agent 使用已配置的生图模型生成图片
- **THEN** 任务过程显示生图工具的状态，最终助手消息显示可放大和保存的图片

#### Scenario: Token Plan 模型生图
- **WHEN** 默认生图模型选择了 `Token Plan` 接口且提供方返回图片
- **THEN** 系统使用 Token Plan 同步生图接口获取图片，将其保存为本会话资产并在对话中展示，历史消息不依赖提供方临时图片地址

#### Scenario: 并行生成多张图片
- **WHEN** Agent 在一次生图调用中提交 2 至 16 条图片需求
- **THEN** Runtime 在同一次调用中保持最多 4 条需求同时执行，已完成一条才启动下一条；对话在开始时显示同数量的稳定占位卡，每张图片完成后按输入插槽原位替换，最终显示所有成功图片

#### Scenario: 超过单次上限
- **WHEN** 生图工具收到第 17 条图片需求
- **THEN** 工具在发起任何生图网络请求前拒绝该调用，并向 Agent 返回输入无效状态

#### Scenario: 一张失败但其他图片成功
- **WHEN** 并行生成中部分请求失败
- **THEN** 已成功图片继续展示，失败插槽显示失败状态，工具显示部分失败与失败数量，不把整批结果伪装为全部成功

#### Scenario: 取消并行生图
- **WHEN** 用户在多张图片生成期间取消任务
- **THEN** Runtime 中止仍在运行的请求、不启动排队中的请求，已经完成并持久化的图片保留，未完成的插槽显示取消状态，不显示为成功

#### Scenario: 生图失败
- **WHEN** 提供方返回错误或生成超时
- **THEN** 工具显示失败原因，助手消息不包含无效图片，模型可继续给出文字反馈

#### Scenario: 生图占位动画
- **WHEN** 生图工具开始执行 1 至 16 条图片需求
- **THEN** 对话在该调用的位置显示同数量的圆角浅灰占位卡；每张进行中的卡片仅有一块尺寸明显小于卡片的点云，在卡片范围内沿平滑且不局限于单一横向或纵向的轨迹移动，并只在点云内部轻微闪动；卡片数量与位置在完成前保持稳定

#### Scenario: 减少动态效果
- **WHEN** 系统启用减少动态效果且生图正在运行或图片刚完成
- **THEN** 占位卡显示静态小点云，图片无淡入，进度及结果仍可辨认

#### Scenario: 多卡片点云错峰
- **WHEN** 同一批有多张图片同时等待生成
- **THEN** 各卡片点云的起始位置或运动相位不同，均在各自卡片内活动，不表现为同步闪烁；生成完成先后不改变插槽顺序

#### Scenario: 结果终止等待动效
- **WHEN** 单个插槽生成成功、失败或被取消
- **THEN** 仅该插槽停止点云运动并在原位显示相应图片或状态，其他进行中的插槽继续运动

#### Scenario: 不同尺寸下的点云活动范围
- **WHEN** 画廊因窗口宽度变化而由双列变成单列，或等待卡尺寸发生变化
- **THEN** 点云仍保持为卡片中的小区域，轨迹留在卡片边界内，状态文字与生成结果不被遮挡

#### Scenario: 完成前后文字与图片顺序一致
- **WHEN** 助手先调用生图工具、随后生成最终回复文字，且部分或全部图片已完成
- **THEN** 该调用的画廊始终在最终文字上方；响应结束、重连及历史打开后顺序不变化，用户上传图片气泡的顺序不受影响

#### Scenario: 多批次按调用顺序
- **WHEN** 同一轮先后发起多个生图调用，批次内的图片完成顺序与请求顺序不同
- **THEN** 每批画廊固定在各自调用位置，批次按调用顺序排列，每批图片按原始输入索引占据稳定插槽，任何结果完成都不改变其他批次和最终文字的位置

#### Scenario: 过程文字与最终回复
- **WHEN** Agent 在多个生图调用之间输出过程文字，并在最后一批之后给出最终回复
- **THEN** 过程文字保留在可展开的任务归档中，最终回复位于最后一批画廊之后，不把过程文字合并到最终回复顶部
