## Purpose

定义桌面应用 Main 进程对模型连接的持有与验证行为，使用户配置的端点与凭据被安全保存、真实校验，并且只在页面暴露掩码信息。

## ADDED Requirements

### Requirement: 在 Main 进程持有模型连接与凭据
系统 SHALL 由 Electron Main 进程独占模型连接配置与 API Key，把连接配置持久化到应用数据目录，并使用操作系统保护的加密能力保存密钥；Renderer、Runtime 与日志 MUST NOT 获得明文密钥。

#### Scenario: 保存新连接
- **WHEN** 用户提交包含名称、协议、接口地址和 API Key 的模型集
- **THEN** 系统在应用数据目录保存该连接，且磁盘上的密钥以密文形式存放

#### Scenario: 重启后读取连接
- **WHEN** 应用重新启动并打开模型连接设置页
- **THEN** 系统返回已保存的连接、协议、地址、模型与启用状态，并只在需要发起请求时在 Main 进程内解密密钥

#### Scenario: 页面读取连接
- **WHEN** Renderer 请求连接列表或连接详情
- **THEN** 系统只返回掩码后的凭据标识（例如末尾若干字符），不返回明文密钥

#### Scenario: 系统加密不可用
- **WHEN** 运行环境不提供操作系统加密能力
- **THEN** 系统拒绝保存明文密钥并返回可诊断错误，不静默降级为明文存储

### Requirement: 通过协议适配验证连接与模型
系统 SHALL 按连接协议执行真实网络调用：`OpenAI 兼容` 通过模型列表接口发现模型并以最小对话调用验证单个模型，`Anthropic 兼容` 通过消息接口验证单个模型；每个调用 MUST 具备超时与失败返回。

#### Scenario: 发现可用模型
- **WHEN** 用户对 OpenAI 兼容连接请求发现模型
- **THEN** 系统返回该端点提供的模型标识列表，保留用户已启用的模型选择

#### Scenario: 协议没有发现接口
- **WHEN** 用户对 Anthropic 兼容连接请求发现模型
- **THEN** 系统返回空列表并保留手动添加模型的入口，而不是判定连接失败

#### Scenario: 连接验证成功
- **WHEN** 用户以有效凭据测试连接
- **THEN** 系统在超时时间内返回成功，并允许进入选择模型步骤

#### Scenario: 连接验证失败
- **WHEN** 用户以无效凭据、错误地址或不可达端点测试连接
- **THEN** 系统在超时时间内返回失败，并区分认证失败、地址或路径错误、限流、服务错误与网络或超时

#### Scenario: 单个模型验证
- **WHEN** 用户测试连接中的一个模型
- **THEN** 系统以最小调用验证该模型并返回成功、失败或不支持文本的结果

#### Scenario: 模型不接受文本请求
- **WHEN** 模型对文本探测返回参数或能力错误
- **THEN** 系统把该模型标记为不支持文本，而不是把连接或整体配置标记为失败

### Requirement: 使用可替换的传输端口执行远程调用
系统 SHALL 通过可注入的传输端口执行所有远程调用，使单元测试与端到端测试无需真实网络与真实凭据即可覆盖成功、失败与超时路径。

#### Scenario: 测试环境替换传输
- **WHEN** 测试组合根注入确定性传输端口
- **THEN** 连接验证、模型发现与模型测试使用该端口，不发起真实网络请求

#### Scenario: 仓库不留存真实凭据
- **WHEN** 开发者运行单元测试或端到端测试
- **THEN** 测试代码、固件与断言中不出现真实 API Key，也不写入真实密钥到版本库
