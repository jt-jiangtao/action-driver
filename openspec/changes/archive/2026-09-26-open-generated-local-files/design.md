## Context

见 proposal.md。当前 `StreamSessionService` 每轮创建新 taskId、复用 sessionId；图片先暂存，再绑定到应用私有 `SessionAssetStore`。四种脚本工具由 `createScriptTools` 注册，经 `ToolInvocationService` 调用，当前执行器只得到工具调用和取消信号，所有脚本以同一个 workspaceRoot 启动并继承 Runtime 环境。`skill_install` 可由有权限的 Runtime 按模型给出的本地路径读取文件。桌面页面目前只有图片片段，无通用文件产物投影；主进程无按产物标识打开文件的桥接。

## Goals / Non-Goals

**Goals:**

- 输入文件、脚本工作目录、成品扫描和历史产物建立一致的 sessionId／taskId 所有权模型；跨会话拒绝按路径、标识或代读工具访问。
- 在打包 macOS 应用中验证文件、环境、进程及本地 Runtime 通道的隔离，并在沙箱不可用时拒绝脚本执行。
- 现有图片消息、视觉模型输入、生图画廊、流式恢复和历史记录继续工作。

**Non-Goals:**

- 将用户已存在的共享工作区文件自动归属于某个会话；迁移必须由用户在对应会话重新附加。
- 把任意临时文件或不在 `output/` 的文件当作交付物；首版只显示规定的成品类型。
- 将 macOS 沙箱视为不同本机登录用户之间的安全边界，或保证对操作系统内核漏洞的防护。

## Decisions

### 1. 会话工作目录与资产所有权

采用 `workspace/sessions/<sessionId>/` 作为脚本当前目录，内部固定 `input/` 和 `output/`。会话内任务串行，后续任务沿用同一目录，因此先前输入可直接读取；其他会话拥有不同目录。上传时先检查内容类型、大小、文件名和内容，再由 Runtime 写入只读的 `input/`；同名文件产生不冲突的稳定名称。现有图片资产表仍是视觉消息的事实来源；同一上传图片额外物化到本会话 `input/`，元数据指向同一会话和上传任务。文档附件使用同一文件登记模型，不把字节写入事件或消息 JSON。

应用私有附件原件、SQLite 和历史成品副本位于脚本可读范围之外；任务和会话关系由 Runtime 从持久化记录取得，不能信任模型传来的 ID。任务终止或重连不删除会话输入；仅应用明确的会话删除／清理流程才可处理它们。

替代方案：继续使用共享工作区并按路径过滤。这无法阻止脚本、子进程或代读工具直接读取其他目录，故不采纳。另一种将所有输入只留在私有资源库的方案可简化隔离，但不满足用户要在工作目录直接读取的要求。

### 2. 每次脚本调用建立会话沙箱

在工具调用链中携带由任务记录查得的可信 sessionId，而不是从 `callId` 或脚本参数解析；四种脚本执行器用它选择当前目录与沙箱配置。进程启动入口统一建立 macOS `sandbox-exec` 配置，拒绝访问其他会话目录、应用私有数据、服务凭据和本地 Runtime 通道，只允许本会话目录及运行解释器、Office 依赖所需的系统／应用文件。上传 `input/` 只允许读取，`output/` 允许写入；符号链接、硬链接、路径穿越、文件描述符和子进程继承均列入边界测试。工具不继承整个 `process.env`，只传构造出的最小环境；尤其去除服务令牌、凭据密钥和连接配置。沙箱建立失败直接返回专门错误，绝不重试裸进程。

本地服务的读文件接口按任务与会话校验；脚本无服务令牌，沙箱还阻断直接连接本地 Runtime。所有模型可调用的代读入口统一审计：`skill_install` 的本地路径不得从其他会话目录或应用私有区读取，也不得把本会话私有输入无授权安装进全局共享 Skill；需要安装共享 Skill 时沿用用户主动选择的桌面流程。`web_open` 已限制为公网 HTTP(S)，继续禁止本地地址。

替代方案：每会话容器或虚拟机隔离更独立，但会引入运行环境部署、体积、启动和 Office 依赖复制成本；用户裁决采用 macOS 每会话沙箱。Apple App Sandbox 是应用级权限，不单独解决本应用多会话隔离；采用每脚本调用的本机沙箱同时保留 Runtime 作为受信任代理。该机制已被 macOS 标为弃用，必须在打包应用中设置功能验证门槛，并把未来替换封装在执行适配层。

### 3. 输入传输、展示与同会话复用

扩展 Composer 的附件队列与上传协议，以稳定的 fileId 绑定发送任务及会话。文档、图片的 UI 元数据投影只携带 ID、类型、名称、大小和受控预览引用；文档显示文件卡片，图片沿用当前缩略图及放大交互。模型视觉输入继续走已有图片资产路径；对于文档，Agent 通过当前会话 `input/` 路径和随包脚本工具读取内容，避免把文档二进制注入模型消息。发送前拒绝不支持、损坏或超限文件；同会话后续任务从持久化输入清单获得文件名和路径。历史记录按上传任务显示，不将旧输入重新归为后续任务的附件。

替代方案：只在页面展示输入而不物化到工作目录，改动较小但无法满足用户的脚本读取需求，故不采用。

### 4. `output/` 成品登记与历史快照

每个任务开始时建立本会话 `output/` 的安全基线，任务成功结束后仅比较该任务新建或更新的符合格式普通文件；禁止跟随符号链接，不接收越界路径或其他会话内容。每个文件通过受控复制保存到应用私有产物库，记录 fileId、sessionId、taskId、原相对路径、格式、大小、校验摘要和创建时间，并与任务完成状态一致提交。产物库内容只读，主进程打开时物化可丢弃的临时打开副本，避免外部应用修改历史原件。同一会话后续任务可在 `output/` 读写工作副本，但历史快照互不影响。

替代方案：直接把卡片指向 `output/` 原路径，不需要额外存储，却会在后续任务覆盖同名文件时改变历史结果；用户明确选择每任务副本，故不采用。扫描整个工作区易混入中间文件，亦不采用。

### 5. 展示、打开与恢复

在任务投影和流式快照中加入按任务归属的输入与输出文件元数据；文件字节只经受控资源通道传送。结果卡片紧随对应任务的最终回复，提供类型、名称、大小、图片缩略图及“打开文件”。Renderer 仅传 fileId 与当前 taskId，Desktop 主进程通过可信 Runtime 查询并核验 sessionId／taskId、文件真实位置、类型和登记摘要，然后调用系统默认应用打开临时副本。文件缺失、篡改、权限不足或打开失败的错误停留在对应卡片，不影响其他消息。键盘和测试标识沿用现有组件约定。

替代方案：页面直接传绝对路径给 `shell.openPath`，实现更短但允许页面打开任意本地文件，不能满足登记与会话边界，故不采用。

## Risks / Trade-offs

- `sandbox-exec` 已弃用，后续 macOS 版本可能改变行为 → 沙箱适配层独立封装；开发与打包环境都跑正反向隔离测试；无法建立时拒绝执行并呈现错误。用户已明确接受该维护风险。
- 现有脚本依赖任意本机路径或本地服务可能失效 → 明确暴露会话工作目录及受支持依赖路径，迁移系统 Skill 的输出约定；对需要额外输入的任务引导用户在当前会话附加。用户已接受文件读取范围收紧。
- 受信任 Runtime 工具或资源接口可能成为绕过入口 → 在每个代读入口传入可信会话上下文，负向测试跨会话标识、路径、全局 Skill 安装及本地服务调用。
- `output/` 扫描遇到大文件、并发写入或伪装扩展名 → 限制大小和类型，安全打开与复制，只有完整稳定文件才登记；超限文件给出可见诊断而非静默混入。
- 每任务成品快照增加磁盘占用 → 在 UI 展示真实大小；未来清理或配额作为单独决策，首版不自动删除历史产物。

## Migration Plan

1. 先引入会话工作目录和可信执行上下文、沙箱验证；在任何新输入写入前保证跨会话拒绝读取。
2. 扩展附件与元数据持久化，保留旧图片资产读取路径；旧会话的上传图片继续按原记录展示，不默默复制到新工作目录。
3. 加入 `output/` 基线、快照、投影与打开桥接；迁移系统 Skill 的成品输出说明。已有共享工作区文件不自动登记，旧任务仍可查看原消息。
4. 对开发版与打包版验证沙箱、Office 脚本、输入上传、同会话复用、跨会话拒绝、输出覆盖、重连与打开；若沙箱检查失败，回滚新执行路径的发布，不降级为无沙箱脚本。
