## Context

见 [proposal.md](proposal.md)。本机 Electron Fork 源码仍处于已实现水印的提交 `593df43c`，并保留 `thirdparty/build/electron/Electron.app`。当前主分支缺少原先的启动解析器与来源记录，而运行进程实际来自 `node_modules/electron/dist`。桌面项目及打包脚本存在其他任务的未提交改动。

## Goals / Non-Goals

**Goals:** 让所有桌面入口使用同一经过来源、版本、架构与哈希验证的 Fork；恢复既有水印的可见性；在现有脏工作区只改本次相关内容。

**Non-Goals:** 不重写原生水印实现，不改变 IPC、页面 UI 或其他平台行为，不顺带合并分叉分支上的无关功能。

## Decisions

- **恢复既有 Fork 解析器和启动器。** 复用已实现的 `ELECTRON_EXEC_PATH` 注入路径，开发和预览脚本经校验后启动。桌面 E2E 与 macOS 打包从同一解析器取得可执行文件。此前已裁决始终使用自有 Fork；本次是执行该决策。替代方案是只在本机设置环境变量，但无法约束测试与打包、不能阻止下次回退，故不采用。
- **恢复来源记录而非仅检查文件存在。** 校验源码提交、哈希、版本、架构与构建参数。替代方案是直接固定本机绝对路径，虽然更小，但无法证明运行的是带水印的构建且不可复现，故不采用。
- **按文件和代码段恢复，不合并整个分支。** 既有 Fork 分支还包含其他变更，当前工作区也有并行编辑。只迁入所需文件并精确修改入口脚本。

## Risks / Trade-offs

- [本机产物或来源记录失配] → 启动明确失败，先重新导出匹配产物；不回退官方 Electron。
- [启动器与正在运行的进程不同步] → 变更后重启应用，再核对进程可执行路径与原生窗口水印。
- [当前工作区并行编辑] → 避免覆盖已有文件，提交时只选择本次文件与代码段；无法干净隔离的改动保持未提交并在交付中说明。
