## Why

仓库经过多轮运行时和插件迁移，留下可能已经失去入口的源码。清理这些代码可降低维护和检索成本，但必须避免误删按包导出、动态加载或测试夹具使用的文件。

Battle 已完成。用户最终选择比逐项保守清理更积极的代码清理，并明确限定为“只删代码”；明确备份、本地构建产物和工具链缓存不在范围内。当前没有未裁决的方向分歧。

提交前全量测试出现 76 项失败后，追加 Battle 已完成。相同测试在 Node v20.14.0 与 v24.20.0 下结果不同，且部分失败在未修改的主工作区复现。用户最终裁决统一测试使用 Node v24.20.0，并在本清理分支修复测试失败；接受同一分支因此包含既有测试基线修复的范围扩张。修复只针对复现并查明根因的失败，不以提高超时或跳过测试掩盖问题。

## What Changes

- 扫描 Git 跟踪的应用、包、插件及脚本代码，按运行、构建、测试、包导出和动态加载入口识别无用文件与无用代码。
- 删除无消费者且无独立入口的源码、随之失效的专属测试及空源码目录；同步清理相关导出、引用和配置。
- 保留有用途的测试夹具、声明文件、脚本入口和包公共入口。若删除将改变外部行为或兼容性，先暂停该项并重新裁决。
- 不清理 `thirdparty/backup`、Git 子模块、文档与设计资产、未跟踪的 `.env.local`，以及 `dist`、`.build`、`out`、`thirdparty/build` 等本地产物或缓存。
- 使用同一 Node v24.20.0 环境对照主工作区和清理分支；在本分支修复已复现的全量测试失败，并记录与清理改动的关系。

## Capabilities

### New Capabilities

无。本变更只清理无用代码，不引入产品能力。

### Modified Capabilities

无。现有可观察行为和 OpenSpec 要求保持不变，因此本变更设置 `skip_specs: true`。

## Impact

可能影响 `apps/`、`packages/`、`plugins/`、`scripts/` 的源码、专属测试和相关导出。清理范围以逐项可达性证据为准；不改变产品接口、依赖版本、构建工具链或持久化数据。

追加测试修复可能触及测试基础设施及既有测试所覆盖的多个模块；每项先在统一 Node 环境复现并定位，避免扩大产品行为修改。
