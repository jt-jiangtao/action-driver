## Purpose

定义自有 Playwright 与 Electron 从全新主仓库检出到真实编译、产物导出和桌面打包验证的命令行为，明确锁定输入、系统前置条件、失败恢复与本机来源记录的边界，避免依赖现有机器隐藏配置或缓存冒充完整构建成功。

## ADDED Requirements

### Requirement: 构建输入可从 Git 恢复
构建流程 MUST 通过受 Git 管理的源码指针、配置模板、依赖锁文件及工具版本记录恢复构建输入；可再生依赖与产物 SHALL 保持忽略，并提供确定的获取或生成步骤。

#### Scenario: 全新源码检出
- **WHEN** 用户递归拉取主仓库且没有本机构建目录
- **THEN** 所有自有源码和必要构建逻辑可获取，不依赖未提交文件，生成必要包边界和配置后准备构建

#### Scenario: 系统前置条件缺失
- **WHEN** 平台、SDK、Metal 或必需系统工具不满足声明条件
- **THEN** 流程明确报告缺失条件与准备方法，停止依赖该条件的阶段

### Requirement: 分阶段构建与失败恢复
统一命令 SHALL 提供准备、同步、构建、导出、验证及打包阶段，按依赖顺序执行并支持显式续跑。失败 MUST 停止后续阶段，记录命令、退出状态和日志；恢复 MUST 重新核验输入和输出。

#### Scenario: 阶段失败
- **WHEN** 下载校验、依赖同步或编译失败
- **THEN** 命令返回非零状态并标明阶段，不报告后续阶段成功

#### Scenario: 工作树有用户改动
- **WHEN** 同步源码或配置将覆盖既有用户修改
- **THEN** 流程明确拒绝覆盖并报告冲突，不执行强制清理

#### Scenario: 从失败阶段恢复
- **WHEN** 用户修复问题后指定续跑阶段
- **THEN** 重新核验前置阶段输入与产物，只复用仍匹配的结果

### Requirement: 本机产物来源真实且独立
产物导出 MUST 记录实际源码、补丁应用结果、构建参数、工具环境、平台架构和完整产物哈希。启动与验证 MUST 核验生成记录，不沿用其他机器哈希，不自动更新记录以接受篡改，不回退官方产物。

#### Scenario: 新机器重建
- **WHEN** 新机器完成真实源码构建并导出产物
- **THEN** 生成对应本机产物的来源记录并核验，不要求与旧机器二进制逐字节一致

#### Scenario: 产物或来源无效
- **WHEN** 产物或来源缺失、被修改或与锁定源码不匹配
- **THEN** 启动及验证明确失败，不通过自动重算哈希报告成功

### Requirement: 全新工作区完整验收
整体构建成功 MUST 通过全新检出、真实远端源码获取、双 Fork 源码编译、基础操作及桌面原生模块和打包启动验证。验收 MUST 记录已安装的系统前置条件，MUST NOT 复制现有工作区的依赖或产物来宣称通过。

#### Scenario: 完整链路通过
- **WHEN** 从不含 thirdparty 构建缓存、node_modules、out 或 dist 的全新检出执行完整流程
- **THEN** 实际完成所有构建与验证阶段，提供命令、来源、产物及结果记录

#### Scenario: 只完成部分阶段
- **WHEN** 仅完成源码拉取、旧工作区增量构建或部分测试
- **THEN** 仅报告已完成阶段，不声明整体新机器构建链路通过
