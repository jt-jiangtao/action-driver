## Context

见 proposal.md。`ModelConnectionService` 当前是 local-runtime 的单一装配入口，同时实现连接服务端口和聊天完成端口；`runtime-storage.ts` 注入存储、密文能力、HTTP 传输和可选图像解析器。服务的 `testConnectionModels` 与 `generateImage` 会在异步请求后重新读取状态，防止旧结果覆盖新连接或在默认模型改变后接受图片。现有 Token Plan 双接口测试与凭据脱敏属于必须保留的行为。

## Goals / Non-Goals

**Goals:** 让能力探测、模型展示与生图规则能分别阅读和测试，同时维持服务对状态和副作用的统一编排；让测试失败能定位到相应业务流程。

**Non-Goals:** 不改变公共端口、DTO、持久格式、模型选择规则、测试请求数量与顺序、并发上限、错误映射、凭据存取方式、进程边界或用户界面。本轮不修改持久规格中尚未解决的密钥保护要求。

## Decisions

1. **保留服务作为唯一状态编排点。** `service.ts` 继续持有连接的读写、加解密错误转换、草稿接口证据缓存，以及异步前后对连接、模型和默认生图引用的复查。`complete`、`stream`、`generateImage` 和公开连接操作仍从同一个实例进入。替代方案是拆成多个有状态服务再由 façade 转发；它会使缓存、连接水位和密钥能力需要跨服务协调，当前没有第二种装配需求。用户裁决选择内部拆分而非新增服务层。
2. **按现有变化轴提取内部模块。** 能力测试模块接收端点、模型 ID 与可注入传输，负责现有最多四模型并发、同模型能力探测及 Token Plan 双接口验证，不持有连接存储。规则模块承载模型展示、聊天候选、生图资格和接口选择等无副作用判断；必要时把 DTO 映射与连接验证留在服务附近的内部函数文件。实现时以实测依赖方向决定最小文件数，不创建单实现接口、额外工厂或跨包公共导出。替代方案是只移动文本块而保留交叉依赖，虽然可缩短主文件，却不能降低理解与测试成本，因此不采用。
3. **按行为拆分测试。** 把现有 35 个显式测试定义（实际运行 41 个用例）按连接管理、能力探测、生图和聊天调用移到 `apps/local-runtime/tests/unit/` 的独立文件。共享工具只包括确定性的内存存储、密文和传输构造；全局 `fetch` 桩由使用它的测试自身建立与清理，避免测试间状态泄漏。先核对异步状态失效及凭据边界的覆盖缺口，再逐块提取代码。替代方案是仅拆生产文件而保留 1397 行单测，仍难以定位业务回归，不采用。
4. **验收用等价性与结构证据。** 记录拆分前的 693 行服务、21 个方法、41 个实际运行的用例和内部依赖；完成后核对服务公开方法、公共导出、依赖方向与各测试组覆盖的行为。行为必须等价；文件变短只作为结构观察，不单独作为成功依据。迭代期运行相关 `pnpm vitest run <file>` 和包级 typecheck，提交前依仓库门禁一次性运行完整验证。

## Risks / Trade-offs

- [提取能力测试改变并发、双接口先后或失败诊断] → 先锁定请求序列与结果的现有测试，保持探测调用与错误映射顺序。
- [把生图资格判断复制到两个模块] → 只保留一个纯规则入口，服务和 DTO 映射共同调用它。
- [异步期间连接、默认模型或启用状态变化] → 重读与拒绝逻辑仍留在服务，由竞态定向测试验证。
- [共享测试工具过大而掩盖行为] → 仅共享确定性基础设施，各测试显式构造所需响应和断言。
- [持久规格与密钥保护实现存在既有冲突] → 本轮不编辑该规格或密钥路径；在独立变更中裁决保护和迁移，不能用本次重构的通过结果声称该安全要求已满足。

用户未覆盖 Agent 推荐；已接受本轮范围控制。若需改变凭据所有权、安全边界或存储格式，停止相关实施并重新 Battle。

## Migration Plan

无数据或接口迁移。内部模块可逐块回退到 `service.ts`；测试文件拆分可独立回退，不改变运行时状态。

## 验证记录

- 基线：原服务 693 行，公共导出为 `ModelConnectionServiceOptions`、`ModelConnectionService`、`validateDraft`；原测试文件 35 个显式定义、参数化展开后 41 个用例，定向运行 41/41 通过。
- 拆分后：服务 490 行；新增无状态规则 75 行、能力探测 131 行、错误归一化 30 行。新增模块只依赖现有 catalog、adapter、transport 与错误模块，不反向导入服务；公共导出与装配点未改。文件行数是结构观测，不是速度或维护收益的实测值。
- 测试按连接管理 6、能力探测 11、生图 11、聊天 13 个实际用例归组，合计 41/41 通过；加上 `model-gateway` 14 与 `service-http` 25，六文件定向测试共 80/80 通过。`pnpm --filter @action-driver/local-runtime typecheck` 通过。
- 新工作树初次包级 typecheck 因 `plugin-contracts` 与 `plugin-sdk` 缺少 `dist` 类型产物而失败；按两个包的既有 build 脚本构建后，相同 typecheck 通过。没有改动这两个包的源码或依赖。
- 提交前门禁：`pnpm typecheck` 通过（先构建新工作树缺失的 `browser-runtime`、`sky`、`browser-desktop`、`cua` 类型产物；此前失败均为这些包的 `dist` 声明缺失）；`pnpm lint` 通过，含 152 条交互声明校验；`pnpm test` 为 431 个文件通过、13 个文件失败、2 个文件跳过，2598 个用例通过、59 个用例失败、5 个用例跳过，另有 1 个 suite 失败。失败文件不含本次拆分的四个测试文件。主要原因是新工作树没有 local-runtime 打包运行时、插件及 JS REPL 资源，另有基线 `database.test.ts` 仍预期迁移到 v16，而当前基线已含 v17。未为本轮重构改动这些资源或旧测试；全量测试不能声明通过。
