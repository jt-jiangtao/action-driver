## Context

见 [proposal.md](./proposal.md) 的问题背景与 [desktop-shell delta](./specs/desktop-shell/spec.md) 的行为要求。当前 `App` 只保存一个 `AppRoute`，没有应用页面历史；设置路由携带 `returnTo`。侧栏头行、`HomePage`、`TaskHeader`、`BrowserTabBar` 和设置侧栏各自提供拖拽与顶部控件，分别使用 24、36、44、56px 布局。浏览器网页历史由 `BrowserNavigationBar` 和 Browser Session 管理，必须与应用页面历史分离。

## Goals / Non-Goals

**Goals:**
- 以同一个顶部尺寸和背景 Token 约束各可见区域，并用共享导航控件保持窗口坐标稳定。
- 在 Renderer 内管理应用页面后退／前进，覆盖设置子页面、主页和任务页。
- 保留主提示词现有的未保存内容离开确认以及任务恢复语义。

**Non-Goals:**
- 不将浏览器网页地址或标签页写入应用页面历史。
- 不引入系统级浏览器历史、跨重启历史持久化或新的 Main IPC。
- 不改变任务运行状态、浏览器会话所有权和设置页业务内容。

## Decisions

### 统一顶部采用共享控件和布局 Token

在现有各区域顶部复用一个语义化的应用导航控件组，统一 44px 高度、浅色背景和边框；导航按钮的可见控件缩为 28px，保留清晰焦点和可点击区域。应用导航按钮中心位于 y=22。macOS 原生按钮通过修复后的 Electron fork 使用 `titleBarStyle: 'hiddenInset'` 与 `trafficLightPosition: {x:14,y:15}` 定位。侧栏展开时控件位于侧栏头行，折叠时位于当前可见内容的头行，布局为两种状态保留相同的窗口横向坐标。设置页侧栏顶部同样承载应用左右按钮。任务页浏览器独占时由浏览器顶部承载恢复按钮。使用 Grid/Flex 与共享尺寸变量实现，避免依赖页面各自估算的左内边距；保留 macOS 窗口控件安全空间和拖拽区域。

替代方案是给每个页面单独微调 padding 和背景，改动较少，但当前 24/36/44/56px 分歧和折叠时按钮换容器正是偏移原因，后续新增设置页也容易再出错。没有新增依赖或不可逆影响。用户裁决选择统一方案 A。

### macOS 27 原生按钮位置修复

在当前 Electron 38.8.6 fork 上，主进程传入 `{x:100,y:30}` 并在窗口显示后调用 `setWindowButtonPosition`，`getWindowButtonPosition` 返回相同数值，但三个系统按钮在截图中仍位于默认坐标。`titleBarStyle: 'hidden'`、`hiddenInset`、`titleBarOverlay.height`、延迟重设与窗口尺寸重排均未改变可见位置。原生日志确认 macOS 27 将按钮直接放在全窗口根视图中，旧实现查找两层父视图得到空值。修复后的 Cocoa 路径只移动三个按钮，不调整根视图高度，并在 AppKit 改变按钮 frame 后重设边距。用户对首次修复截图反馈“偏下了”，因此将顶部边距从 17 调为 15；原生按钮高度为 14，中心为 y=22。保留旧版 macOS 的嵌套标题栏路径，更新 fork 锁定提交并导出本地 Electron 构建。

替代方案是将 Renderer 导航控件上移约 6px，能快速实现视觉对齐，但无法满足用户明确提出的“优先调整红绿灯位置”。用户了解 fork 重编译和维护成本后裁决采用原生修复。风险是 macOS 版本差异可能导致 AppKit 再次重排，因此保留其他系统默认行为并覆盖显示、聚焦、缩放场景；如果原生系统禁止重定位，需要重新 Battle，不以仿制按钮替代。

### 应用历史由 App 路由层持有

在 `App` 的路由层维护条目序列与当前位置。普通页面跳转在当前位置之后追加去重条目；后退／前进只移动指针；从旧位置打开新页截断前进分支。折叠侧栏、任务浏览器模式变化和浏览器网页导航不追加历史。任务条目再次激活时按 task ID 从现有仓库／目录恢复投影；条目不可用时保持当前页并显示可恢复反馈，不留下空白任务页。`returnTo` 仍用于“返回应用”，返回操作走同一个路由切换入口。

替代方案是直接使用 `window.history`，但当前路由只存在 React 状态，且任务恢复、设置页 `returnTo` 和未保存内容确认没有 URL 映射；引入 URL/History API 会扩大范围。用户确认的 A 是应用页面历史，不是浏览器网页历史。

### 离开确认先于历史位置提交

应用左右按钮经过当前页面的离开拦截。主提示词存在未保存修改时复用已有确认对话框；只有确认离开后才移动历史指针。取消不会改变页面、草稿或按钮启用状态。其他页面正常切换。保留现有 Browser Session 的前进／后退按钮与测试 ID。

## Risks / Trade-offs

- [各区域改为 44px 会改变浏览器内容可用高度] → 以现有 viewport 测量和 ResizeObserver 更新嵌入区域，验证任务分栏及独占布局。
- [折叠时控件换承载区域可能重现 6px 偏差] → 共享同一控件组和起始槽宽，并在首页、任务页、浏览器独占和设置页比较 `boundingBox`。
- [异步任务恢复与快速历史点击竞态] → 为恢复请求使用递增序号，仅最后一次有效导航提交页面和历史位置。
- [主提示词离开确认被新按钮绕过] → 将历史导航接入其现有 `requestNavigation`，覆盖取消和确认测试。
- [macOS 27 会覆盖 Electron 的原生按钮视图布局] → 订阅原生按钮 frame 变化并重新定位；使用实际构建窗口与用户截图反馈验收。用户要求本轮不再运行单元测试，后续 macOS 系统升级时仍需复查原生控件。
- [fork 源码与本地二进制不一致] → 同步更新子模块提交、锁文件和导出记录，在提交前验证构建产物来源。
- [用户覆盖] → 无；用户选择了推荐的应用页面历史方案 A，并在实际截图反馈后明确要求缩短顶部、缩小按钮及对齐原生窗口按钮。原先的 56px 设计高度被 44px 取代。原生定位失效的新证据出现后，用户明确裁决优先修复 Electron fork。

## Migration Plan

无数据迁移。先实现路由历史与共享导航，再统一顶部布局；用定向组件／E2E 检查状态与坐标。回滚时移除 Renderer 的历史状态与顶部控件即可恢复原布局。
