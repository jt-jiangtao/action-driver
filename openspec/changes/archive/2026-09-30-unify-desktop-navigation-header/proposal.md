## Why

桌面窗口的侧栏、任务区、浏览器区和设置页使用不同高度与背景的顶部区域；折叠侧栏时按钮换位，造成明显跳动。用户还需要在应用页面之间前进和后退，而现有左右按钮只控制任务内浏览器。

Battle 已完成：用户选择应用页面历史方案 A，并确认任务内浏览器保留独立导航。目标是顶部视觉一致、按钮在折叠及页面切换后保持窗口坐标稳定，且页面历史可前进和后退；无未决关键分歧。

## What Changes

- 将首页、任务页及设置页的顶部区域统一为同一高度和背景色，覆盖左侧栏、任务区与浏览器区。
- 在桌面窗口顶部提供固定位置的侧栏折叠／展开按钮与应用页面后退／前进按钮；设置页也显示同一组左右按钮。
- 记录应用内页面访问历史，支持返回与重新前进，并在没有对应历史时禁用按钮；任务内浏览器原有导航保持独立。
- 保留切换前的任务、侧栏、浏览器布局及适用的编辑状态，避免导航造成内容或按钮位置跳动。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `desktop-shell`: 扩展桌面顶部布局、侧栏切换稳定性及应用页面历史导航要求。

## Impact

涉及 Renderer 的 App 路由状态、共享顶部控件、首页与任务页头部、浏览器标签栏、设置侧栏和相关 CSS 与定向交互测试，以及 macOS 原生窗口按钮布局。原生 Electron API 在 macOS 27 的实际运行窗口中接受位置参数却不移动系统按钮；用户裁决优先修复现有 Electron fork。该部分需要更新 fork 源码、构建产物与仓库锁定提交，不新增 Renderer IPC、持久化格式或外部依赖。
