## Context

见 proposal.md。现有实现仅在模型主动调用内部活动更新时建立时间线；普通工具流和快照投影缺少活动事实来源，Renderer 因而显示旧工具卡。

## Goals / Non-Goals

**Goals:**

- 让每个真实工具工作阶段呈现为一个含 `n` 条工具的活动任务。
- 让实时流、重连和快照恢复共享同一活动过程。
- 令任务页只使用 Codex 风格的扁平活动行、展开式原始 I/O 和完成归档。

**Non-Goals:**

- 不公开模型原始思维链，不变更工具权限或模型提供商协议。
- 不定义完整 LLM 调用日志的保留和脱敏策略。

## Decisions

### Runtime 生成受控兜底活动

模型的 `activity.update` 仍是较丰富的标题来源；当其缺失时，Graph 在第一条外部工具前生成稳定兜底活动，并在同一连续工作阶段内复用该 id。这样一条任务容纳 `n` 个工具，且工具调用不再各自成为卡片。替代方案是在 Renderer 按工具类型或相邻事件猜测分组；这会在重连时不稳定并违背 Runtime 是唯一事实来源的边界。用户已确认 Runtime 聚合。

### 快照携带活动过程投影

快照同时返回活动组、按 cursor 排列的活动正文/工具引用和每条工具的原始 I/O 边界。替代方案是恢复后重放或重算历史；前者受事件保留期限制，后者会改变标题与顺序。选择快照投影以确保重新打开任务后与实时界面一致。

### 移除 Runtime 任务的旧卡回退

Runtime 驱动任务总是渲染活动时间线；空过程仅显示“正在思考”或完成结论。替代方案是保留旧卡作为缺失活动时的容错 UI；它正是本次回归的可见原因，且与 Codex 视觉规则冲突。

## Risks / Trade-offs

- [兜底标题较模型摘要泛化] → 标题只描述可观察工具意图，显式受控摘要到达后在原位更新。
- [快照负载增大] → 复用既有原始 I/O 上限和截断标记，且只投影单任务所需过程。
- [旧任务没有活动历史] → 对遗留数据构造受控恢复活动，避免展示旧类别卡。

## Migration Plan

1. 用失败测试固定普通工具流和快照恢复的回归。
2. 在 Runtime 中写入兜底活动和完整快照投影。
3. 将 Desktop 统一到活动时间线，移除旧卡分支并做视觉 E2E 验证。
4. 若发生回归，保留事件与快照数据但回滚 Renderer 的新样式；不恢复固定类别卡作为长期路径。
