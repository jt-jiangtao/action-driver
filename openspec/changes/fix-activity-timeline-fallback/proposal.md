## Why

真实模型工具流未发送 `activity.update` 时，任务页会回退到旧的“运行中 / 运行结束”工具卡，违背已发布的 Codex 风格活动时间线契约。快照恢复也未重建活动过程，导致已完成任务重新打开后无法稳定回看过程。

这是执行型回归修复：先前 Battle 已裁决动态活动任务、受控标题和结束态归档；本次不改变这些交互或系统边界，只确保全部真实工具流和恢复路径兑现既有契约。

## What Changes

- Runtime 在工具调用缺少模型显式活动更新时，生成受控的兜底活动记录，并将一个连续工作阶段的 `n` 条工具调用与其间正文关联到同一任务。
- 活动过程成为快照与恢复投影的一部分，确保重连和重新打开任务后仍保留任务、工具、正文及原始 I/O 的顺序。
- Desktop 任务页停止将存在工具记录的真实任务回退为旧的分组工具卡；活动时间线以 Codex 风格的扁平行呈现运行态、归档态与原始 I/O。
- 补充真实普通工具流与快照恢复的单元及桌面 E2E 回归覆盖。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `codex-task-activity`: 要求所有实际工具流与恢复投影均呈现动态活动任务，而非旧工具类别卡。
- `agent-tool-runtime`: 要求没有模型显式活动更新的工具调用获得受控活动归属，且活动过程可在快照中恢复。

## Impact

- 影响 Agent Graph、Stream Session 的事件与快照投影，以及 Desktop Renderer 任务页和相关单元/E2E 测试。
- 不新增第三方依赖，不改变工具权限、模型调用协议或远程服务边界。
