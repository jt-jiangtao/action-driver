## MODIFIED Requirements

### Requirement: 动态活动任务与有序正文
系统 SHALL 将一个 Turn 呈现为按 cursor 排列的正文片段和动态活动任务，而不是固定工具类别或每次 LLM 调用的卡片。活动任务 MUST 具有稳定 `activityId`，且可混排正文、网页搜索、文件读取、Shell 与文件编辑事件。系统 MUST 对全部实际工具流建立活动任务：模型显式提供活动更新时采用该受控摘要；缺失时 Runtime MUST 为连续工作阶段创建受控兜底活动，并将该阶段的 `n` 条工具调用及其间正文保序归属到同一活动任务。客户端 MUST 在实时、重连和快照恢复时使用同一活动投影，MUST NOT 将存在工具记录的任务回退为固定工具类别卡。

#### Scenario: 异构工具属于同一工作目标
- **WHEN** Agent 为同一受控任务摘要依次读取文件、搜索网页并运行命令
- **THEN** 客户端在同一个活动任务中按发生顺序显示这些事件

#### Scenario: 正文位于任务之间
- **WHEN** Runtime 发送没有 `activityId` 的可见正文事件
- **THEN** 客户端在相邻活动任务之间将其呈现为独立正文片段

#### Scenario: 普通工具流缺少显式活动更新
- **WHEN** 模型发起一个或多个外部工具调用且未发送活动更新
- **THEN** Runtime 创建受控兜底活动任务，并将该连续批次的所有工具调用显示为同一任务内的平铺条目

#### Scenario: 从快照重新打开完成任务
- **WHEN** 客户端通过快照恢复包含工具调用的已完成任务
- **THEN** 页面显示原有的活动过程归档和最终结论，而不显示“运行中 / 运行结束”工具类别卡
