## Purpose

定义内嵌浏览器的导航、观察、动作与用户控制行为，使 Agent 能在产品内部真实操作网页，并把过程与结果实时投影到界面。

## ADDED Requirements

### Requirement: 在产品内部执行网页导航
系统 SHALL 在应用内部载入与操作网页，MUST NOT 调起外部浏览器；导航栏 SHALL 反映当前地址与加载状态，并保持既有布局。

#### Scenario: 打开目标网页
- **WHEN** Agent 或用户导航到一个地址
- **THEN** 网页在应用内部渲染，导航栏显示当前地址与加载状态

#### Scenario: 导航失败
- **WHEN** 地址不可达或加载超时
- **THEN** 界面展示可诊断的失败状态，任务不伪造成功

### Requirement: 提供结构化观察
系统 SHALL 提供结构化页面观察，包含可交互元素、可见文本与结构层级，并为元素提供稳定引用；引用 MUST 在页面变化后按规则校验，失效时返回失效结果而不是指向其他元素。

#### Scenario: 观察结果包含稳定引用
- **WHEN** Agent 请求当前页面观察
- **THEN** 返回的元素带有可在后续动作中使用的稳定引用与语义描述

#### Scenario: 元素失效
- **WHEN** 页面变化导致先前引用失效
- **THEN** 使用该引用的动作返回可诊断的失效结果，不作用于其他元素

### Requirement: 通过受约束动作操作页面
系统 SHALL 只允许受约束的动作集合（导航、点击、输入、选择、滚动、按键、等待、截图）通过 Browser Skill 执行，动作 SHALL 支持超时与取消，并 SHALL 返回可观察结果。

#### Scenario: 执行点击
- **WHEN** Agent 通过 Skill 请求点击一个有效引用
- **THEN** 动作在页面上执行，返回结果并触发后续观察

#### Scenario: 动作超时或取消
- **WHEN** 动作超出截止时间或任务被中断
- **THEN** 动作返回超时或取消结果，迟到的页面变化不被当作新的成功结果

### Requirement: 把过程投影到界面
系统 SHALL 在任务时间线中展示观察与动作步骤，并 SHALL 在当前页面高亮当前目标元素；界面 MUST 从同一状态来源投影，不重复实现页面语义。

#### Scenario: 展示当前目标
- **WHEN** Agent 选择了一个目标元素
- **THEN** 浏览器区域高亮该元素，时间线展示对应步骤

#### Scenario: 状态一致
- **WHEN** 步骤状态变化
- **THEN** 时间线与浏览器面板显示一致的状态，不出现互相矛盾的结果

### Requirement: 支持用户控制与接管
系统 SHALL 在浏览器区域提供暂停、继续与人工接管控制，并使控制结果对 Agent 可见；接管期间 Agent MUST NOT 继续发起新的浏览器动作。

#### Scenario: 暂停与继续
- **WHEN** 用户暂停运行中的浏览器任务
- **THEN** Agent 停止发起新动作，任务停在最近安全状态；继续后从该状态恢复

#### Scenario: 人工接管
- **WHEN** 用户接管浏览器
- **THEN** 界面进入接管状态，Agent 不再自动操作，直到用户交还控制

### Requirement: 引擎实现可替换
系统 SHALL 允许按 Provider 标识替换浏览器引擎实现，并 SHALL 为不同引擎保留各自接口与评测边界；切换引擎 MUST NOT 改变页面与 Agent 的既有契约。

#### Scenario: 注册引擎
- **WHEN** Browser Skill 以某个引擎实现注册
- **THEN** Agent 通过同一 Skill 契约调用，页面与任务投影无需修改

#### Scenario: 多引擎并存
- **WHEN** 同时存在多个浏览器引擎实现
- **THEN** 系统按注册信息选择实现，不把两者抽象成同一个底层实现
