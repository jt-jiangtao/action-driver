## Context

参见 `proposal.md` 的 Why。既有约束：`agent-skill-boundary` 要求 Agent 通过统一 Skill 契约调用能力、Browser 与 Computer 独立注册；服务端是配置的写入者（见 `serve-runtime-over-http`）；页面通过窄桥/服务端接口访问能力，不直接构造实现。

## Goals / Non-Goals

**Goals**

- 建立 Skill 注册表与页面入口，使新增能力只需注册。
- 保持内置 Skill 与自定义 Skill 的清晰边界。
- 为后续 Browser/Computer 真实实现留出注册位置。

**Non-Goals**

- 不实现 MCP（仅保留入口）。
- 不实现自定义 Skill 的沙箱执行、市场分发或版本升级。
- 不改变 Agent Loop 的调用契约。

## Decisions

### 1. Skill 注册表由服务端持有
与模型连接一致：服务端写入本地、页面只读与变更状态。替代方案是客户端持有定义并注入 Runtime：会出现两个事实来源。

### 2. 首版自定义 Skill 采用声明式描述
自定义 Skill 首版只包含元数据（标识、名称、描述、输入/输出说明），执行仍由已注册的执行器承担。替代方案是可执行脚本包：需要沙箱、依赖与权限模型，超出本期范围。

### 3. 内置 Skill 只读
Browser Use 与 Computer Use 作为内置项，只能启用/停用，不能删除或改名，避免与后续真实实现冲突。

### 4. 页面复用设置页的组件与交互语义
Skill 管理页复用设置页的列表、状态胶囊、空状态与错误提示样式，保持 Figma 已确认的视觉语言。

## Risks / Trade-offs

- [自定义 Skill 描述与实际执行能力不一致] → 首版只允许启用已注册执行器的 Skill，未注册执行器在调用时返回能力不可用。
- [Skill 列表与 Runtime 注册表不一致] → 服务端作为唯一来源，Runtime 在任务开始时读取同一声明；测试覆盖"停用后调用被拒绝"。
- [新增页面引发视觉回归] → 新增页面使用既有组件与间距体系，并补充视觉验收。

## Migration Plan

1. 服务端注册表与接口（含内置项种子）。
2. 客户端数据接入与容器绑定。
3. Skills 页面与侧栏入口接线。
4. 运行组件、视觉与集成验证。

回滚：隐藏侧栏 Skills 入口并切回只读列表。
