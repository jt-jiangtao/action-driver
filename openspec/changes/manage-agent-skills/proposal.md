## Why

模型连接、主提示词、Skill 状态与日志目前分散在不同入口或仅有 Mock，用户无法在一个稳定位置配置 Agent 的真实运行上下文。需要先建立由本地 Runtime 持有的 Agent 配置中心，让后续真实发送能够读取同一份主提示词、Skill 与模型连接数据。

## What Changes

- 在设置侧栏新增“Agent”分组及“主提示词”“Skills”页面，保留“模型连接”和“日志”入口。
- 主提示词首版采用全局唯一配置，直接读写 `~/.action-driver/prompts/main.md`，在同一个编辑面板中提供 Markdown 实时渲染与 Monaco 源码模式、显式保存、未保存提醒、恢复默认值及失败重试。
- Skill 页面直接管理 `~/.action-driver/skills/<skill>/` 文件夹：列表进入详情后使用文件树与单编辑面板编辑 `SKILL.md`、引用资料和脚本文件；首版不因文件存在而自动获得可执行权限。
- `SKILL.md` 通过可选的 `executor` frontmatter 显式映射已注册执行器；目录名继续作为配置标识而不强制等于执行器 ID。只有映射到当前已注册执行器且处于启用状态的 Skill 才会进入任务运行上下文，缺少或无法解析执行器的 Skill 显示为不可用并拒绝启用或调用。
- 应用主侧栏的 Skills 入口作为快捷入口打开同一个设置页，不建立第二份页面或数据。
- Runtime 作为唯一写入者，通过受限文件服务读写 `~/.action-driver`；主提示词与 Skill MUST NOT 写入数据库、`localStorage` 或独立 JSON 注册表。
- 设置内容区复用唯一的 248px 设置侧栏，页面内部使用局部 Auto Layout 保证对齐，但不为了组件复用牺牲视觉还原；日志页按用户最新裁决采用 Codex 式简约内容区（右侧纯白、中性灰分隔、蓝色仅用于选中态和链接）。
- 这些页面的生产组合根移除 Mock 数据依赖；确定性 Mock 仅保留为单元测试、组件测试和视觉状态验收的可替换实现。

## Capabilities

### New Capabilities

- `skill-management`: 定义本地主提示词与 Skill 配置的编辑、持久化、运行时读取、状态管理及设置页面行为。

### Modified Capabilities

- `desktop-shell`: 设置侧栏新增“主提示词”和“Skills”，应用主侧栏 Skills 入口跳转到同一设置页面，并保留模型连接与日志导航。

## Impact

- Runtime：新增限定在 `~/.action-driver/prompts` 与 `~/.action-driver/skills` 的文件读写、目录枚举、原子保存和任务启动读取能力。
- 客户端：新增与现有 ActionDriver 主题一致的主提示词与 Skills 设置页、单面板 Markdown 编辑、Monaco 源码模式和设置导航；应用主侧栏 Skills 改为快捷入口。
- 契约：新增主提示词文件、Skill 目录树、文件内容、保存状态与执行器状态 DTO，以及相应查询和变更接口。
- 测试：生产组合根验证不注入 Mock；测试组合根继续使用确定性替身覆盖加载、空、保存、失败和删除等状态。

## Battle Status

- 类型：产品与架构混合决策。
- 状态：**已完成并由用户明确裁决**。
- 最终方向：采用方案 A，由本地 Runtime 独占读写 `~/.action-driver` 文件目录，不使用数据库；主提示词首版全局唯一；Skill 以目录和文件为事实来源，通过 `SKILL.md` 的 `executor` frontmatter 显式映射执行器，目录名不承担运行时 ID；仅已注册且已启用的执行器可进入任务上下文并被调用；设置页为唯一管理入口；生产路径去除 Mock，测试替身保留。
- 视觉方向：用户在视觉复核后覆盖此前的 Primer 优先方向，改为“生图还原优先、组件复用次要”。所有设置页使用既有 248px 设置侧栏、品牌色和主题 Token。Figma 设计稿按 `04 Model Configuration`、`05 Agent Configuration`、`06 Logs` 分页管理，分别存放模型配置、主提示词与 Skills、接口层与模型层日志；该设计稿分组不改变应用内统一设置导航。
- 日志视觉补充裁决：用户要求日志内容区贴近 Codex 简约风格。保留统一设置侧栏和日志信息架构，右侧画布改为纯白，边框与分隔线改为低对比中性灰，避免浅蓝大面积铺底；语义成功、运行、失败色继续保留。
- Agent 配置视觉补充裁决：用户要求删除既有 Agent 配置稿并重写，不再保留重复的 Fidelity/旧版页面。新稿与日志页共享 Codex 式纯白简约内容区，保持统一设置侧栏；浮层使用固定尺寸体系与明确层级（页面、遮罩、抽屉/模态框），并完整保留主提示词和 Skills 的保存、错误、菜单、筛选、创建、删除及历史状态。
- 已比较替代方案：Renderer `localStorage`、JSON 注册表或 SQLite 会形成用户可见文件与内部记录的双重事实来源；强制 Skill 目录名等于执行器 ID 会要求迁移既有 `browser-tools` 等目录并把可读配置名与内部能力标识耦合；强行套用 Primer 或统一组件外观会偏离已确认生图并产生第二套侧栏。因此采用 Runtime 受限文件服务、`executor` 显式映射、原有主题和页面内局部布局方案。
- 未解决关键分歧：无。
