## Why

生成文档或图片后，用户需要在产生它的任务中直接看到并打开成品；上传的文档和图片也应进入工作目录，供同一会话的后续任务使用。当前脚本共用一个工作区，且能够读取其他会话的文件与 Runtime 凭据，无法满足用户明确要求的跨会话严格隔离。

## What Changes

- 每个会话拥有独立工作目录及 `input/`、`output/`；上传的 DOCX、PPTX、XLSX、PDF 和受支持图片进入本会话 `input/`，在发送消息和历史任务中显示文件卡片，图片保留缩略预览。同一会话的后续任务可读取这些输入。
- 自动登记当前任务在本会话 `output/` 下新建或更新的 DOCX、PPTX、XLSX、PDF 和受支持图片；每个任务保存独立不可变成品副本，结果区展示类型、名称、大小和“打开文件”，历史任务始终指向自己的版本。
- 所有脚本工具按当前会话工作目录启动，并由 macOS 每会话进程沙箱阻断其他会话文件、应用私有资产与本地 Runtime 接口；子进程不继承服务令牌和凭据。沙箱不可用时拒绝脚本执行。由 Runtime 代读文件的工具同样校验会话范围。
- 桌面主进程仅按已登记的文件标识打开可核验的本地副本；输入、输出的元数据及任务／会话归属可在重连和重启后恢复。现有图片消息和生图结果继续正常显示。

## Battle

- 类型：产品与架构混合决策；状态：已完成，用户逐项明确裁决。
- 目标与验收：输入在工作目录内可见、同会话后续任务可读；其他会话的脚本和代读工具不能按路径或本地接口取得这些文件；生成成品出现在产生它的任务，点击能打开当时版本。
- 事实与假设：当前图片资产保存在应用私有目录，脚本工具共用工作区并继承 Runtime 环境变量；单纯按会话分目录或隐藏页面入口不足以隔离。macOS 本机诊断验证了进程沙箱可拒绝跨目录读取，但系统手册明确标注 `sandbox-exec` 已弃用。
- 产品方案比较：解析回复中的链接依赖模型手写路径；扫描整个工作区会混入中间文件；仅登记 `output/` 成品使交付物边界明确。用户选择自动登记 `output/`，为每任务保留独立副本，并让输入在页面展示及同会话后续任务可读。
- 隔离方案比较：仅限制自动发现和 UI 无法阻止脚本读文件；每会话容器或虚拟机有独立边界，但增加部署依赖、资源开销和启动耗时；macOS 每会话进程沙箱可复用现有脚本运行时，但需要收紧文件、环境变量、进程与本地服务访问，并承担弃用风险。Agent 推荐后者，用户明确选择后者及严格跨会话隔离。
- 已知代价：现有脚本读取任意本机文件的能力将收紧；`sandbox-exec` 弃用可能需要未来迁移；每任务副本占用本地空间。用户理解并接受这些代价。若沙箱不可用，任务获得明确错误而非退回无隔离执行。
- 重新开启条件：macOS 沙箱无法在打包应用中稳定实现所需边界，或出现新的跨会话读取通道。其他已裁决项不重复 Battle。

## Capabilities

### New Capabilities

- `generated-local-files`：定义 `output/` 成品登记、任务版本、文件卡片、历史恢复和本地打开。
- `session-input-files`：定义输入文档及图片进入会话工作目录、页面展示、同会话复用及跨会话可见性。

### Modified Capabilities

- `sandbox-execution`：把脚本默认工作目录和文件访问边界从共享工作区调整为每会话沙箱，并约束 Runtime 代读工具的文件访问。

## Impact

- Runtime：扩展附件上传、存储与任务投影；建立会话工作目录和成品清单；给工具执行传入可信会话上下文；限制子进程和代读工具的文件、网络与凭据访问。
- Desktop：扩展输入选择和文件卡片、图片预览、打开文件的类型化桥接及错误反馈。
- 兼容性：原有图片消息与历史记录继续恢复；既有共用工作区文件不自动归入任一会话。Office／图片生成 Skill 的最终文件路径约定需要切换到会话 `output/`。
