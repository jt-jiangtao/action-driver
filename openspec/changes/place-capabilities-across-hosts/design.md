## Context

见 [proposal.md](proposal.md)。已有 `local/cloud` 工具身份、grants、插件实例固定与 Desktop 本地能力 WebSocket 通道。运行位置尚不是统一可声明、可发现和可选择的契约；完整多宿主能力需要与贡献目录及资源 URI 平台衔接。

## Goals / Non-Goals

**Goals:**

- 在 UI、本地工作区、远程工作区和云端宿主中按能力需求选择唯一执行位置。
- 跨宿主保持来源、授权、版本、取消和结果未知语义。
- 断连与重连后安全恢复可用性，不自动重放副作用。

**Non-Goals:**

- 不合并 `local/cloud` 工具身份或 grants，不让 UI 宿主获得原始桌面权限。
- 不把“能连接某宿主”视为可以迁移现有任务或副作用调用。

## Decisions

### 位置与工具 target 是不同维度

插件声明可运行位置、偏好及设备/工作区要求；调用方的 target 与 grants 仍独立检查。选择器只在兼容、已安装、已授权且在线的宿主中确定一个实例，并将决定记录在调用上下文。替代方案是用工具 ID 的 `local/cloud` 直接推断具体进程位置，无法表达 UI 低延迟能力和远程工作区文件归属，不采用。

### 宿主以版本化握手和实例租约接入

本地与远程宿主注册能力、协议版本及实例 ID；Runtime 负责选择和调用路由，宿主只执行被授权的最小操作。断连撤回新调用，重连重新握手；旧实例消息按 epoch 拒绝。替代方案是复用当前本地通道并仅验证位置声明，成本较低但不具备用户裁决的多宿主调度与恢复。用户选择完整能力，接受新的传输与运维成本。

### 在途调用固定，不自动迁移

调用开始时固定宿主和插件版本；取消和期限向该宿主传播，副作用未确认时标记结果未知。新调用可在重新发现后选择其他合格宿主，但必须重新校验 target、grants 和资源访问。替代方案是断线自动在其他宿主重放，存在重复本机/云端副作用风险，不采用。

## Risks / Trade-offs

- [多宿主调度、远程传输与故障恢复的建设和运维成本高] → 分阶段接入宿主类型、协议兼容检查和故障演练；这是用户覆盖静态校验建议时接受的代价。
- [位置选择扩大数据与凭据暴露面] → 最小上下文、凭据代理、资源 URI 授权和位置审计。
- [断连时副作用结果不可知] → 结果未知终态、禁止自动重放，用户显式发起新请求。
- [升级或迟到消息污染新实例] → 插件版本固定和宿主 epoch 校验。
- [与资源 URI 或贡献点协议并发实现产生漂移] → 依次稳定两者契约，再实施位置选择；三份变更独立验证。

## Migration Plan

1. 增加位置声明和版本化宿主握手，保持现有本地能力可通过兼容适配注册。
2. 加入位置选择、调用固定、授权及审计；接入 UI 与本地工作区宿主。
3. 接入远程工作区/云端宿主、资源引用、取消和故障恢复。
4. 验证混合位置、断连、重连、升级和旧插件兼容；回滚时只使用旧本地路径，远程要求明确不可用而不静默回落。
