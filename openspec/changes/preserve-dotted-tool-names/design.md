## Context

当前 createToolIdentity 在公共 SDK 把点号和连字符换为下划线。OpenAI function 协议禁止点号，但这一限制不应污染公开 API。用户已明确裁决兼容性边界。

## Decisions

- 公开 id/modelName 对内置工具相同且使用点分隔，公共校验允许点号；第三方既有合法名字继续接受。
- 仅 provider adapter 创建当前请求的双向映射，wire 名称仍用兼容下划线形式。发送 tools、历史 assistant tool calls 和 tool result 的 name 统一转换；回传 preparing/end 恢复原公开名称。
- 转换冲突和超长/非法协议名称在发送前拒绝，未知响应不猜测命名空间或授权。
- 用户后续裁决：项目尚未发布，直接替换，不保留旧名称/授权别名与迁移层，不因本次修改升级 SDK/插件版本。
- 比较方案：完全取消转换会被 OpenAI 拒绝；继续公开下划线不符合用户命名需求。最终采用用户选择的协议边界转换。

## Risks / Trade-offs

模型可能自然复述 wire 名称；通过公开名称描述与指令明确展示规范，但不改写任意模型正文。不兼容未发布旧名称，规范名称转换后的冲突明确失败，不静默映射到其他工具。项目未发布，本次直接更新 schema，保持当前版本号。

## Implementation Plan

先以公开契约及 provider 流式/历史回归证明旧行为失败，再同步名称和公共声明；协议层建立双向映射并验证冲突与回传；最后运行命名相关定向测试、类型检查和 lint，不在迭代阶段执行全量测试。
