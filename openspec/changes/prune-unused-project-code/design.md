## Context

参见 `proposal.md`。仓库有多个 TypeScript 包、Electron 三进程入口、插件清单、脚本入口及 Swift helper；`packages/back` 是明确备份。`git ls-files` 中约 1,052 个应用、包和插件代码文件。初步静态相对导入扫描出现 147 个零入边文件，但其中包含 `runtime-entry.ts`、插件入口、脚本和包导出，因此零入边只能生成候选，不能直接作为删除依据。已核实 `apps/desktop/src/shared/detail-bounds.ts` 目前无源码引用，可作为首个删除候选。

## Goals / Non-Goals

**Goals:**

- 在整个受控代码范围内发现并删除无用源码、专属死测试和空源码目录。
- 每个删除组都保留可复核的入口与引用证据；更新受影响的导出和配置。
- 清理后既有类型、Lint、定向测试、构建及必要的本地运行路径仍可用。

**Non-Goals:**

- 不修改产品功能、公共契约、持久化格式或安全限制。
- 不删除备份、子模块、文档、设计资产、本地配置、依赖安装或本地构建产物。
- 不因代码没有当前生产调用就删除仍由有效测试、分析工具或公开包入口使用的代码。

## Decisions

### D1：采用积极的源码清理，但以多入口可达性核对控制误删

原建议是仅删除逐项完全证实无用的文件。用户最终裁决采用更激进的清理：覆盖整个受控代码范围，也清理文件内部无用导出、失效测试与空目录。可执行替代方案是只做静态导入图的批量删除；它更快，但会把 Electron、插件、CLI、资源和包导出入口误判为死代码。选择全域候选扫描加入口核对，允许删除仅由已失效专属测试引用的实现及测试，同时保留真实契约。

### D2：入口清单优先于单一静态工具结果

入口清单取自根目录及工作区 `package.json` 的 `scripts`、`exports`、`bin`、插件 `plugin.json`、Electron Vite 配置、HTML/预加载入口、Swift `Package.swift`、资源复制脚本、测试配置和动态路径字符串。对候选用 `rg`、类型/导入图以及相关测试反查消费者；对文件内部符号同时检查再导出和字符串注册。替代方案是安装一个全新死代码扫描依赖并信任其输出；本仓库含多语言与动态装配，单一工具不能覆盖这些入口，且无须为了清理引入持久依赖。

### D3：限定写入边界并分组验证

只修改 Git 跟踪的 `apps/`、`packages/`、`plugins/`、`scripts/` 代码及其直接关联的配置和专属测试；清理这些区域下真正空的源码目录。保留 `packages/back`、两个子模块、`.gitkeep` 所维护的 OpenSpec 结构和所有被忽略的本地构建目录。每组先记录删除理由，再删除并运行对应定向测试；全量验证只在准备提交时按 `AGENTS.md` 执行一次。替代方案是同时清空忽略目录，能释放大量磁盘空间，但用户已明确选择“只删代码”。

## Risks / Trade-offs

- [用户覆盖了较保守的清理建议；动态入口可能无法由静态扫描发现] → 核对清单、插件清单与资源装配路径；删除后做对应构建/运行检查。若需要改变真实公共接口，暂停该项并重新 Battle。
- [跨包代码删除可能影响尚在进行的 OpenSpec 变更] → 对照活跃变更及最近提交；不删除仍被已批准计划明确依赖的代码。
- [测试专属代码可能是重要的回归夹具] → 仅在实现已失效且测试不再证明现行行为时成组删除；保留通用夹具与仍有意义的回归测试。
- [Git 未跟踪的 `.env.local` 和大体积缓存可能被误删] → 删除操作只针对逐项列明的受控源码路径；不执行全仓 `git clean` 或递归清缓存。

## Migration Plan

1. 固定 Git 状态并建立代码入口清单；记录所有候选的引用、入口和保留/删除理由。
2. 按桌面端、运行时、共享包、插件与脚本分组删除无用代码，更新直接关联的配置和测试。
3. 清理这些源码区域中剩下的空目录；核实备份和忽略产物未被触及。
4. 运行定向验证。准备提交时依仓库规范一次性执行全量类型检查、Lint、测试和需要的构建/运行验证；失败时还原对应删除组或修正遗漏引用。

回滚可按提交逐组撤销；本变更不迁移用户数据。
