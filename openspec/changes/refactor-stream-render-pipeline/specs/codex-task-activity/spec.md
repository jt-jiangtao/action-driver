## MODIFIED Requirements

### Requirement: 动态活动任务与有序正文
系统 SHALL 将一个 Turn 呈现为按持久化 cursor 排列的正文片段和动态活动任务，而不是固定工具类别或每次 LLM 调用的卡片。活动任务 MUST 具有稳定 `activityId`，且可混排正文、网页搜索、文件读取、Shell 与文件编辑事件。系统 MUST 对全部实际工具流建立活动任务：Runtime 为连续工作阶段创建受控活动，并在每次实际工具调用前按规则原位修订标题，将该阶段的 `n` 条工具调用及其间正文保序归属到同一活动任务。客户端 MUST 在实时、重连和快照恢复时使用同一活动投影，MUST NOT 将存在工具记录的任务回退为固定工具类别卡，也 MUST NOT 将累计助手正文整体置于活动时间线之前。同一段过程正文的归属 MUST 只被决定一次：客户端 MUST NOT 让同一段文本同时出现在正文与活动归档中，也 MUST NOT 由多个展示组件各自重新推导归属。

#### Scenario: 异构工具属于同一工作目标
- **WHEN** Agent 为同一受控任务摘要依次读取文件、搜索网页并运行命令
- **THEN** 客户端在同一个活动任务中按发生顺序显示这些事件

#### Scenario: 正文位于任务之间
- **WHEN** Runtime 发送没有 `activityId` 的可见正文事件
- **THEN** 客户端在相邻活动任务之间将其呈现为独立正文片段

#### Scenario: 普通工具流缺少显式活动更新
- **WHEN** 模型发起一个或多个外部工具调用且未发送活动更新
- **THEN** Runtime 创建受控兜底活动任务，并将该连续批次的所有工具调用显示为同一任务内的平铺条目

#### Scenario: 从快照重新打开完成任务
- **WHEN** 客户端通过快照恢复包含工具调用的已完成任务
- **THEN** 页面显示原有的活动过程归档和最终结论，而不显示“运行中 / 运行结束”工具类别卡

#### Scenario: 刷新任务页
- **WHEN** 用户在任务页刷新 Renderer
- **THEN** 客户端按当前任务 ID 从 Runtime 恢复任务详情、标题、消息和活动过程，不要求用户再次从侧栏点击任务；最近任务列表加载失败不应阻断详情恢复

#### Scenario: 活动组与工具行展开
- **WHEN** 用户展开包含文件读取、搜索和命令的活动任务
- **THEN** 活动标题箭头紧跟标题，活动与子工具图标及展开面板左边界对齐，工具行的展开箭头位于行尾；文件、搜索、Shell 与 Web Search 使用对应图标

#### Scenario: 完成态用时摘要
- **WHEN** 任务用时超过一分钟
- **THEN** 归档摘要按分钟和秒显示，而不是累计秒数

#### Scenario: 展开 Shell 输入输出
- **WHEN** 用户展开有可解析原始输入输出的 Shell 工具行
- **THEN** 面板以终端形式显示 `$` 命令、输出与退出码，不以 JSON 包装代替终端内容；持久化的原始 I/O 不变

#### Scenario: 过程正文不重复出现在两处
- **WHEN** 某一轮既有活动归档的过程正文，又有包含同一段文本的助手消息
- **THEN** 用户看到的该段文本只出现一次，且其归属在流式增量期间保持稳定，不出现忽隐忽现
