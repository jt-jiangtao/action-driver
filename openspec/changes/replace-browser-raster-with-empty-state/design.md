## Context

参见 proposal.md。`TaskPage` 仅在 `task.browser !== null` 时保留浏览器区域；`BrowserPanel` 依据 `sessionId` 决定是否有真实会话。当前无会话的分栏分支导入酒店截图并覆盖目标高亮，放大分支已使用“开始浏览”空状态。真实内嵌会话由 Electron 视图绘制，外部 Chrome 会话有独立说明。`agent-task-experience` 规范和视觉基准仍记录旧静态网页。

## Goals / Non-Goals

**Goals:** 同一无会话空状态适用于分栏与放大布局；移除无用截图及样式；保持有会话的渲染和现有布局、控制行为。

**Non-Goals:** 不重构 Browser 会话生命周期、IPC、数据契约或任务页整体布局；不把 Mock 任务改为自动启动真实浏览器。

## Decisions

1. **复用现有空状态。** `BrowserPanel` 的无会话分支统一显示“开始浏览”，不再按布局选择截图或空状态；移除截图、目标高亮的渲染及专用样式。Mock 投影中的目标坐标清为 `null`，公共 `BrowserSkillProjection` 契约留待独立变更评估。这样既能删除 1,823,683 字节的资产，又不会把无会话状态误报为真实网页。
2. **保留浏览器区域和原控制。** 用户已裁决保留无会话时的区域，避免在会话建立瞬间改变任务页宽度。替代方案是仅在会话建立后显示整个区域；它能避免空白面板，但会造成任务页布局跳变，并使 Mock 控制状态无法在原位置验收。另一真实可行方案是压缩截图；它保留旧视觉，但继续暗示网页已经加载，已被用户否决。
3. **同步行为测试和视觉基准。** 组件测试断言空状态、无截图/高亮以及真实会话分支；相关任务页截图基准按新状态重建，保留宽度与交互检查。现有 `design/references` 存放 Playwright 基准，更新须仅针对受影响任务页图片。

## Risks / Trade-offs

- [旧 Mock 任务失去酒店网页示例] → 保留标题、URL、Skill 状态与控制条；空状态明确表明尚无真实会话。这是用户选择方案后的已知代价，无 Agent 建议被覆盖。
- [视觉基准与旧 Figma 画板不再一致] → 在本变更中更新 OpenSpec 行为描述及受影响基准，并核对侧栏、Agent 区域、浏览器区域尺寸未变。
- [残留目标坐标可能再被错误展示] → 清理 Mock 投影的目标坐标，并在组件测试中断言无目标高亮。

## Migration Plan

该变更只影响渲染产物。发布时不迁移用户数据；若出现视觉问题，可回退本变更恢复旧渲染与基准。
