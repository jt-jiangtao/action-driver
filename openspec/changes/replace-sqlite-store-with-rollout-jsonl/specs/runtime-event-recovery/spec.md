## MODIFIED Requirements

### Requirement: 请求事件具有连续顺序

系统 MUST 为同一请求的每个持久化事件分配唯一且连续的请求内序号，该序号 SHALL 来自该会话追加式日志的单调序号，并 SHALL 在日志追加成功后才向客户端发布；全局水位 SHALL 仅作为日志定位、投影与重放水位。工具准备进度事件也 MUST 遵守该顺序，不得绕过持久化直接广播。

#### Scenario: 两个请求交错产生事件
- **WHEN** 请求 A 和 B 的事件交替追加
- **THEN** 每个请求从接受到终态的序号分别连续，客户端不会因为另一个请求占用水位而停止显示

#### Scenario: 事件写入失败
- **WHEN** 日志追加事务失败
- **THEN** 请求序号和任务状态均不推进，服务端不广播该事件

#### Scenario: 工具准备事件与执行事件
- **WHEN** 模型先流出工具名，后续完成参数并开始执行
- **THEN** 同一请求中的准备、正式工具及终态事件按日志序号到达，重连回放不重复执行工具

#### Scenario: 页面刷新时请求仍在运行
- **WHEN** 客户端通过任务快照恢复仍在运行的请求
- **THEN** 客户端使用该请求标识和快照水位续订，展示后续事件及最终结果，并保留取消能力，不重复执行或显示已入快照的工具

### Requirement: 重放与快照恢复保持一致

系统 SHALL 从会话追加式日志按序号有界重放已提交事件，并 SHALL 由日志折叠出的投影生成同一高水位的状态快照；客户端 MUST 忽略重复事件，按请求序号连续应用后才推进已应用水位。生图批次位置 MUST 在工具开始时以占位行与助手内容一同追加，并 SHALL 在其图片结果之前进入可重放日志；重放和快照 MUST 保持同一批次、文字与工具组的顺序。

#### Scenario: 重连时遇到乱序和重复事件
- **WHEN** 客户端收到重复帧、乱序帧和其他请求交错的帧
- **THEN** 每个请求的过程文本、工具条目与终态恰好投影一次，顺序与日志折叠结果一致

#### Scenario: 重放范围已过期
- **WHEN** 客户端请求的事件早于服务端保留范围
- **THEN** 客户端以由日志折叠出的一致快照替换旧投影，仅应用快照水位之后的新事件

#### Scenario: 批次开始后断线
- **WHEN** 生图调用已经开始并追加了批次占位，但图片尚未全部完成时客户端断线
- **THEN** 重放或快照恢复同一批次位置与插槽数量，后续图片只更新原索引，重连不重新执行生图调用

#### Scenario: 批次位置持久化失败
- **WHEN** 批次占位行连同其序号分配未能追加
- **THEN** 客户端不收到孤立的批次事件，助手消息与水位均不推进

### Requirement: 异常重启安全结束运行中任务

Runtime MUST 在对外提供服务前，依据日志与投影把无执行者的运行中请求幂等转为中断终态，保留已提交内容与工具记录；MUST NOT 自动重放可能产生副作用的工具。恢复 MUST 只追加终结行，MUST NOT 改写既有历史行。

#### Scenario: 模型输出中途退出
- **WHEN** Runtime 在追加了部分助手内容后退出并重启
- **THEN** 用户仍能看到部分内容和明确失败状态，重复重启不会新增第二个终态

#### Scenario: 工具执行结果未知
- **WHEN** 工具已开始但结果未写入日志时 Runtime 退出
- **THEN** 恢复视图将调用结果显示为未知，系统不自动再次执行该调用

## REMOVED Requirements

### Requirement: 旧事件可安全迁移

**Reason**: 用户已裁决本次持久化改造不做数据迁移，旧运行时库整体废弃，不再承担旧事件的回填、备份与无损恢复承诺。

**Migration**: 删除旧运行时 SQLite 库及其 `-wal`/`-shm` 旁文件；新版从空的 rollout 日志开始，不读取、不转换、不保留旧库记录。
