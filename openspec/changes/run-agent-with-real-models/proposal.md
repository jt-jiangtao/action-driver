## Why

当前 Agent Loop 使用确定性模型，提交目标后得到的是固定的演示流程。模型连接已经可用（服务端持有配置与凭据），下一步需要让 Agent Loop 真正调用用户启用的模型完成规划与结果生成，页面时间线展示真实推理与结果，产品才从"界面演示"变为"可使用"。

## What Changes

- 服务端的模型网关从确定性实现切换为"经模型连接推理"：按任务选择的启用模型发起真实调用，模型连接与凭据只由服务端使用。
- Agent Loop 的规划节点消费真实模型输出，并把决策结果投影为任务步骤；模型失败、超时、限流与能力不足映射为可诊断的任务状态与步骤，不伪造成功。
- 推理只发送完成当前节点所需的上下文（目标、必要历史摘要、可用 Skill 描述），不发送整个会话历史。
- 保留确定性模型作为测试与离线装配，生产（local）装配使用真实模型。
- 页面时间线展示真实步骤与结果；模型选择器选中的模型作为任务的模型选择传入服务端。

## Capabilities

### New Capabilities

- `real-model-generation`: 定义服务端用已配置模型完成真实推理的行为、上下文最小化、失败映射与确定性装配的回退边界。

## Impact

- 服务端：`ModelGateway` 增加真实实现（协议适配复用 `@actiondriver/model-connections`），新增模型选择解析与调用记录。
- Agent Loop：`plan` 节点消费真实输出；失败/超时进入可诊断状态；步骤投影包含模型决策摘要。
- 客户端：模型选择器选中项随任务提交传给服务端；时间线展示真实步骤。
- 测试：真实调用使用本地假服务端或注入传输端口，不访问真实供应商；网络路径使用注入替身。

## Battle Status

- 类型：架构（模型推理接入）+ 产品可见行为（时间线与结果真实化）。
- 状态：**方向已裁决**（真实模型推理由服务端承担、客户端不持有凭据），实现细节待裁决：
  1. 上下文构造：只发送目标与必要的最近消息摘要（推荐），还是附带完整本地历史。
  2. 失败重试：仅对可重试错误（限流、超时、5xx）最多重试 2 次并指数退避（推荐），还是不做自动重试。
  3. 流式输出：本期一次返回完整结果（推荐），流式增量作为后续增强。
  4. 模型选择粒度：任务级选择（提交时确定，推荐），会话级继承。
