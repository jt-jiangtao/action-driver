## Purpose

定义服务端使用已配置模型完成真实推理的行为，使 Agent 任务由真实模型驱动、失败可诊断、上下文最小化，并保留确定性装配用于测试与离线场景。

## ADDED Requirements

### Requirement: 使用已启用模型完成推理
系统 SHALL 让 Agent Loop 通过服务端持有的模型连接发起真实推理，模型连接与凭据 MUST 只在服务端使用；客户端与 Runtime 边界 MUST NOT 接触明文凭据。

#### Scenario: 提交目标触发真实推理
- **WHEN** 用户选择一个已启用模型并提交目标
- **THEN** 服务端使用该模型完成规划推理，并把决策投影为任务步骤

#### Scenario: 未选择模型
- **WHEN** 任务没有可用的启用模型
- **THEN** 系统返回可诊断的不可用结果，不伪造推理结果

#### Scenario: 模型不可用
- **WHEN** 模型请求因认证、限流、超时或服务错误失败
- **THEN** 任务进入可诊断的失败或等待状态，错误分类与模型连接测试使用同一套分类

### Requirement: 最小化推理上下文
系统 SHALL 只发送完成当前推理节点所需的上下文，不得上传完整会话历史或本地文件内容；模型侧 MUST NOT 成为历史的事实来源。

#### Scenario: 规划节点请求模型
- **WHEN** Agent Loop 需要模型输出下一步计划
- **THEN** 请求只包含目标、必要的最近上下文摘要与可用 Skill 描述

#### Scenario: 检查请求载荷
- **WHEN** 开发者检查发往模型的请求
- **THEN** 载荷中不包含完整历史、本地文件内容或凭据

### Requirement: 推理结果驱动任务步骤
系统 SHALL 把真实模型输出投影为任务步骤与结果，并 SHALL 在时间线中展示步骤标题、细节与状态；步骤 MUST 与任务投影使用同一状态来源。

#### Scenario: 规划成功
- **WHEN** 模型返回可执行计划
- **THEN** 任务步骤展示每一步的标题与细节，执行进度按步骤推进

#### Scenario: 规划失败
- **WHEN** 模型返回不可用结果或调用失败
- **THEN** 时间线展示失败步骤与可诊断原因，任务状态为失败而不是成功

### Requirement: 保留确定性装配
系统 SHALL 保留确定性模型装配用于测试、视觉验收与离线开发，并 SHALL 让两条装配对上层暴露同一接口。

#### Scenario: 测试装配
- **WHEN** 测试或视觉用例启动
- **THEN** 推理使用确定性实现，不访问网络与真实凭据

#### Scenario: 切换装配
- **WHEN** 应用从测试装配切换到生产装配
- **THEN** Agent Loop、任务投影与界面代码不变，只替换模型网关实现
