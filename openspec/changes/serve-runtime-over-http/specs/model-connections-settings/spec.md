## MODIFIED Requirements

### Requirement: 展示模型连接设置页
系统 SHALL 提供“模型连接”设置页，并以 Figma 节点 `273:6`、`273:54` 和 `273:90` 为基准呈现有数据、空状态和更多菜单状态。页面 SHALL 通过服务端 HTTP 接口读取真实连接，凭据由服务端持有，页面只展示掩码提示。

#### Scenario: 已有模型集
- **WHEN** 服务端返回一个或多个已保存的模型集
- **THEN** 页面按模型集展示连接名称、协议与地址、模型数量、已启用数量以及每个模型的启用状态

#### Scenario: 没有模型集
- **WHEN** 服务端返回空列表
- **THEN** 页面展示引导式空状态、添加模型集按钮和支持协议入口，不展示伪造的模型集行

#### Scenario: 打开更多菜单
- **WHEN** 用户打开模型集更多菜单
- **THEN** 页面按节点 `273:90` 呈现菜单，并保持卡片、模型行和页面布局稳定

#### Scenario: 服务端不可用
- **WHEN** 页面无法访问服务端接口
- **THEN** 页面展示可诊断的不可用提示并保留添加模型集入口，不展示过期的示例数据

#### Scenario: 页面不持有凭据
- **WHEN** 页面渲染连接卡片与模型行
- **THEN** 页面只显示掩码提示，模板、状态与请求载荷中都不包含明文凭据

### Requirement: 管理模型集
系统 SHALL 允许用户展开或收起模型集、打开更多菜单、刷新模型列表、启用或停用模型，并在确认后删除模型集；这些操作 SHALL 通过服务端 HTTP 接口完成，由服务端写入本地存储。

#### Scenario: 刷新模型
- **WHEN** 用户点击模型集的刷新纯图标按钮
- **THEN** 服务端重新发现模型、保留已启用模型的选择并写回存储，页面展示更新后的列表

#### Scenario: 启用或停用模型
- **WHEN** 用户切换模型的启用状态
- **THEN** 服务端保存新状态，页面同步更新模型集的已启用数量

#### Scenario: 删除模型集
- **WHEN** 用户在更多菜单中选择删除并确认
- **THEN** 服务端移除该模型集及其保存的凭据，并在最后一个模型集被删除后显示空状态

#### Scenario: 取消删除
- **WHEN** 用户在删除确认中取消
- **THEN** 模型集及其展开、启用和测试状态保持不变

#### Scenario: 操作失败
- **WHEN** 刷新、保存启用状态或删除被服务端拒绝或遇到网络错误
- **THEN** 页面保留操作前的可见状态并展示可诊断错误，不显示虚假成功

### Requirement: 添加并验证模型集
系统 SHALL 提供连接配置和选择模型两步流程，并在第一步提供协议选择、名称、接口地址和 API Key 输入；连接测试、模型发现与模型测试 SHALL 由服务端真实发起，页面只提交表单并展示结果，并 SHALL 覆盖 Figma 节点 `273:126`、`273:162`、`273:198`、`273:234` 和 `273:270`。

#### Scenario: 配置连接
- **WHEN** 用户选择协议、填写模型集名称、接口地址和 API Key 并测试连接
- **THEN** 请求经服务端发起真实校验，页面展示连接测试进度与结果，成功后允许进入选择模型步骤

#### Scenario: 凭据只提交一次
- **WHEN** 用户在向导中提交凭据
- **THEN** 凭据只随配置请求发送给服务端，不写入客户端存储，也不出现在页面状态或后续读取结果中

#### Scenario: 发现与手动添加入口
- **WHEN** 用户进入选择模型步骤
- **THEN** 页面展示服务端发现的模型，并提供纯图标的手动添加入口，但 MUST NOT 展示固定的“手动添加模型”行

#### Scenario: 协议没有发现接口
- **WHEN** 用户选择的协议不提供模型发现
- **THEN** 页面展示手动添加模型的入口与说明，不把缺少发现接口当作连接失败

#### Scenario: 未测试状态
- **WHEN** 用户刚进入模型选择步骤
- **THEN** 页面按节点 `273:162` 显示模型选择和未测试状态

#### Scenario: 测试模型状态
- **WHEN** 用户测试发现的模型
- **THEN** 页面先按节点 `273:198` 呈现测试中，再根据服务端返回的真实结果按节点 `273:234` 或 `273:270` 呈现部分失败或全部成功

#### Scenario: 不支持文本的模型
- **WHEN** 某个模型不接受文本请求
- **THEN** 页面把该模型标记为不支持文本，并允许用户按节点 `273:270` 保存其余已成功测试的模型

#### Scenario: 保存模型集
- **WHEN** 至少一个模型测试成功且用户保存
- **THEN** 服务端保存模型集与其凭据到本地存储，页面返回模型集列表页展示新数据

#### Scenario: 步骤间保留数据
- **WHEN** 用户在连接配置和模型选择步骤之间前进或返回
- **THEN** 已填写连接字段、选择的模型和已有测试结果均保持不变

## ADDED Requirements

### Requirement: 为 Agent 提供真实且无歧义的模型选项
系统 SHALL 从服务端持久化的模型连接中投影 Agent 可选模型，并 MUST 使用 `connectionId` 与 `modelId` 的组合标识一次选择；本地生产装配 MUST NOT 注入硬编码默认模型或示例模型作为降级内容。

#### Scenario: 选择可执行的 OpenAI-compatible 模型
- **WHEN** 一个 OpenAI-compatible 连接已启用且其中存在已启用、支持文本的模型
- **THEN** Agent 模型选择器展示该连接与模型，并把 `{ connectionId, modelId }` 作为提交引用

#### Scenario: 两个连接包含同名模型
- **WHEN** 两个连接都包含相同 `modelId`
- **THEN** 页面按连接名称区分选项，选择其中一个不会解析到另一个连接

#### Scenario: Anthropic 尚未接入 Agent 执行
- **WHEN** 已配置可用的 Anthropic-compatible 连接
- **THEN** 连接仍可在设置页管理和测试，但 Agent 模型选择器将其标记为不可选并说明“Agent 调用暂未接入”

#### Scenario: 没有可用模型
- **WHEN** 服务端没有返回任何可用于 Agent 执行的模型
- **THEN** 页面展示配置模型连接的空状态，提交操作不可用且不选择示例模型

#### Scenario: 已选模型不再可用
- **WHEN** 当前选择对应的连接被删除、停用或模型被停用
- **THEN** 页面清除失效选择、阻止提交并要求用户重新选择
