- [ ] 1.2 在服务端内实现 HTTP/WS 监听与就绪状态上报，验证启动后 `GET /health` 返回就绪、未就绪时返回可识别的暂不可用结果。
- [ ] 1.3 实现每次启动生成的访问凭据（随机 token）与校验中间件，验证缺少或错误凭据被拒绝、正确凭据通过，且 token 不出现在日志与错误载荷中。

- [ ] 1.5 实现服务端单实例、异常退出重启与受控关闭，验证多窗口不创建第二个服务端、退出时完成存储收尾且无残留进程。

## 2. HTTP 接口与契约

- [ ] 2.1 定义 HTTP 契约（路径、方法、请求/响应类型、错误码、协议版本头），用契约测试验证类型可往返且未知字段被拒绝。
- [ ] 2.2 实现配置类接口：模型连接列表、创建、删除、启用/停用、发现模型、连接测试、模型测试，验证成功与失败都返回结构化结果。
- [ ] 2.3 实现任务查询接口（按任务读取投影）与版本接口，验证投影与 WebSocket 事件最终一致。
- [ ] 2.4 实现结构化错误模型（参数、授权、版本、超时、上游故障、存储故障），验证客户端可区分可重试与不可重试，且错误内容不含凭据。
- [ ] 2.5 增加请求日志与可观察性，验证日志包含请求标识与结果码、不包含凭据、模型密钥或完整请求载荷中的敏感字段。

## 3. WebSocket 会话协议

- [ ] 3.1 定义 WebSocket 消息契约（握手、命令、响应、事件、反向 Skill 请求与结果、错误），用契约测试验证每条消息可序列化且主版本不一致时拒绝业务消息。
- [ ] 3.2 实现握手与鉴权，验证未授权连接无法提交任务、授权连接获得协商后的能力集合。
- [ ] 3.3 实现会话命令：提交目标、中断、继续、提供用户输入，验证每条命令都有对应响应并按请求标识关联。
- [ ] 3.4 实现事件推送与游标确认，验证从 `cursor + 1` 继续、重复确认不重复应用、迟到事件不覆盖新状态。
- [ ] 3.5 实现单连接多任务多路复用，验证两个任务同时运行时不串线、每个任务的事件只推送给对应订阅。
- [ ] 3.6 实现断线重连与页面重载恢复，验证连接中断后客户端按最后确认游标补齐事件并得到与断线前一致的可见状态。
- [ ] 3.7 实现心跳与连接健康检查，验证半开连接被识别并触发重连，且重连期间命令返回可诊断结果而不是静默丢失。

## 4. 反向 Skill 调用

- [ ] 4.2 在服务端实现反向调用客户端（经会话连接下发请求并等待结果），验证成功、超时、取消与迟到响应四类路径。
- [ ] 4.3 在 Main 实现反向调用执行方（收到请求后调用 Browser/Computer Provider 并回传结果），验证 Provider 缺失时返回可诊断的能力不可用错误。
