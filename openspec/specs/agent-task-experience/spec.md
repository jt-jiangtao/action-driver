# agent-task-experience Specification

## Purpose

定义普通用户从首页描述目标到查看任务执行状态的完整界面体验，并覆盖对话、时间线、输入框以及浏览器面板的全部已绘制布局状态。

## Requirements

### Requirement: 呈现 Agent 优先首页
系统 SHALL 按 Figma 节点 `60:5` 呈现首页，并支持节点 `202:750` 的模型选择状态；首页包括居中的品牌标志、标题、说明文字和底部输入框。模型选择器 SHALL 允许选择已启用的聊天候选，即使该模型尚未测试或测试失败；选择时 SHALL 不显示测试提醒。

#### Scenario: 查看空白首页
- **WHEN** 用户进入首页且尚未提交目标
- **THEN** 页面显示“我们应该在 Action-Driver 中做些什么？”以及包含加号、模型触发器和发送按钮的输入框

#### Scenario: 在首页选择模型
- **WHEN** 用户打开模型触发器
- **THEN** 页面按节点 `202:750` 显示连接分组、展开状态、模型列表与当前选择，并在选择后关闭菜单和更新触发器文案

#### Scenario: 选择未测试模型并发送
- **WHEN** 用户选择已启用、未测试的聊天候选并发送文字或图片
- **THEN** 选择器不显示测试提示，任务接收用户消息并尝试实际模型调用；调用失败在该轮对话中展示

### Requirement: 使用富文本输入框
系统 SHALL 使用 Slate.js 提供输入能力，并保持 Figma 中的自定义 Codex 风格视觉，不套用 Ant Design 输入框外观；输入框 SHALL 复用同一模型选择器组件，并提供图片选择、粘贴、预览与移除能力。

#### Scenario: 提交非空目标
- **WHEN** 用户输入目标并点击发送按钮
- **THEN** Mock Agent 会话被创建，系统进入任务页并显示相应的用户消息和执行状态

#### Scenario: 仅图片输入
- **WHEN** 用户没有输入文字但添加了有效图片
- **THEN** 发送按钮可用，提交后用户消息展示图片

#### Scenario: 执行中的输入框
- **WHEN** Mock Agent 处于运行状态
- **THEN** 发送按钮替换为圆形中断按钮，按钮内部显示白色停止方块

#### Scenario: 任务中切换模型
- **WHEN** 用户在任务输入框打开并选择另一个已启用模型
- **THEN** 输入内容与已选图片保持不变，模型触发器更新，当前任务的其余 Mock 状态不被重置

### Requirement: 呈现默认任务工作区
系统 SHALL 按 Figma 节点 `60:7` 呈现 248px 侧栏、536px Agent 面板和 656px 浏览器占位面板，三个区域不得重叠；模型选择状态 SHALL 按节点 `202:1337` 呈现。

#### Scenario: 查看运行中的任务
- **WHEN** 用户打开任一运行中的 Mock 任务
- **THEN** Agent 面板显示该任务的标题、对话、执行进度和输入框，浏览器区域显示对应静态网页栅格、当前目标高亮及浮动控制条

#### Scenario: 打开任务模型选择器
- **WHEN** 用户在默认任务工作区打开模型触发器
- **THEN** 模型菜单覆盖在输入框上方且不改变 Agent 与浏览器面板的宽度

### Requirement: 呈现执行时间线
系统 SHALL 使用 Ant Design Timeline 表达执行进度，并保持时间线宽度与当前对话流宽度一致。

#### Scenario: 显示四步执行状态
- **WHEN** Mock 任务包含已完成、当前和等待步骤
- **THEN** 时间线按竖直顺序展示四步、`3 / 4` 进度、对应状态圆点和当前步骤背景

### Requirement: 切换任务页布局状态
系统 SHALL 支持 Figma 中的默认分栏、浏览器放大和浏览器折叠三种视觉状态，且尺寸切换按钮仅替换图标，不改变按钮背景和边框。

#### Scenario: 放大浏览器占位面板
- **WHEN** 用户在默认分栏状态点击浏览器放大按钮
- **THEN** 页面切换到节点 `111:247` 的浏览器放大布局，侧栏保留，Agent 面板隐藏

#### Scenario: 折叠浏览器占位面板
- **WHEN** 用户点击浏览器折叠按钮
- **THEN** 页面切换到节点 `112:409` 的浏览器折叠布局，Agent 对话区扩展到剩余宽度

#### Scenario: 恢复默认分栏
- **WHEN** 用户从浏览器放大或折叠状态点击对应的恢复图标
- **THEN** 页面恢复默认分栏布局，并保留当前 Mock 会话状态

### Requirement: 表达 Browser Skill 控制状态
系统 SHALL 在浏览器占位面板的浮动控制条中表达运行、暂停和人工接管状态，但本阶段 MUST NOT 驱动真实网页。

#### Scenario: 暂停 Mock Browser Skill
- **WHEN** 用户点击暂停
- **THEN** 控制条切换为暂停状态并提供继续操作，页面栅格保持不变

#### Scenario: 人工接管 Mock Browser Skill
- **WHEN** 用户点击人工接管
- **THEN** 控制条切换为人工接管状态并提供继续 Agent 操作，页面栅格保持不变

### Requirement: 使用本地 Mock 数据
系统 SHALL 使用确定性的本地 Mock 数据提供多个最近任务及各自的对话、执行步骤、Skill 状态、浏览器占位内容和模型选择状态，且刷新应用后仍可复现设计验收场景。

#### Scenario: 无后端运行
- **WHEN** 本地 Agent Runtime、SQLite 和真实浏览器能力均未启动
- **THEN** 首页和任务页仍可完整展示和切换所有已绘制状态

#### Scenario: 切换最近任务
- **WHEN** 用户依次打开两个不同的最近任务
- **THEN** 标题和投影内容随 task ID 确定性切换，两个任务共享页面组件但不共享错误的显示数据

### Requirement: 任务页按生成状态呈现过程
系统 SHALL 在任务页按生成中和生成结束呈现不同过程视图；运行中的活动任务和工具 SHALL 提供扫光反馈，并遵循 reduced-motion 偏好。生图过程 SHALL 显示工具状态，生成图片 SHALL 出现在助手消息中。

#### Scenario: 无工具的初始生成
- **WHEN** Turn 运行且尚无正文或活动任务
- **THEN** 用户看到“正在思考”尾部状态和扫光反馈

#### Scenario: 活动任务标题更新
- **WHEN** 正在展开的活动任务收到有效的新标题
- **THEN** 任务在原位改名且保持展开状态和已显示的子项

#### Scenario: 生图完成
- **WHEN** 当前轮生图工具完成并且助手生成结束
- **THEN** 工具过程可在活动任务中查看，图片显示在最终助手消息中，而不是只显示图片地址或原始 JSON

### Requirement: 工具自动执行期间输入区保持可用
系统 SHALL 在已授权工具自动执行时继续呈现任务过程和输入框，不得显示要求用户允许或拒绝的工具审批控件。

#### Scenario: Shell 和 Web Search 正在自动执行
- **WHEN** 工具由 Runtime 直接排队或运行
- **THEN** 用户看到关联活动中的工具行和正常输入区，不需要点击允许一次或拒绝

#### Scenario: 查看旧审批历史
- **WHEN** 用户打开包含历史 `waiting_approval` 事件的已完成任务
- **THEN** 页面可回看原工具过程，但不显示可操作的审批按钮

### Requirement: 流式输出期间只重渲染变化的内容
系统 SHALL 在模型流式输出期间只重新渲染发生变化的消息、文本块、工具行与活动组；未变化的历史消息与历史轮次 MUST NOT 因新的流式增量而重新渲染或重新执行 Markdown 渲染。同一条正在流式生成的助手消息 MUST 只重新解析正在增长的文本块，已闭合的文本块 MUST 复用其既有渲染结果，且分块渲染的输出 MUST 与整段渲染一致。历史轮次的派生视图（分组、去重、可见性过滤）MUST 在一次流式输出中保持不重新计算，因此历史数据 MUST 以稳定引用提供。流式更新 MUST NOT 引起侧边栏、首页与输入区重新渲染。任务快照 SHALL 为不可变数据，分发路径 MUST NOT 修改已发出的快照。

#### Scenario: 长对话中流式输出
- **WHEN** 任务已有 100 条历史消息，最后一条助手消息持续收到文本增量
- **THEN** 只有最后一条消息重新渲染，历史消息的渲染次数不变，历史轮次的派生视图不重新计算

#### Scenario: 长回答的块级增量渲染
- **WHEN** 助手消息已包含多个由空行分隔的文本块，最后一块继续收到增量
- **THEN** 只有最后一块重新解析与更新 DOM，已闭合块的渲染结果被复用，且该消息的最终可见 Markdown 与一次性整段渲染一致

#### Scenario: 边界语法不被拆坏
- **WHEN** 回答包含跨空行的列表、引用、围栏代码块、表格或缩进代码
- **THEN** 分块渲染结果与整段渲染逐字一致，列表不会因分块变成多个列表，代码块内容不被截断

#### Scenario: 流式更新不影响应用外壳
- **WHEN** 当前任务收到流式更新
- **THEN** 侧边栏、应用外壳与输入区不重新渲染，任务页正确显示最新内容

#### Scenario: 已发出的快照保持不变
- **WHEN** 投影在发出快照后继续处理后续事件，包括审批请求与审批结果事件
- **THEN** 此前发出的快照内容保持不变，新快照中未变化的部分与旧快照共享同一引用

### Requirement: 图片预览支持缩放、变换与组内切换
系统 SHALL 为对话中的图片、输入框中的待发送图片与任务交付的图片提供同一种预览：用户 SHALL 能缩放、拖动、左右旋转、水平与垂直翻转当前图片，能用按钮或方向键在同一组图片之间切换，能保存当前图片，并能用关闭按钮或 Esc 退出预览。同一次生成调用、同一条用户消息、全部待发送图片、同一任务的图片成品各为一组；预览 MUST NOT 切换到其他组的图片。

#### Scenario: 放大查看生成图细节
- **WHEN** 用户点击一张生成图的缩略图
- **THEN** 预览打开并显示该图片，用户可缩放、拖动、旋转与翻转

#### Scenario: 在同一批生成图之间切换
- **WHEN** 一次生成调用产出多张图片，用户在预览中按右方向键
- **THEN** 预览切换到同一批的下一张图片，且不会切换到其他生成调用的图片

#### Scenario: 保存与关闭
- **WHEN** 用户在预览中点击保存，或按 Esc
- **THEN** 保存的是当前显示的图片；按 Esc 后预览关闭，缩略图保持原样

### Requirement: 任务页分离正文与内联工具活动
系统 SHALL 在任务页对话视口中显示内联工具活动区，同时保持用户消息与最终 Assistant Markdown 的既有顺序和正文边界。活动区 MUST 适配 Agent-only、分栏和浏览器折叠布局，且不替换任务中断或模型选择控件。

#### Scenario: 查看执行中的任务
- **WHEN** 用户打开存在运行中工具调用的任务
- **THEN** 对话视口显示展开的当前工具活动卡、可访问的其他活动卡及原有消息正文

#### Scenario: 重新打开已完成任务
- **WHEN** 用户重新打开包含终态工具调用的任务
- **THEN** 工具卡以完成区默认折叠状态恢复，助手最终 Markdown 不包含工具进度或原始输出

### Requirement: 展示归属与顺序由单一决策点确定
任务页当前轮次的正文块、过程文本、工具活动、图片画廊、审批卡片、交付文件与失败提示的归属和顺序 SHALL 由一个纯决策点统一确定；展示组件 MUST NOT 各自重复推导同一归属（例如图片批次锚定、过程文本去重、可见性过滤）。活动区 SHALL 只拥有被 Runtime 以 `phase: process` 关闭的过程叙述；未关闭（`pending`）与结束（`final`）的文本 MUST 只出现在正文中，因此同一段文本 MUST NOT 因缺少顺序信息而在活动区再被镜像一次。该决策 MUST 可在不渲染界面的情况下被单元测试覆盖。

#### Scenario: 生图画廊固定在调用位置
- **WHEN** 同一轮先有过程正文、随后有多个生图调用、最后有最终回复
- **THEN** 每个批次画廊固定在其调用位置、按输入索引排列，正文不把画廊挤到别处，重载后顺序不变

#### Scenario: 过程文本只出现一次
- **WHEN** 过程文本同时存在于助手消息与活动区（活动通道领先正文一个增量，或转录缺少顺序信息）
- **THEN** 已关闭的过程叙述只出现在活动归档，未关闭与结束的文本只出现在正文，该文本在页面上只出现一次且不会在每次增量时闪烁地出现又消失

#### Scenario: 失败轮次只保留可交付内容
- **WHEN** 任务失败
- **THEN** 该轮助手消息只保留图片与工具等非文本内容，并显示失败提示，不重复展示已归档的过程文本

#### Scenario: 决策点可被单元测试覆盖
- **WHEN** 开发者针对同一任务快照调用该决策点
- **THEN** 返回的块序列包含稳定的标识与种类，且不依赖任何界面组件
