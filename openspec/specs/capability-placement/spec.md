# capability-placement Specification

## Purpose
为插件能力定义可声明、可验证的运行位置契约，使 UI、本地工作区和远程或云端宿主能够按设备、数据与授权要求选择执行位置，并在取消、断连、恢复及升级期间保持调用归属和结果可信。

## Requirements

### Requirement: 声明运行环境与能力需求

插件或能力 SHALL 声明支持的 UI、本地工作区、远程/云端宿主位置、位置偏好、所需设备/工作区能力及协议版本。宿主 SHALL 在激活前验证声明与实际环境、安装位置及权限；缺失要求时 MUST 明确不可用，不得以不同位置的近似能力静默替代。

#### Scenario: Computer 能力缺少本机设备
- **WHEN** 一个只能访问本机屏幕的能力被请求放到没有屏幕权限的云端宿主
- **THEN** 宿主拒绝激活并说明缺失的设备能力，不在云端假装可用

#### Scenario: 多位置插件选择
- **WHEN** 同一插件兼容 UI 与本地工作区宿主，且两者都可用
- **THEN** 系统按声明偏好与调用者上下文确定唯一宿主，并记录实际位置

### Requirement: 宿主选择保持工具身份与授权

每次能力调用 SHALL 固定目标宿主、插件版本和实例，继续使用 `local/cloud` 工具 ID 与相应 grants；选择位置 MUST NOT 将 local 授权转换为 cloud 授权，或把任务来源、会话上下文和权限检查交给不受信任的调用输入。

#### Scenario: 仅有本地授权
- **WHEN** 任务只被授予 `tools/local/...` 而请求云端同名能力
- **THEN** 云端调用被拒绝，系统不复用本地授权或回落到本机执行

#### Scenario: 调用期间位置变化
- **WHEN** 已开始调用的远程宿主在执行期间失效而本地宿主可用
- **THEN** 该调用仍绑定原远程实例并标记真实结果，不自动在本地重复执行

### Requirement: 跨宿主调用与取消

系统 SHALL 在选定宿主建立有界、可取消的调用通道，传递最小必要的任务上下文和资源引用，并将取消、期限与停用传播至目标宿主。宿主 SHALL 在确认实际终态后发布成功、失败或取消；未确认的副作用 MUST 标记结果未知。

#### Scenario: 取消远程工具
- **WHEN** 用户取消正在远程宿主执行的工具
- **THEN** 取消请求传至该宿主，系统依据其确认的终态记录结果，不把发送取消等同于已取消

#### Scenario: 远程连接断开
- **WHEN** 远程副作用调用开始后连接中断且没有最终确认
- **THEN** 调用显示结果未知，系统不自动重试或在另一宿主重放

### Requirement: 宿主发现、恢复与升级

系统 SHALL 发现可用宿主并以版本化握手验证协议和能力。断连 SHALL 撤回新调用入口；重连 SHALL 重新验证实例、授权及资源可用性后恢复发现，旧实例迟到结果 MUST NOT 覆盖新实例。升级 SHALL 固定在途调用的原版本并避免同一贡献双重发布。

#### Scenario: 宿主重连
- **WHEN** 远程宿主断线后以新实例重连
- **THEN** 新调用只在握手和授权重新验证后恢复，旧实例迟到消息被拒绝

#### Scenario: 升级时仍有调用
- **WHEN** 目标宿主升级插件且旧实例仍有在途调用
- **THEN** 旧调用保持原实例归属，新版本贡献不与旧版本同时对外发布

### Requirement: 跨位置数据与凭据边界

系统 MUST 只向目标宿主提供该调用获授权的任务上下文、资源操作和凭据代理能力，并记录宿主位置与调用归属。UI 宿主 MUST NOT 因位置选择获得原始 Node、Electron、数据库或任意 IPC 权限；远程宿主 MUST NOT 通过资源 URI 绕过会话隔离或下载未授权本地文件。

#### Scenario: 远程宿主请求其他会话输入
- **WHEN** 远程插件持有其他会话输入的 URI 并请求读取
- **THEN** 资源宿主拒绝请求，内容和私有元数据均不发送到远程宿主

#### Scenario: UI 插件请求原始桌面 API
- **WHEN** 运行在 UI 位置的插件请求未声明的 Electron IPC 操作
- **THEN** 宿主拒绝并记录诊断，不扩大页面权限
