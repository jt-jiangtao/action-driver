# codex-task-activity Specification

## Purpose

定义本地 Runtime Agent 的 Codex 风格活动时间线：运行中可检查正文、动态任务和原始 I/O，结束后过程可折叠回看而结论保持清晰。

## Requirements

### Requirement: 动态活动任务与有序正文

系统 SHALL 把一个 Turn 呈现为按会话追加式日志序号排列的可见块序列，而不是固定工具类别或每次 LLM 调用的卡片。可见块 MUST 包括过程正文、工具组、图片批次占位、图片与文档；每块 MUST 只有一次分配的序号。系统 MUST 对全部实际工具流建立工具组：Runtime 在工具执行前创建受控工具组、按规则确定其受控标题，并把连续工具调用及其间正文保序归属到同一组。客户端 MUST 在实时、重连和快照恢复时使用同一「折叠日志」结果，MUST NOT 另设一套顺序来源，MUST NOT 将存在工具记录的组回退为固定工具类别卡，也 MUST NOT 将累计助手正文整体置于活动时间线之前。

工具组 MUST 在遇到任意可见块时结束：除过程正文外，图片批次、图片与文档同样是边界；被边界隔开的工具调用 MUST 归入新组，没有被任何可见块隔开的连续或同轮并行工具调用 MUST 归入同一组。同一段过程正文的归属 MUST 只被决定一次：客户端 MUST NOT 让同一段文本同时出现在正文与活动归档中，也 MUST NOT 由多个展示组件各自重新推导归属。工具组与其子工具的占位和状态 MUST 来自日志折​叠，重开后位置 MUST 不变。

#### Scenario: 异构工具属于同一工作目标
- **WHEN** Agent 为同一受控任务摘要依次读取文件、搜索网页并运行命令
- **THEN** 客户端在同一个工具组中按发生顺序显示这些事件

#### Scenario: 正文位于任务之间
- **WHEN** Runtime 记录没有工具归属的可见正文
- **THEN** 客户端在相邻工具组之间将其呈现为独立正文片段

#### Scenario: 生成图片后的工具归入新组
- **WHEN** 生图批次与图片已作为可见块出现，其后又执行工具
- **THEN** 该工具进入新的工具组，不并入生图所在的工具组

#### Scenario: 同轮并行工具归入同组
- **WHEN** 同一轮模型返回多个工具调用，且其间没有可见块
- **THEN** 这些调用归入同一工具组，并按调用顺序稳定排列

#### Scenario: 普通工具流缺少显式活动更新
- **WHEN** 模型发起一个或多个外部工具调用且未提供受控组标题
- **THEN** Runtime 创建受控兜底工具组，并将该连续批次的所有工具调用显示为同一组内的平铺条目

#### Scenario: 从快照重新打开完成任务
- **WHEN** 客户端通过快照恢复包含工具调用的已完成任务
- **THEN** 页面显示原有的过程归档和最终结论，而不显示“运行中 / 运行结束”工具类别卡

#### Scenario: 刷新任务页
- **WHEN** 用户在任务页刷新 Renderer
- **THEN** 客户端按当前任务 ID 从日志折叠结果恢复任务详情、标题、消息和活动过程，不要求用户再次从侧栏点击任务；最近任务列表加载失败不应阻断详情恢复

#### Scenario: 活动组与工具行展开
- **WHEN** 用户展开包含文件读取、搜索和命令的活动任务
- **THEN** 活动标题箭头紧跟标题，活动与子工具图标及展开面板左边界对齐，工具行的展开箭头位于行尾；文件、搜索、Shell 与 Web Search 使用对应图标

#### Scenario: 完成态用时摘要
- **WHEN** 任务用时超过一分钟
- **THEN** 归档摘要按分钟和秒显示，而不是累计秒数

#### Scenario: 展开 Shell 输入输出
- **WHEN** 用户展开有可解析原始输入输出的 Shell 工具行
- **THEN** 面板以终端形式显示 `$` 命令、输出与退出码，不以 JSON 包装代替终端内容；持久化的原始 I/O 不变

#### Scenario: 过程正文不重复出现在两处
- **WHEN** 某一轮既有活动归档的过程正文，又有包含同一段文本的助手消息
- **THEN** 用户看到的该段文本只出现一次，且其归属在流式增量期间保持稳定，不出现忽隐忽现

### Requirement: 活动任务标题可修订
系统 MUST 允许 Agent Graph 为活动任务提供面向用户的受控摘要，并以稳定 `activityId` 和单调递增的 `titleRevision` 更新标题；该摘要 MUST NOT 是原始思维链。

#### Scenario: 任务标题随进展更新
- **WHEN** Runtime 为已存在的活动任务发送更高 `titleRevision` 的标题更新
- **THEN** 客户端原位更新同一任务标题，保留时间线位置、子项和展开状态

#### Scenario: 收到过时标题更新
- **WHEN** 客户端收到不高于当前版本的标题更新
- **THEN** 客户端忽略该更新

### Requirement: “正在思考”尾部状态
系统 SHALL 在初始生成、活动任务结束后等待下一次模型输出、或工具结果返回后等待模型续跑时，在活动时间线末尾显示“正在思考”状态行。若模型正在生成可识别的工具调用，状态行 SHALL 改为显示工具名和准备状态。该状态行不是活动任务，也 MUST NOT 在 Turn 完成后作为历史项保留。

#### Scenario: 任务间隙
- **WHEN** 上一个活动任务已经结束且尚未收到新的正文、活动任务或最终结论
- **THEN** 用户看到带低强度扫光的“正在思考”状态行

#### Scenario: 工具参数尚未完整
- **WHEN** 模型流已给出 `shell_run` 等可识别工具名但尚未结束该响应
- **THEN** 尾部状态显示“正在准备”及该工具名，不展示原始参数片段，也不创建空活动任务

#### Scenario: 准备状态结束
- **WHEN** 工具开始正式执行、模型改为输出正文、任务失败或任务取消
- **THEN** 准备状态消失或被当前运行状态替换，完成任务的归档不保留准备状态行

### Requirement: 结束后归档过程
系统 SHALL 在生成结束后将完整过程收进“用时 N 秒”折叠记录，并将最终结论和产物显示在其后。

#### Scenario: 查看完成任务
- **WHEN** 任务完成
- **THEN** 过程默认折叠且结论和文件变更卡保持可见

### Requirement: 本地原始 I/O 模式
系统 MUST 在本地 Runtime 链路显示工具和脚本的原始输入输出，而不得以 `NODE_ENV` 改变该行为，并 SHALL 保留可展开的记录边界。

#### Scenario: 查看 Shell 输出
- **WHEN** 用户展开 Shell 记录
- **THEN** 系统显示原始命令和输出

### Requirement: 展开的活动组限制高度
系统 SHALL 为展开的活动任务组设置随视口高度收缩的最大展示高度。内容超出时 MUST 在该组内部滚动，活动标题及展开操作 MUST 保持可见；内容未超出时 MUST 不出现无意义的空白或滚动条。运行中与已完成任务的历史归档 MUST 采用相同规则。

#### Scenario: 大量工具行
- **WHEN** 一个活动组包含超过可见高度的工具行，用户展开该组
- **THEN** 组内容在自身区域滚动，标题仍可见，页面后续回复不会被整组无限推远

#### Scenario: 少量工具行
- **WHEN** 活动组内容短于最大高度
- **THEN** 组高度跟随内容，不出现额外空白或滚动条

### Requirement: 可滚动活动组的底部渐隐提示
系统 SHALL 在活动组仍有内容可向下滚动时，于内容区域底部显示柔和渐隐，提示下方仍有内容。内容未溢出或已滚动到底时 MUST 不显示渐隐，且渐隐 MUST 不遮挡活动标题或阻止内容滚动。

#### Scenario: 长组继续向下滚动
- **WHEN** 活动组内容超出最大高度，且当前尚未滚动到底
- **THEN** 内容区域底部有渐隐提示，用户仍可正常滚动及操作工具行

#### Scenario: 短组或长组已滚动到底
- **WHEN** 活动组内容没有溢出，或用户已将长组滚动到底
- **THEN** 内容区域底部没有渐隐提示

### Requirement: 内联脚本直接展示源码
系统 SHALL 在 Shell、Python、Node.js 和 TypeScript 工具的输入为内联脚本时，直接展示脚本源码，不在源码前添加执行器名称、命令提示符或表示标准输入的 `-`。系统 MUST 继续显示实际输出、截断提示、退出码和错误状态；对于旧式命令输入，MUST 继续展示实际命令而非把命令改写为源码。持久化原始输入输出 MUST 保持不变。

#### Scenario: 展开四类脚本
- **WHEN** 用户展开任一类脚本工具，其原始输入包含内联 `script`
- **THEN** 面板从脚本第一行开始显示源码，不出现 `$ zsh -`、`$ python3 -`、`$ node -` 或 TypeScript 执行器前缀，输出与退出码仍在源码之后

#### Scenario: 展开旧式 Shell 命令
- **WHEN** 用户展开使用 `command` 与参数的 Shell 工具
- **THEN** 面板仍显示实际执行的命令、输出与退出码，不显示原始 JSON 包装
