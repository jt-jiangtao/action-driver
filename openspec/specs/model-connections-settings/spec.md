# model-connections-settings Specification

## Purpose

定义用户在 ActionDriver 设置中发现、验证、添加、启用和维护模型连接的完整可见行为，并确保各种测试与空状态都有一致、可恢复的反馈。

## Requirements

### Requirement: 展示模型连接设置页
系统 SHALL 提供“模型连接”设置页，并以 Figma 节点 `273:6`、`273:54` 和 `273:90` 为基准呈现有数据、空状态和更多菜单状态。

#### Scenario: 已有模型集
- **WHEN** Mock 数据返回一个或多个模型集
- **THEN** 页面按模型集展示连接名称、协议与地址、模型数量、已启用数量以及每个模型的启用状态

#### Scenario: 没有模型集
- **WHEN** Mock 数据返回空列表
- **THEN** 页面展示引导式空状态、添加模型集按钮和支持协议入口，不展示伪造的模型集行

#### Scenario: 打开更多菜单
- **WHEN** 用户打开模型集更多菜单
- **THEN** 页面按节点 `273:90` 呈现菜单，并保持卡片、模型行和页面布局稳定

### Requirement: 管理模型集
系统 SHALL 允许用户展开或收起模型集、打开更多菜单、刷新模型列表、启用或停用模型，并在确认后删除模型集。

#### Scenario: 刷新模型
- **WHEN** 用户点击模型集的刷新纯图标按钮
- **THEN** 系统通过 Mock 接口重新发现模型并更新该模型集列表

#### Scenario: 启用或停用模型
- **WHEN** 用户切换模型的启用状态
- **THEN** 系统通过 Mock 接口保存新状态，并同步更新模型集的已启用数量

#### Scenario: 删除模型集
- **WHEN** 用户在更多菜单中选择删除并确认
- **THEN** 系统通过 Mock 接口移除模型集，并在最后一个模型集被删除后显示空状态

#### Scenario: 取消删除
- **WHEN** 用户在删除确认中取消
- **THEN** 模型集及其展开、启用和测试状态保持不变

### Requirement: 添加并验证模型集
系统 SHALL 提供连接配置和选择模型两步流程，并通过 Mock 接口支持发现模型、测试连接和测试单个模型；流程 SHALL 覆盖 Figma 节点 `273:126`、`273:162`、`273:198`、`273:234` 和 `273:270`。

#### Scenario: 配置连接
- **WHEN** 用户填写模型集名称、接口地址和 API Key 并测试连接
- **THEN** 系统展示连接测试进度与结果，成功后允许进入选择模型步骤

#### Scenario: 发现与手动添加入口
- **WHEN** 用户进入选择模型步骤
- **THEN** 系统展示发现的模型，并提供纯图标的手动添加入口，但 MUST NOT 展示固定的“手动添加模型”行

#### Scenario: 未测试状态
- **WHEN** 用户刚进入模型选择步骤
- **THEN** 页面按节点 `273:162` 显示模型选择和未测试状态

#### Scenario: 测试模型状态
- **WHEN** 用户测试发现的模型
- **THEN** 页面先按节点 `273:198` 呈现测试中，再根据确定性 Mock 结果按节点 `273:234` 或 `273:270` 呈现部分失败或全部成功

#### Scenario: 保存模型集
- **WHEN** 至少一个模型测试成功且用户保存
- **THEN** 系统通过 Mock 接口添加模型集，并返回模型集列表页展示新数据

#### Scenario: 步骤间保留数据
- **WHEN** 用户在连接配置和模型选择步骤之间前进或返回
- **THEN** 已填写连接字段、选择的模型和已有测试结果均保持不变

### Requirement: 遵循操作与状态视觉语义
系统 SHALL 使用清晰区分连接/网关、模型与新增动作的匹配图标，并遵循已确认的按钮、图标前景色和状态样式约束。

#### Scenario: 图标和按钮样式
- **WHEN** 页面展示模型集、连接选择器、空状态、手动添加、刷新或模型测试操作
- **THEN** 连接/网关使用网络或连接语义图标，模型使用模型语义图标，新增使用 Plus；手动添加、刷新和测试模型为无边框纯图标按钮，文字按钮有边框

#### Scenario: 主按钮图标颜色
- **WHEN** 添加模型集按钮处于默认、hover、pressed、focus、loading 或 disabled 状态
- **THEN** Plus 图标颜色与同状态按钮文字颜色一致

#### Scenario: 状态和测试结果
- **WHEN** 页面展示模型测试状态与结果
- **THEN** 状态使用图标与文字同色的胶囊，且测试结果 MUST NOT 额外显示汇总行

### Requirement: 配置图片相关模型能力
系统 SHALL 在现有模型连接列表的模型行提供图片输入和图片生成能力开关，并允许用户从已开启图片生成能力的模型中指定一个全局默认生图模型。图片生成模型 SHALL 可单独选择 `Images API` 或 `Token Plan` 接口；选择接口不改变该连接的聊天协议。能力开关是用户配置，不得根据模型名称自动选择默认模型，也不得在刷新列表时逐个发起生图请求。系统 SHALL 允许保存仅用于生图的模型，而不要求该模型通过聊天补全测试。未配置默认生图模型时，生图工具不可用。

#### Scenario: 选择视觉聊天模型
- **WHEN** 用户在模型行打开图片输入能力开关
- **THEN** 该模型可用于含图片的对话，普通文字对话行为保持不变

#### Scenario: 配置默认生图模型
- **WHEN** 用户在已保存模型行打开图片生成开关，并将其设为默认生图模型
- **THEN** 系统保存该选择，之后的生图工具调用使用该模型，当前聊天模型选择不改变

#### Scenario: 为模型选择生图接口
- **WHEN** 用户在已启用生图的模型行选择 `Token Plan` 或 `Images API` 接口
- **THEN** 系统保存该模型的选择，重开设置页和刷新模型列表后保持，并仅用所选接口发起该模型的生图请求

#### Scenario: 迁移已有生图配置
- **WHEN** 应用读取升级前已启用图片生成的模型
- **THEN** 该模型默认沿用 `Images API` 接口，原有能力开关和默认模型引用保持不变

#### Scenario: 添加仅支持生图的连接
- **WHEN** 用户手动添加只支持 Images API 兼容端点的模型
- **THEN** 系统允许将它保存到模型连接列表并打开图片生成开关，不要求其通过聊天补全测试

#### Scenario: 默认生图模型被关闭或删除
- **WHEN** 用户关闭默认模型的图片生成开关、停用该模型，或删除其模型连接
- **THEN** 系统清除默认选择并显示未配置状态，Agent 不把生图工具暴露为可用能力

#### Scenario: 提供方不支持生图请求
- **WHEN** 用户启用图片生成开关的模型实际不支持所选生图接口
- **THEN** 生图调用以明确错误结束，图片不显示为成功，设置页保留用户选择以便修改
