# model-connections-settings Specification

## Purpose

定义用户在 Action-Driver 设置中发现、验证、添加、启用和维护模型连接的完整可见行为，并确保各种测试与空状态都有一致、可恢复的反馈。

## Requirements

### Requirement: 展示模型连接设置页
系统 SHALL 提供“模型连接”设置页，并以 Figma 节点 `273:6`、`273:54` 和 `273:90` 为基准呈现有数据、空状态和更多菜单状态。页面 SHALL 展示 Main 进程保存的真实连接，而不是内置的示例数据。

#### Scenario: 已有模型集
- **WHEN** 应用返回一个或多个已保存的模型集
- **THEN** 页面按模型集展示连接名称、协议与地址、模型数量、已启用数量以及每个模型的启用状态

#### Scenario: 没有模型集
- **WHEN** 应用返回空列表
- **THEN** 页面展示引导式空状态、添加模型集按钮和支持协议入口，不展示伪造的模型集行

#### Scenario: 打开更多菜单
- **WHEN** 用户打开模型集更多菜单
- **THEN** 页面按节点 `273:90` 呈现菜单，并保持卡片、模型行和页面布局稳定

#### Scenario: 读取连接失败
- **WHEN** 应用无法读取已保存的连接
- **THEN** 页面展示可诊断的错误提示，并保留添加模型集入口，不显示过期的示例数据

### Requirement: 管理模型集
系统 SHALL 允许用户展开或收起模型集、打开更多菜单、刷新模型列表、启用或停用模型，并在确认后删除模型集；这些操作 SHALL 通过 Main 进程的模型连接能力完成并持久化结果。

#### Scenario: 刷新模型
- **WHEN** 用户点击模型集的刷新纯图标按钮
- **THEN** 系统通过真实端点重新发现模型，保留已启用模型的选择，并更新该模型集列表

#### Scenario: 启用或停用模型
- **WHEN** 用户切换模型的启用状态
- **THEN** 系统通过模型连接能力保存新状态，并同步更新模型集的已启用数量

#### Scenario: 删除模型集
- **WHEN** 用户在更多菜单中选择删除并确认
- **THEN** 系统移除该模型集及其保存的凭据，并在最后一个模型集被删除后显示空状态

#### Scenario: 取消删除
- **WHEN** 用户在删除确认中取消
- **THEN** 模型集及其展开、启用和测试状态保持不变

#### Scenario: 操作失败
- **WHEN** 刷新、保存启用状态或删除被后端拒绝或遇到网络错误
- **THEN** 页面保留操作前的可见状态并展示可诊断错误，不显示虚假成功

### Requirement: 添加并验证模型集
系统 SHALL 提供连接配置和选择模型两步流程，并在第一步提供协议选择、名称、接口地址和 API Key 输入；系统 SHALL 通过真实端点发现模型、测试连接和测试单个模型，并 SHALL 覆盖 Figma 节点 `273:126`、`273:162`、`273:198`、`273:234` 和 `273:270`。

#### Scenario: 配置连接
- **WHEN** 用户选择协议、填写模型集名称、接口地址和 API Key 并测试连接
- **THEN** 系统展示连接测试进度与结果，成功后允许进入选择模型步骤

#### Scenario: 发现与手动添加入口
- **WHEN** 用户进入选择模型步骤
- **THEN** 系统展示发现到的模型，并提供纯图标的手动添加入口，但 MUST NOT 展示固定的“手动添加模型”行

#### Scenario: 协议没有发现接口
- **WHEN** 用户选择的协议不提供模型发现
- **THEN** 系统展示手动添加模型的入口与说明，不把缺少发现接口当作连接失败

#### Scenario: 未测试状态
- **WHEN** 用户刚进入模型选择步骤
- **THEN** 页面按节点 `273:162` 显示模型选择和未测试状态

#### Scenario: 测试模型状态
- **WHEN** 用户测试发现的模型
- **THEN** 页面先按节点 `273:198` 呈现测试中，再根据真实结果按节点 `273:234` 或 `273:270` 呈现部分失败或全部成功

#### Scenario: 不支持文本的模型
- **WHEN** 某个模型不接受文本请求
- **THEN** 页面把该模型标记为不支持文本，并允许用户按节点 `273:270` 保存其余已成功测试的模型

#### Scenario: 保存模型集
- **WHEN** 至少一个模型测试成功且用户保存
- **THEN** 系统保存模型集与其凭据，并返回模型集列表页展示新数据

#### Scenario: 步骤间保留数据
- **WHEN** 用户在连接配置和模型选择步骤之间前进或返回
- **THEN** 已填写连接字段、选择的模型和已有测试结果均保持不变

### Requirement: 遵循操作与状态视觉语义
系统 SHALL 使用清晰区分连接/网关、模型与新增动作的匹配图标，并遵循已确认的按钮、图标前景色和状态样式约束。

#### Scenario: 图标和按钮样式
- **WHEN** 页面展示模型集、连接选择器、空状态、手动添加、刷新或模型测试操作
- **THEN** 连接/网关使用网络或连接语义图标，模型使用模型语义图标，新增使用 Plus；手动添加、刷新和测试模型为无边框纯图标按钮，文字按钮有边框

#### Scenario: 主按钮图标颜色
- **WHEN** 添加模型集按钮处于默认、hover、pressed、focus、loading 或 disabled 状态
- **THEN** Plus 图标颜色与同状态按钮文字颜色一致

#### Scenario: 状态和测试结果
- **WHEN** 页面展示模型测试状态与结果
- **THEN** 状态使用图标与文字同色的胶囊，测试失败与不支持文本使用可区分的状态文案，且测试结果 MUST NOT 额外显示汇总行

#### Scenario: 协议选择控件
- **WHEN** 页面展示协议选择控件
- **THEN** 控件具备稳定测试标识、可见焦点状态，并复用现有设置页表单样式

### Requirement: 已保存模型的测试反馈
系统 MUST 在已保存模型集的单项测试和刷新批量测试中对每个模型的文本、推理、视觉、生图四项即时显示加载态，并在完成后仅以“成功”或“失败”展示每项结果。测试失败或请求异常时 MUST 保留内部诊断信息，但设置页 MUST NOT 展示错误原因，也不能继续呈现为未测试或静默结束。批量测试中一个模型失败 SHALL 不阻止其他模型继续测试；语音和视频目录模型 SHALL 保留模型行并真实探测文本、推理、视觉、生图四项，但不测试或展示音视频专项能力。

#### Scenario: 单项测试进行中
- **WHEN** 用户点击已保存模型的一行测试按钮
- **THEN** 该行的文本、推理、视觉、生图四项立即显示加载态并避免重复发起，完成后刷新逐项二态结果；若请求异常，该行显示失败而不展示原因，仍可重试

#### Scenario: 批量测试部分失败
- **WHEN** 刷新后一个模型的能力测试失败或请求异常，而其他模型仍可测试
- **THEN** 页面显示已完成数量及对应行的成功或失败状态，不展示错误原因，并继续处理其余模型，最终结果不将失败模型伪装为已通过

#### Scenario: 批量模型同时进入测试态
- **WHEN** 刷新发现一批模型，数量超过同时运行的请求数
- **THEN** 所有待测模型的文本、推理、视觉、生图能力立即显示“测试中”，包括排队模型；每个模型完成后独立更新结果，请求并发数仍受限制

#### Scenario: 音视频只展示
- **WHEN** 刷新发现的模型属于音频或视频目录能力
- **THEN** 该行保留名称与启用状态，并实际测试、展示文本、推理、视觉、生图四项；不显示语音、视频或“未接入测试”标签，也不发起音视频专项请求

#### Scenario: 重复点击刷新
- **WHEN** 同一模型集刷新及测试尚未完成，用户再次点击刷新操作
- **THEN** 系统不启动第二批重复请求，已有进度与结果继续可见

#### Scenario: 批量与单项测试互斥
- **WHEN** 模型集正在刷新测试或其任一模型正在单项测试
- **THEN** 页面禁用会与当前测试重叠的入口，不同时发起该模型的重复探测

#### Scenario: 并行测试模型和能力
- **WHEN** 用户刷新模型集或在添加模型集时测试全部模型
- **THEN** 系统并行探测多个模型，且并行探测每个模型的文本、推理、视觉、生图四项；单个模型失败不阻止其他模型和能力完成

#### Scenario: 清理不再适用的旧结果
- **WHEN** 本次测试得到的能力候选与旧测试记录不同
- **THEN** 该模型只展示本次适用能力的结果，不继续展示旧候选能力的“需重新测试”或旧成功状态

#### Scenario: 测试终态只展示成功或失败
- **WHEN** 能力探测完成并在内部判定为成功、失败、不支持或无法判定
- **THEN** 设置页仅显示“成功”或“失败”，不支持与无法判定均显示失败，且不展示错误原因；内部判定保持原值，用于默认生图资格与诊断

### Requirement: 配置图片相关模型能力
系统 SHALL 根据用户主动发起的真实测试，分别记录模型的文本、推理、视觉和生图结果。每个模型的文本、推理、视觉、生图四项 SHALL 真实测试，MUST NOT 按模型名称、目录声明或旧手工类型跳过其中任何一项；目录 MAY 指导模型用途，但 MUST NOT 被显示为测试成功。设置页 SHALL 不显示聊天/生图类型选择、识图或生图开关、生图接口选择；用户只选择全局唯一默认生图模型。已启用的聊天候选 SHALL 无论文本测试是否运行或成功都出现在聊天选择器，选择时不显示阻断提示；模型行的信息图标 SHALL 展示各项测试状态；纯生图和纯语音视频目录模型不进入聊天选择器。生图测试成功的已启用模型 SHALL 可设为默认生图模型；两项可同时成立。系统 MUST 允许仅生图测试成功的连接被保存。未配置已验证的默认生图模型时，生图工具不可用。

#### Scenario: 多能力模型
- **WHEN** 同一模型的文本和生图测试均成功
- **THEN** 该模型同时可用于聊天和默认生图候选，设置页逐项显示两项成功，不要求用户选择单一类型

#### Scenario: 未测试聊天模型仍可选择
- **WHEN** 已启用的聊天候选尚未测试，或文本测试失败、无法判定
- **THEN** 聊天下拉列表仍允许选择该模型且不显示阻断提示；发送后若提供方拒绝，错误出现在该轮对话中

#### Scenario: 非聊天模型不进入下拉列表
- **WHEN** 模型已停用，或目录只含生图、语音、视频能力，或连接协议尚不支持聊天调用
- **THEN** 它不作为可选聊天模型出现，但保留在模型设置列表中

#### Scenario: 选择视觉聊天模型
- **WHEN** 模型的文本测试成功但视觉测试失败、不支持或无法判定
- **THEN** 它仍可尝试纯文字或附图聊天，设置页分别显示两项测试结果；实际模型调用失败在对话中展示

#### Scenario: 推理结果缺乏证据
- **WHEN** 推理测试收到普通最终文本但没有可验证的推理证据
- **THEN** 内部记录“无法判定”，设置页只显示“失败”而不展示原因，不得显示推理测试成功或抹除该模型已成功的文本测试

#### Scenario: 配置默认生图模型
- **WHEN** 用户在已保存、已启用且生图测试成功的模型行将其设为默认生图模型
- **THEN** 系统保存该选择，之后的生图工具调用使用经测试的接口，当前聊天模型选择不改变

#### Scenario: 为模型选择生图接口
- **WHEN** 用户在已配置 Token Plan 连接中显式测试 `wan2.7-image`、`wan2.7-image-pro` 或 `qwen-image-3.0-pro`，包括在“刷新并测试”中测试这些模型
- **THEN** 系统对该模型逐一真实测试适用的兼容 Images API 与 Token Plan 多模态生成接口，分别保存各接口的成功或失败状态、测试时间及可诊断失败信息；不因首个接口成功或失败而跳过另一个接口，也不把测试图加入会话

#### Scenario: 按接口结果决定生图资格
- **WHEN** 指定 Token Plan 模型的接口测试完成
- **THEN** 只有至少一个接口完成真实图片验证且成功结果与该模型及当前连接配置对应时，生图能力才显示成功并允许设为默认；失败接口保留内部诊断，但设置页仅展示生图能力成功或失败，不展示接口选择或错误原因

#### Scenario: 重测覆盖旧接口结果
- **WHEN** 用户重测指定 Token Plan 模型，或连接的接口地址、凭据发生变化
- **THEN** 系统以当前连接和本次测试结果决定接口可用性，旧成功状态不得让本次失败接口继续成为运行路径；若没有成功接口，默认生图模型不再可用

#### Scenario: 旧配置等待逐接口验证
- **WHEN** 已有指定 Token Plan 模型仅有旧版生图成功状态或旧生图接口字段，没有与当前连接匹配的逐接口验证结果
- **THEN** 系统保留连接、模型及默认引用，但将其生图可用性视为待验证，直到用户重新测试；不得把旧字段直接当作已验证接口

#### Scenario: 其他连接的生图测试
- **WHEN** 用户测试不属于上述指定 Token Plan 连接与模型组合的模型
- **THEN** 系统沿用该连接既有的生图测试方式，不将 Token Plan 双接口探测扩展到其他连接或模型

#### Scenario: 迁移已有生图配置
- **WHEN** 应用读取升级前有单一测试成功、手工生图类型或默认生图引用的记录
- **THEN** 原连接、启用状态、模型 ID 和默认引用得以保留，但旧结果仅显示“待测试”，不得自动当作文本、视觉或生图已验证成功；已启用聊天候选仍可尝试调用

#### Scenario: 默认生图模型被关闭或删除
- **WHEN** 默认生图模型被停用、删除或生图重测不再成功
- **THEN** 系统清除可用默认选择或标记为待验证，Agent 不把生图工具暴露为可用能力

#### Scenario: 音频视频能力只展示
- **WHEN** 模型目录包含语音识别、实时语音、语音合成或视频生成模型
- **THEN** 设置页保留模型行并测试、展示文本、推理、视觉、生图四项；语音、视频能力及“未接入测试”标签不显示，也不发起音视频专项请求，不把该模型加入聊天或默认生图候选

#### Scenario: 提供方不支持生图请求
- **WHEN** 用户主动测试生图能力而提供方拒绝、超时或返回无效图片
- **THEN** 设置页只显示该能力“失败”且不展示具体原因，其他能力的成功结果不变，不把测试图加入会话

#### Scenario: 添加仅支持生图的连接
- **WHEN** 用户手动添加仅支持 Images API 的模型并主动测试生图
- **THEN** 生图测试实际验证一张图片；测试成功后可保存连接并设为默认，不要求聊天补全成功

#### Scenario: 逐模型区分类型与测试接口
- **WHEN** 同一连接同时包含文本模型和生图模型，用户分别点击测试
- **THEN** Runtime 对两个模型均测试文本、推理、视觉、生图四项，并逐项显示结果，页面不要求用户为模型选择类型

#### Scenario: 修改已保存模型类型
- **WHEN** 用户在已保存模型列表中查看或重测一个模型
- **THEN** 页面不提供聊天或生图类型修改控件；该模型的可用用途随逐项测试结果更新

#### Scenario: 名称不影响三项测试
- **WHEN** 模型 ID 看起来属于纯生图、音频、视频或未知类别
- **THEN** 系统仍分别向提供方测试文本、推理、视觉、生图四项，按真实响应记录成功或失败，不因名称直接填入结果

#### Scenario: 下拉列表查看能力状态
- **WHEN** 用户悬停聊天模型下拉列表行的信息图标，或用键盘导航到该模型行
- **THEN** 信息图标紧跟模型名称，选中对号单独靠右；页面显示该模型文本、推理、视觉、生图四项各自的“成功”“失败”或“待测试”状态；不显示提供方错误原因，不阻止选择；未测试模型仍可选择
