# runtime-event-recovery Specification

## Purpose

定义多个请求同时运行时事件持久化、重放、快照和异常重启的稳定行为，使用户看到的过程与 Runtime 中的任务事实一致且不重复执行本机副作用。

## Requirements

### Requirement: 请求事件具有连续顺序
系统 MUST 为同一请求的每个持久化事件分配唯一且连续的请求内序号，并 SHALL 在事件写入成功后才向客户端发布；全局 cursor SHALL 仅作为数据库定位和重放水位。工具准备进度事件也 MUST 遵守该顺序，不得绕过持久化直接广播。

#### Scenario: 两个请求交错产生事件
- **WHEN** 请求 A 和 B 的事件交替写入数据库
- **THEN** 每个请求从接受到终态的序号分别连续，客户端不会因为另一个请求占用了全局 cursor 而停止显示

#### Scenario: 事件写入失败
- **WHEN** 事件写入事务失败
- **THEN** 请求序号和任务状态均不推进，服务端不广播该事件

#### Scenario: 工具准备事件与执行事件
- **WHEN** 模型先流出工具名，后续完成参数并开始执行
- **THEN** 同一请求中的准备、正式工具及终态事件按持久化序号到达，重连回放不重复执行工具

#### Scenario: 页面刷新时请求仍在运行
- **WHEN** 客户端通过任务快照恢复仍在运行的请求
- **THEN** 客户端使用该请求标识和快照水位续订，展示后续事件及最终结果，并保留取消能力，不重复执行或显示已入快照的工具

### Requirement: 重放与快照恢复保持一致
系统 SHALL 按请求和 cursor 有界重放已提交事件，并 SHALL 在重放缺口不可恢复时提供同一高水位的状态快照；客户端 MUST 忽略重复事件，按请求序号连续应用后才推进已应用水位。

#### Scenario: 重连时遇到乱序和重复事件
- **WHEN** 客户端收到重复帧、乱序帧和其他请求交错的帧
- **THEN** 每个请求的过程文本、工具条目与终态恰好投影一次，顺序与持久化结果一致

#### Scenario: 重放范围已过期
- **WHEN** 客户端请求的事件早于服务端保留范围
- **THEN** 客户端以一致快照替换旧投影，仅应用快照水位之后的新事件

### Requirement: 异常重启安全结束运行中任务
Runtime MUST 在对外提供服务前，将无执行者的运行中请求幂等转为中断终态，保留已提交内容与工具记录；MUST NOT 自动重放可能产生副作用的工具。

#### Scenario: 模型输出中途退出
- **WHEN** Runtime 在写入部分助手内容后退出并重启
- **THEN** 用户仍能看到部分内容和明确失败状态，重复重启不会新增第二个终态

#### Scenario: 工具执行结果未知
- **WHEN** 工具已开始但结果未持久化时 Runtime 退出
- **THEN** 恢复视图将调用结果显示为未知，系统不自动再次执行该调用

### Requirement: 旧事件可安全迁移
系统 MUST 在改变持久化事件结构前备份数据库，校验旧事件的请求身份与顺序，并在无法无损回填时保持原数据可恢复，不能静默猜测缺失事件。

#### Scenario: 旧数据库含并发事件
- **WHEN** 升级打开旧版数据库，两个请求的全局 cursor 交错
- **THEN** 系统按每个请求自身的持久化次序建立连续序号且保留原 cursor 与事件身份
